# Run Dashboard — 主题分区与精选图设计

## 定位与边界

Debug Viewer 的 Run 页是 **Dashboard**：帮助人和 AI **发现问题、定位异常、
导航到证据**，不追求在页面上完成归因分析。

```
Dashboard（Run 页）        发现问题、定位 update、找到证据入口
    ↓
调查工具（Resume / Dump / Delta / 临时探针）    回到现场、验证因果
    ↓
框架能力（param_overrides / --param / 对照实验）  执行干预
```

本设计只调整**信息组织与展示层级**，不调整现有指标的计算与记录。

**唯一例外**：2000 帧梯度诊断（gradsig）相关内容从 Run Dashboard 完全移除
——不是藏进"展开更多"，而是不留展示位。其计算能力与 Dump 的承接方式
是后续独立任务，本文档不覆盖。

## 准入原则

每张精选图必须能通过四个问题：

1. **它在回答什么问题？**
2. **什么变化值得注意？**
3. **注意到变化后，下一步做什么？**
4. **它不能说明什么？**

"讲故事"的含义：让用户形成一个值得调查的疑问，而不是让曲线看起来
已经证明了因果。

**关键机制约束**：指标可以默认进入数据接口，但不能默认获得 Dashboard
展示位。当前实现里未被布局消费的字段会自动补图——这个 fallback 必须
被覆盖，否则删掉几张图只是暂时的，未来还会膨胀回来。

## 分区结构：六个主题区，默认九张精选图

从上到下按**用户排查优先级**排列（不是数据流水线顺序）：

| 顺序 | 主题区 | 核心问题 | 精选图 |
|---|---|---|---|
| 1 | 任务表现 | 训练有没有让任务做得更好？ | 评估表现（eval.* 全量一图） |
| 2 | 策略更新 | PPO 是否在正常推进？ | 策略漂移与早停、Actor 更新执行量 |
| 3 | 训练信号 | 提供给 Actor 的学习依据是否可靠？ | Critic 解释度与通道置信度 |
| 4 | 探索状态 | 策略是否过早失去探索能力？ | 不确定性与保护下限 |
| 5 | 采样与轨迹 | 本轮训练的数据是否符合预期？ | 数据数量、Episode/trajectory 长度 |
| 6 | 运行开销 | 时间花在哪里，是否出现瓶颈？ | 每轮耗时与阶段组成 |

阅读动线：

```
任务有没有进步？
    ↓
更新过程有没有异常？
    ↓
训练信号是否可靠？探索是否受限？
    ↓
数据来源是否变化？
    ↓
运行成本是否异常？
```

页面顶部保留紧凑的 Run 信息与 checkpoint / Dump / 视频入口，
不新增图表区。

## 分区定义与精选图

### 1. 任务表现

**职责：首先回答"这次训练值不值得继续"。**

#### 精选图 1A：评估表现

展示实验 `on_eval` 输出的**全部 `eval.*` 指标，合在一张图里**——
能被实验选作评估输出的指标天然都是重要指标，不再做 prefer/回退挑选。
量纲差异明显的指标共用一图，用户可通过图例点选关线。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 当前评估条件下，策略完成任务的能力是否改善？ |
| 值得注意的变化？ | 持续停滞、突然退化、波动明显增大；两个指标一升一降。 |
| 下一步做什么？ | 看对应评估视频；检查配置/课程变化；对照"策略更新"和"探索状态"。比较多个评估点而非盯住单点。 |
| 不能说明什么？ | 单次评估不能证明稳定提升；结果受评估样本、场景、随机性影响，也不说明变化的原因。 |

**展开更多**：`exp.*` 在线指标（实验 `on_update` 输出），一指标一图。
实验无 `eval.*` 输出时精选卡显示"本实验无 eval.* 指标输出"，
不拿 PPO loss 顶替任务表现。

**Compare 模式**：eval 全量图同样 overlay 全部 run——对比只有画在
一张图里才有意义，不因线多拆面板。

### 2. 策略更新

**职责：回答"更新是否被截断，策略是否发生异常漂移"。**

#### 精选图 2A：策略漂移与早停

默认展示：

- `post_kl_mean`：更新结束后在完整 buffer 上的平均 KL 估计（末态）。
- `kl_mean`：更新过程中的平均 KL 估计（过程量）。
- 早停标记：用 `early_stop_kl_mean`；**未触发时不把零值连成曲线**。

清楚标注"更新末态"与"更新过程"，不默认叠加 max、正负 ADV 分组。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 本轮策略相对采样策略改变了多少？是否触发 KL 早停？ |
| 值得注意的变化？ | KL 突然升高；早停开始频繁；KL 长期接近零；过程/末态关系改变。 |
| 下一步做什么？ | 先看 Actor 更新执行量；展开 ratio、梯度辅助图；局部突变则定位首次异常 update，进 Dump timeline。 |
| 不能说明什么？ | KL 更低不等于更好、更高不必然更坏；是采样估计不是参数位移，更不是任务收益。早停阈值只针对其指定窗口。 |

#### 精选图 2B：Actor 更新执行量

同图卡分开显示：`actor_steps`，以及 `actor_epochs_done` vs `epochs_done`。
不同单位不混同一纵轴；`n_batches` 放展开。

若要加"计划步数"参考线，必须使用**该 update 实际生效的配置**
（考虑 param_overrides），不能拿 Run 初始配置套所有历史点。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | Actor 实际执行了多少更新？是否在 Critic 继续训练时提前停止？ |
| 值得注意的变化？ | Actor 步数突然下降；actor/总 epoch 数开始分离；更新量长期偏低。 |
| 下一步做什么？ | 对照早停标记；检查 epochs、minibatch size、buffer 配置变化，区分主动改配置与提前截断。 |
| 不能说明什么？ | 步数多/epoch 跑满不等于学习效率高；变化也可能只是数据量或 minibatch 配置变了。 |

**展开更多**（按子组组织）：概率变化（ratio、clip fraction、ratio bins）、
优化信号（policy loss、Actor gradient norm）、更新末态（post-KL 细分、
ΔClipLoss gain/harm）、`n_batches`。

### 3. 训练信号

**职责：回答"Critic 产生的学习依据是否可靠，哪些通道实际参与训练"。**

#### 精选图 3A：Critic 解释度与通道置信度

展示每通道 EV 与 confidence（同色不同线型；通道多时用选择器或小图组）。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | Critic 能否解释当前 return 的变化？置信度机制是否正在压低某些通道的 Actor 信号？ |
| 值得注意的变化？ | EV 突然下降或长期为负；confidence 长期接近零；某通道明显落后。 |
| 下一步做什么？ | 展开该通道的 reward/return/ADV/value loss/actor weight，判断是目标分布变化、Critic 拟合问题还是权重机制使信号失效。 |
| 不能说明什么？ | 高 EV 不保证 ADV 无异常尾部或 value 无偏差；confidence 高不等于通道重要性高或实际贡献大。 |

**展开更多**：各通道 reward / return / 原始 ADV 统计、actor weight、
critic value loss 与梯度范数、通道活跃比例。

原始 ADV min/max 不进精选——它们不是最终送入 Actor 的 combined ADV，
作为首要健康图容易误读。本版不新增替代指标。

### 4. 探索状态

**职责：回答"策略是否过早收缩，探索保护是否持续介入"。**

#### 精选图 4A：不确定性与保护下限

默认展示 `uncertainty_mean` 与 `uncertainty_floor`。
`uncertainty_coef` 作为选中 update 的参数说明或展开内容，
不与不确定性共用数值轴。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 策略不确定性如何变化？均值是否持续处于保护下限附近或以下？ |
| 值得注意的变化？ | 不确定性快速下降、长期低于下限、下限调整后不响应、任务停滞同时持续收缩。 |
| 下一步做什么？ | 展开 floor loss、保护系数和策略特有探索指标；看视频判断行为是否僵化；必要时检查保护梯度。 |
| 不能说明什么？ | 均值不代表所有状态；均值高于 floor 不代表局部保护项未激活；高不确定性不等于有用探索。 |

**展开更多**：floor loss、uncertainty_coef、policy/floor 梯度分解、
策略贡献指标（std、effective std 等，作为独立子组，不强行解释成探索指标）。

### 5. 采样与轨迹

**职责：回答"我们究竟用什么规模、什么形态的数据在训练"。**

#### 精选图 5A：Episode 与 trajectory 数量

展示 `n_episodes` 与 `n_trajectories`。每通道 active trajectories 不默认混入。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 实际采集了多少 episode，构成多少训练轨迹？ |
| 值得注意的变化？ | 数量意外下降；traj/episode 数量关系突变；与预期规模不符。 |
| 下一步做什么？ | 检查 episodes 配置、trajectory 切分、agent 参与和通道激活；必要时看 Dump 映射。 |
| 不能说明什么？ | 数量多不等于信息量大；重复、强相关数据不因数量大变成高质量样本。 |

#### 精选图 5B：Episode 与 trajectory 长度

默认展示两个 mean；min/max 为可开启的范围信息，不默认六条线全展示。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 环境交互长度和进入训练的轨迹长度是否发生结构变化？ |
| 值得注意的变化？ | 长度突然缩短；两种长度开始明显分离；范围变宽；长期固定 timeout。 |
| 下一步做什么？ | 检查终止原因、时间上限和切分规则；结合任务表现及 episode 证据判断。 |
| 不能说明什么？ | 长不一定好、短不一定坏：可能是更早失败，也可能是更快成功——须由任务语义解释。 |

**展开更多**：total frames、长度 min/max、每通道活跃轨迹等覆盖情况。

### 6. 运行开销

**职责：回答"时间花在了哪里"。**

#### 精选图 6A：每轮耗时与阶段组成

展示现有 `timing`：total 为总体趋势，rollout/ppo/eval 为组成；
jobs/export 等小项默认不强调。total 不作为阶段再次叠加进组成图。

| 四问 | 回答 |
|---|---|
| 回答什么问题？ | 一轮训练耗时多少？主要耗时来自哪个阶段？ |
| 值得注意的变化？ | 总耗时阶跃增长；某阶段持续变慢；周期性耗时尖峰。 |
| 下一步做什么？ | 对照数据规模、实际 Actor 步数、评估周期和诊断开关，再查资源竞争或具体阶段。 |
| 不能说明什么？ | 每轮更快不等于效率更高——可能只是数据变少或提前停止；不据此声称样本效率提升。 |

**展开更多**：所有阶段耗时及其余运行开销数据。

## "展开更多"的组织约束

每个分区统一结构：

```
分区标题
一句话：这一组帮助判断什么

精选图
精选图

展开更多：N 张辅助图（按子问题分组，不是"其他指标"抽屉）
```

三条约束：

1. **展开内容仍有归属**：按子问题分组（如策略更新下分"概率变化 /
   优化信号 / 更新末态"），不做杂物抽屉。
2. **同一指标组只在一个分区出现**：policy loss → 策略更新；
   floor loss → 探索状态；critic loss → 训练信号。可以拆现有混合图，
   不改指标本身。
3. **新指标不自动进精选区**：未配置的新增字段可进所属分区的扩展
   内容保证可查；进入精选区必须填写四个问题。实验自定义指标同规则。

## 四个问题的页面呈现

不把四段解释常显在每张图下（新的阅读负担）。结构：

- **图标题**：看什么。
- **一行副标题**：回答"它在回答什么问题"。
- **"如何读这张图"展开入口**：其余三个问题 + 必要定义。

说明文本继续由 `dumpkit/metric_catalog.py` 统一管理，前端与 CLI 同源，
不复制第二套解释。

## gradsig 的移除范围

从 Run Dashboard 移除：

- `‖G‖ vs mean(p_i)` 图
- Coherence & Direction 图
- Per-frame Support vs G 图
- Update Detail 的梯度热力图、边缘分布、投影分布
- 相关辅助标量的 fallback 自动补图

不删除历史 `gradsig/` 工件（旧 run 仍可读）。诊断已改为
**dump-only**：`grad_sig_sample_size`/`grad_sig_interval` 公共参数
已删除，周期性采集路径已移除；dump 请求触发时以内部固定 2000 帧
运行诊断，数据自包含地写入 `dumps/uNNNNN/gradsig.npz`，经
`DumpData.grad_sig()` / `/api/dump/<d>/gradsig` 读取。

## 验收场景

用三个真实场景验收，而不是看页面是否整齐：

**场景 A：u282 早停事故**——不展开也应发现：Actor 更新量突然下降、
早停发生、策略漂移值得注意；能定位 u282 并找到 checkpoint/Dump 入口。
不要求默认页面解释"为什么是轨迹 576"。

**场景 B：四个 epoch 跑满但任务没进步**——任务表现在最前，用户优先
看到"没有学会"，而不是被正常的 PPO 内部曲线安慰。

**场景 C：训练突然变快**——结合采样量、Actor 步数和耗时判断是性能
改善、数据变少还是提前停止；不直接把"更快"解释成"更有效"。
