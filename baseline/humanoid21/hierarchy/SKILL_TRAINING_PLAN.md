# 基础 Skill 训练总体方案

当前基线技能训练的完整设计（实验 `skill_full_mbs`）。本文只描述
现行方案与决策理由，不记录历史演变。专项细节见
`STRIDE_REWARD_PLAN.md`（移动）与 `STRIKE_LAUNCH_GATE.md`（打击门控）。

## 1. 定位

在已验收的 S2 基础（站立平衡 + 原地踏步，checkpoint
`hier_s2_balance_s42i_b/checkpoints/checkpoint_u01635.pt`）之上，
训练一个**可复用的低层技能策略**：高层战术策略只需下发语义指令，
低层策略自行完成平衡、协调、接触与恢复。不为每个任务重训一个
端到端控制器。

核心决策原则：

- **指令表达意图，不编动作序列**。指令行只携带方向/拳型/目标等
  语义，怎么迈腿、怎么发力由策略自己学。
- **结果评价优先于过程塑形**。能用"这一步/这一拳的结果"评价的，
  就不用逐帧稠密信号去逼近——奖励归因越贴近动作单元越准。
- **饱和指令**。`+1/-1` = 该方向最大运动意图，第一阶段不做连续
  速度/任意方向条件化，减少探索维度。
- **零指令 = 原地踏步**（目标语义，不是已有能力）。S2 会踏步但
  会漂移，并不具备原地保持；位置不发散本身是要在本阶段修正的
  行为。

## 3. Episode 结构：warmup 泛化起手

每个 episode 允许以一段**热身前缀**开始：先执行一个随机先序技能
（最长约 35 步），再切换到本 episode 的目标技能指令。

**决策理由**：高层策略组合技能时，每个技能的起点都是"上一技能的
中段姿态"，不是干净站姿。只在站立起手下训出的技能无法被序列化
使用。warmup 让训练分布直接覆盖全部"技能→技能"衔接面；从 S2
起步时先序技能只会踏步，coverage 随技能成长自动变真。

**step/idle 的两类初始条件**：step episode 的初始条件按显式概率
（`IDLE_FALLEN_PROB=0.5`）分两种——

1. **随机倒地**：与 S2 相同的倒地起手，零指令要求"先恢复再踏步
   并保持位置"；倒地覆盖只存在于 idle episode，必须保留显式概率，
   否则会被 warmup 的高命中率（~97%）挤掉。
2. **其它状态**：非倒地起手——技能中段 warmup 状态（"打拳打到
   一半→原地踏步"等衔接面）或普通站立。两类各占一半。

实现上用两套 env 区分（见 §11）：倒地 env 挂
`RandomFallenStatePlugin`，warmup env 挂 `WarmupSteppingPlugin`，
按 episode 二选一，互斥。

**显式排除"同名打击→同名打击"**——这是有意设计，不是缺口：
若 warmup 把机器人交到"同一招拳正打到一半"的状态，策略该学什么是
歧义的——学"回到准备姿态重新出拳"与出拳中间状态冲突（出拳过程本
来就经过中间态）；学"继续出拳"则当前 extension-only 奖励设计无法
正确评价（进度指针已在半路，奖励语义失效）。因此训练排除该转移。
**部署语义不同**：实际部署中遇到同名拳衔接，策略应继续把拳打完，
而不是回到发力准备状态。

**eval 与 train 同分布**：eval job 同样注入 warmup spec（确定性
rng 采样），idle eval 同样按 0.5 概率分倒地/warmup 两类 env——
评估的就是训练 rollout 的初始条件分布。

## 4. 奖励通道（7 条）

| 通道 | 挂载范围 | 作用 |
|---|---|---|
| `r_potential` | 全部 | 平衡势能 phi（奖励截断于 0.90，见 §5） |
| `r_fall` | 全部（strike 豁免 actor_weight） | 摔倒惩罚 |
| `r_move_step` | move×4 | 按步结算的径向进度（§6） |
| `r_drift_step` | move×4 + step/idle | 按步结算的漂移罚：move 罚侧漂+偏航，step 罚全部位移+偏航（§6） |
| `r_turn` | turn×2 | 朝向指令角速度（密集，已收敛不动） |
| `r_strike` | strike×4 | 两段式：对齐门控 + 单调进度跟踪（§7） |
| `r_std_clip` | step/idle | 标准站姿 clip 匹配 |

**打击 episode 的平衡豁免**：strike 段内 r_potential/r_fall 的
actor_weight = 0——允许重心全情投入（弓步前倾甚至扑倒），"怕摔"
不能压制出拳梯度。

## 5. 平衡势能上限截断（phi cap = 0.90）

`r_potential` 用 StandingBalance4Stage 的 phi（[0,1]，stage4 为
`0.30 + 0.70·w_foot·h_score`，h_score 由躯干高度 [0.15, 1.28m]
归一化）。奖励值截断为 `min(phi, 0.90)`，对应躯干 ~1.12m 满分。

**决策理由**：phi→1.0 的梯度一直把躯干推向 1.28m 顶格站直——
物理上即腿打直、重心提到最高，与"移动时降重心/微前倾"完全反向。
截断后 1.12–1.28m 之间不再分高低，策略可以选择屈膝前倾的运动
站姿而不亏分。raw phi 仍用于摔倒检测和 φ² 门控，语义不变。

## 6. 移动奖励：按步结算

替换原稠密平滑速度方案（17 帧滑窗 ≈0.85s 会把瞬时方向误差摊平，
且逐帧信号难以归因到"某一步迈歪了"）。

- **步界检测**：`feet_forces`（obs[52:54]，体重归一化）的接触
  上升沿 = foot-strike，按脚分别记录；首帧初始接触不算落地，
  <3 帧内的重复上升沿按触地抖动滤除。离线从轨迹提取，不动
  环境/observer。
- **步周期**：同一只脚的连续两次落地界定一个窗口
  `(prev_same_foot, strike]`——正常交替下恰含左右各一步；
  每次落地结算最近一个周期；episode 末按最后落地脚补收尾窗口。
  单脚跳也产生窗口（周期成立，位移评价如实给出）。
- **每周期评三量**（move_track 原始 xy/yaw，周期本身消步态摆动，
  无需滑窗）：径向净速度 `v_rad`（沿指令方向）、横向净漂移
  `v_off`、净偏航 `|Δyaw|`。
- **单点结算**：`r_move_step[t_end] += 2·v_rad·Δt`，
  `r_drift_step[t_end] += -(v_off·Δt + 0.5·|Δyaw|)`。reward 只在
  结算帧非零，不摊回该周期各帧——"一步一评价"；但
  `actor_weight` 保持逐帧 `3·φ²` 稠密，让 GAE 把结算分回传过
  产生它的整个步周期（只给结算帧权重会把准备动作的信用清零）。
- **兜底**：episode 末半个周期补结算；整段不足 2 次落地则在
  ep 末整段结算一次（拖行/不迈步拿不到迈步红利，且零进展的周期
  也照常被评——"没走"本身就是负证据）。
- **step/idle 复用同一套结算**：无指令方向时所有位移都是漂移，
  每周期结算 `r_drift_step = −(|Δxy| + 0.5·|Δyaw|)`，取代旧
  `r_hold` 稠密锁定——同一台步界机器覆盖"走"与"不走"两个语义。
- 折扣因子不动（0.99）——只缩短评价视野，不引入第二变量。

## 7. 打击奖励：两段式（对齐 → 出拳）

**语义：extension-only。**"打击"只学到出拳至最大伸展为止；落地帧
之后的行为（收招、失衡）不评分——收招是后续技能。命中精度
（参数化目标锥）在基础阶段之外，当前不加 `r_tgt_*` 通道。

每个 strike episode 显式分两段，复用同一 `_frame_score` 复合分
（keypoints + 关节角 RMSE + 手位置 + 手臂链形状项，满分 ~2.0）：

**段 A 对齐段（launch gate）**：先回到发力准备姿态——**判据与
稠密引导都是纯关节姿态**：所有受控关节（踝关节除外，共 17 个）
与 clip **第 0 帧**的误差全部 < 各自全量程的 **5%**（归一化
|q_err|<0.10，量程=仿真器 `jnt_ranges`）才过门；过门前每步
r_strike = 17 关节逐关节 Lorentzian 得分 `mean_j 1/(1+(q_err_j/0.10)²)`
——引导与判据同语义：每个关节自带梯度，判据边界上得分 0.5。
**必须重尾核而非高斯核**：判据是"最差关节"准则，最差关节恰恰是
误差最大的——`exp(−(x/0.10)²)` 在 x=0.5 处梯度 ~e⁻²⁵ 等于零，
而 Lorentzian 在 x=0.5 处仍有 ~0.15 的梯度把瓶颈关节往回拉。
**不用复合分做引导**：其 vel 项语义错误（要的是最快回到准备姿态，
不是匹配 clip 速度；从真实准备姿态推进时速度本就被满足），权重
和还会摊薄个别卡死关节的误差。只匹配第 0 帧而非窗口——"出拳中
段帧"不算准备姿态，过门后指针恒从 0 起。踝关节豁免理由：脚底
俯仰/翻转的贴地方式不是发力语义的一部分。

**段 B 执行段（单调进度跟踪）**：过门后指针沿参考 clip 走，每步最多
前进 2 帧到"未来帧里最匹配"的帧，**只进不退**。帧匹配分是除 vel
项外的复合分——**vel 项已弃用**（语义是"出拳越快越好"，奖励匹配
clip 速度是反向压力；速度激励由指针+hold bonus 提供）。指针到落地
帧只是*进度*——`landed` 与 hold bonus 另需完成判据：出拳手距参考点
≤0.10m 且末帧复合分 ≥1.0（逐帧重评，掉出姿态即停发——hold bonus
字面等于"在目标姿态上停留的时长"）。**出拳越快得分严格越高**，
速度不被 clip 节奏封顶。episode 预算 n = clip 到达预算 + 13 步
hold margin（heavy 额外 +6 弓步预算）。

**决策理由**：泛化起手下机器人必须先学"回到准备姿态再发力"——
纯指针方案会让指针去迁就当前姿态、跳过回架段，技能不可重入
（打下一拳前永远收不回来）。严格门控把"收招回架"免费内嵌进了
每个 strike episode；对站立起手近乎零成本（1-2 步过门）。

## 8. 不动的部分

- **turn**：dense 角速度跟踪，已收敛且质量好，不并入步界方案。
- **step/idle**：`r_drift_step`（步界漂移罚，§6）+ `r_std_clip`，
  4s/80 步。
- **gamma、lr 等 PPO 超参**：全部沿用标准配置（lr 3e-5，
  critic 3e-4，1536 ep/update，96 workers，KL 0.03 等）。

## 9. 明确排除（第一阶段范围外）

- 连续速度/任意方向条件化（饱和 ±1 指令即可）
- 打击命中精度的参数化目标通道（`r_tgt_*`，属后续精确化阶段）
- 出拳后的收招/恢复评分（extension-only 语义内由对齐门控部分覆盖）
- 高层战术策略与 self-play（低层技能验收之后）

## 10. 当前训练

`skill_full_mbs` = 步界结算移动 + 打击对齐门控 + warmup 泛化起手
（`SkillStepMBS`/`SkillGateMBS`/`SkillTransMBS` 的 cooperative

## 11. 实现关键设计

### 指令链路：move_schedule

指令行格式 `[n, vx, vy, w, rsv, eff_type, eff_side, tx, ty, tz]`——
`n` 为该段持续的 action 步数（20Hz），其余为语义参数。使用链路：

- **写入**：`build_jobs` 中 `_skill_rows(skill)` 把技能编译成一行，
  经 `episode_options["move_schedule"][robot_id]` 传入 episode；
  train/eval/warmup 全部走这条路。
- **编译**：`CommandSimulator.reset` → `_build_schedule()` 把行展开
  成 `(T, 9)` 逐帧指令表，物理量归一化（vx/vy÷1.5 m/s、w÷2π rad/s、
  tgt÷1.5 m）；打击行在此一次性 `resolve_clip` 绑定参考 clip。
- **消费**：每步把当前 9 维指令拼进 obs[57:66]（57 维本体感之后）
  ——policy 看到的"要做什么"就是这张表；`StrikeTrackObserver` 读
  同一份 schedule 判定技能段并打分；warmup 插件用同格式 schedule
  在内部 sim 里跑先序技能前缀。
- **部署等价物**：高层策略实时下发走 `set_motion` /
  `set_effector` / `clear_effector`——写进同一份 9 维指令契约；
  schedule 行是训练期的批量脚本形式，两者落同一 obs 字段。

### 初始条件：双 env 划分

step/idle 的两类初始条件由两套蓝图互斥实现，而不是单个 env 按
option 开关插件：

- `skill_idle_env.yaml`——倒地初始条件：`RandomFallenStatePlugin`
  写倒地姿态，无 warmup 插件。
- `skill_idle_warm_env.yaml`——其它状态：`WarmupSteppingPlugin`
  技能中段起手（无 spec 的 robot 保持站立出生姿态），无倒地插件。

`build_jobs` 按 `IDLE_FALLEN_PROB` 先决定本 episode 的初始条件
类别，再选对应 env——两类从结构上互斥（倒地插件与 warmup 不写
同一 episode），避免单 env 内插件执行顺序的隐式耦合。move/turn/
strike 各只有 warmup env；倒地恢复的全部覆盖在 idle episode 中。

### 观测结构（66 维）

obs[0:57] 本体感（无对手）+ obs[57:66] 指令块。`feet_forces`
（双足触地力/体重）在 obs[52:54]——步界检测直接离线读轨迹，
不需要改环境。

### 打击动态目标

打击段的 `tx,ty,tz` 不在段内保持常数：段首把参考 clip 的拳手
轨迹锚定到当时位姿，随后每帧覆写为参考手的当前位置（世界系锚定
→ ego 重投影）。指令契约不变（"目标点可以随时间动"），动态目标
携带了恒定目标给不了的出拳相位信息。

### 多 critic 通道化

每个奖励通道一个独立 critic（`RewardChannel`），实验类通过
`_channel_names`/`_channel_gammas` 声明全集，按技能家族在
`build_trajectories` 里挂子集；`actor_weight` 逐帧调制梯度强度
（φ² 门控、结算掩码、strike 豁免都用这个钩子实现）。

### 各通道折扣因子（`_channel_gammas`，全部 0.99，λ=0.95）

γ=0.99 对应信用视野 ~1/(1−γ)=100 步 ≈ 5s（20Hz）。**注意区分两个
"视野"**：步界结算缩的是*评价窗口*（每个事件评什么），gamma 是
*信用视野*（一个结果向前回授多远）——前者缩短，后者保持长程，
让步周期/出拳的结算分能回传到"蓄力、移重心、摆臂"等准备动作上。

| 通道 | γ | 语义适配 |
|---|---|---|
| `r_potential` | 0.99 | 势能 shaping 天然长程——现在蹲一点，未来几十步的平衡收益都与之相关 |
| `r_fall` | 0.99 | 摔倒是终态事件；长程折扣让"走向摔倒"的状态链累积负价值，学的是避险而非只学倒地瞬间 |
| `r_move_step` | 0.99 | 结算点稀疏（每步一次），但一个好步子由整个重心转移过程产生——信用须回传过整个迈步，故折扣不缩 |
| `r_drift_step` | 0.99 | 同上：漂移的原因（落脚位置）在评价窗口*之前*发生 |
| `r_turn` | 0.99 | 逐帧稠密信号，长程平滑 |
| `r_strike` | 0.99 | 信用视野(≈100步)已覆盖整个 24-25 步 strike episode，等价于段内 sum-to-go；对齐段 shaping 自然传导到出拳段 |
| `r_std_clip` | 0.99 | 逐帧稠密 shaping |

曾考虑过给结算类通道降 γ 进一步压缩信用视野，结论是不动：
评价窗口的缩短已提供归因精度，降 γ 反而切断"准备动作→结果"
的信用链，并多引入一个待调变量。
