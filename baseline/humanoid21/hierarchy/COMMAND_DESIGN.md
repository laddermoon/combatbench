# 底层指令空间设计（Command Design）

> 状态：定稿 v1（2026-10-16）
> 适用对象：CombatBench 分层控制架构的低层运动控制策略

## 1. 设计目标

低层策略负责全部 21-DOF 的物理控制；上层（手写战术代码、后续 LLM/VLM 生成或进化的 Code-As-Policy、以及未来的自博弈策略）只在一个固定的、低维的语义指令空间中发命令。

指令空间必须满足：

1. **即时性**：指令描述的是“此刻想要什么”，不是“执行一套预设动作”。不存在带有内部时间表的动作序列（没有“出拳后自动收手”“转身 90° 后停止”这类原语）。想结束一个动作，由上层发新的指令。
2. **解耦**：整体移动（平移、转向、身体高度）与末端动作（哪只手/脚去哪个点）是两条独立通道，可以分别更新、任意组合——例如后退中右手打点、原地转身中左脚踢点。
3. **统一执行体**：两条通道虽然语义解耦，但由同一个低层策略执行。身体协调（侧移时踢出支撑脚、下蹲时保持平衡）是低层策略要学的技能，不在指令层面拆分。
4. **简洁**：维度尽可能少、每个字段语义唯一、所有字段持续有效（上层每步可任意改写）。

## 2. 输入布局（66 维）

```
obs[0:57]   自身本体状态（Humanoid21Simulator 原始观测前 57 维）
obs[57:66]  9 维指令向量
```

57 维本体状态中包含机体系下的场地中心位置，策略可利用它感知场地边界，不产生平移不变性问题。

## 3. 指令字段

| 索引 | 字段 | 语义 | 取值约定 |
|---|---|---|---|
| `57` | `vx` | 前后目标线速度（前进为正） | m/s，训练课程内由慢到快连续取值 |
| `58` | `vy` | 左右目标线速度（向左为正） | m/s |
| `59` | `w` | 目标转向角速度（左转为正） | rad/s |
| `60` | `h` | 目标身体高度偏移（相对正常站姿） | 归一化偏移，`0` = 标准站立高度；负值 = 蹲低 |
| `61` | `eff_type` | 末端类型：`0` 无末端任务，`+1` 手，`-1` 脚 | 离散 |
| `62` | `eff_side` | 末端左右：`+1` 左，`-1` 右；`eff_type=0` 时忽略 | 离散 |
| `63` | `tx` | 末端目标点：前后坐标 | 自身水平系坐标（m），`eff_type=0` 时忽略 |
| `64` | `ty` | 末端目标点：左右坐标 | 同上 |
| `65` | `tz` | 末端目标点：上下坐标 | 同上 |

进入网络前每个字段按固定尺度归一化（速度除 `v_max`、转速除 `w_max`、目标点除工作空间半径）；归一化尺度在整个训练过程中不变。

## 4. 语义规则

### 4.1 身体通道（`vx, vy, w, h`）

**移动/转向跟随速度，高度跟随设定值。**

- 向量 `(vx, vy)` 的方向即移动方向，模长即期望速度。“走到某个位置”是上层的责任：把位置误差换算成速度指令（远离快、接近慢、到位清零）。
- `(0, 0, 0, h*)`：不移动、不转向，保持指定高度的原地动态踱步。
- `h` 是**目标高度偏移**而不是竖直速度。写“下蹲”即把 `h` 调低并保持；“站起”即调回 `0`。过渡过程由低层完成——这符合即时性原则：不存在“下蹲动作”，只有目标高度的变化。
- 参考系：随机器人水平朝向旋转的自身坐标系（yaw 系）。身体前倾不会改变“向前走”的水平含义。

### 4.2 末端通道（`eff_type, eff_side, tx, ty, tz`）

**指定一个末端，让它尽可能快地到达目标点；目标点变，末端就跟。**

- `eff_type=+1, eff_side=+1`：左手到 `(tx, ty, tz)`。
- `eff_type=-1, eff_side=-1`：右脚到 `(tx, ty, tz)`。
- 一次只有一个末端任务。左右手/脚的双端协调留给以后的扩展（若需要，再加一个动作槽位，不破坏现有字段）。
- `eff_type=0`：无末端任务。**只清空动作要求，不清空身体通道**——例如正在向左走、同时把手从打点目标释放回默认姿态。
- 收回末端的方式由上层选择：（a）给一串撤回目标点（例如胸前护架坐标或地面附近落点），或（b）直接 `eff_type=0` 回到默认姿态。两种都训练。
- 目标点坐标与身体通道同一参考系（自身 yaw 系，原点在躯干根部），单位米。

### 4.3 全零命令

`cmd = 0`（九个字段全零）是唯一的“完全待机”指令：不移动、不转向、标准高度、无末端任务 → 进入并保持 s42i 标准动态踱步。

注意与部分零命令的区别：

| 指令 | 移动 | 高度 | 末端 |
|---|---|---|---|
| 全零 | 停 | 标准 | 无 |
| `(0,0,0,0, +1,-1, tx,ty,tz)` | 停 | 标准 | 右手到点 |
| `(0.3,0,0,0, 0,0, x,x,x)` | 前进 | 标准 | 无（末端字段忽略） |

### 4.4 指令的持续性

每条指令在当前时刻整体有效，直到上层改写。策略端对字段更新频率不做约束——但训练课程前期用较慢的指令切换（2~4 s 每段）帮助建立动作，后期逐步加快切换以训练响应速度。

## 5. 训练损失的含义

- **身体通道**：以短窗平均的真实 `v_xy`、`ω` 与指令 `(vx*, vy*, w*)` 的误差为损失（接近越快越好、超调扣分）；`h` 通道以躯干高度与 `h*` 的误差为损失。身体三项可同时训练——前进时要求 `w=0` 不漂移，原地转时要求 `v_xy=0` 不位移。
- **末端通道**：损失围绕“末端与目标点的距离 + 逼近速度”——距目标越近、朝目标运动越快，得分越高；到达后保持在容差内。目标点持续变化时自然覆盖“出击”与“收回”两个方向，无需区分模式。
- **平衡约束（始终生效）**：站立势能、摔倒惩罚与现有标准片段奖励继续在线；除明确允许“破势”的窗口（受推瞬间、末端任务需要的越界伸展）外，平衡约束优先于任务通道。
- **标准动作恢复**：`r_std_clip`（s42i 片段匹配）只在“身体通道全零 + 末端无任务”的待机段全量生效；移动/下蹲/末端任务期间用宽松项（pose 临近 + 节奏自相关）保持步态活性，不强制逐帧贴合原地片段——前进的步态本来就不是原地步态。

## 6. 分阶段训练

低层策略沿用 66 维契约后，按以下顺序扩展能力：

| 阶段 | 身体通道 | 末端通道 | 说明 |
|---|---|---|---|
| S1 起身+标准步态 | 全零 | 无 | 已完成（65 维阶段产物迁移） |
| S2 抗扰恢复 | 全零 | 无 | 正在进行 |
| S3 平移+转向 | `(vx, vy, w)` 低速→连续 | 无 | 含停止指令恢复标准步态 |
| S4 手部到点 | 低速移动为主 | 手 L/R 打点+收回 | 边移动边出手 |
| S5 腿部到点 | 低速移动为主 | 脚 L/R 踢点+收腿 | 含支撑脚切换协调 |
| S6 高度控制 | 加入 `h` 偏移 | 保留 | 下蹲/蹲姿移动/起身恢复站姿 |

S3–S5 期间 `h` 固定为 `0`，先不开放。每个阶段持续混入之前所有任务的样本，防止旧能力退化；各阶段之间 checkpoint 顺序传递，不回头重训。

## 7. 与现有 65 维实现的差异

- 旧契约把移动编码为“方向 ± 相位”，并把末端目标点与 phase 混在 `cmd[3:7]`；新契约把移动扩展为 `(vx, vy, w, h)` 四元组，末端目标点独占 `tx, ty, tz` 三维。
- 旧契约中 `act_mode`（idle/locate/strike）和 `phase` 被删除——即时性原则下不需要动作模式或进度字段；到达快慢由奖励函数衡量，不由指令声明。
- 维度 8 → 9，观测 65 → 66。加载旧 checkpoint 时按“新增第 9 维命令权重置零 + `h` 字段补 0”的方式迁移，全零命令行为与旧策略一致。

## 8. 后续扩展预留

- 双末端同时任务：再加一个末端槽位（`eff_type2/side2/txyz2`），不动现有 9 维。
- 更高层复合语义（方向性打击、格挡姿态）：由上层用目标点轨迹表达，低层不新增模式字段。
- 对手/场地感知：对手观测（39 维）属于上层策略的输入，不进入低层指令空间。
