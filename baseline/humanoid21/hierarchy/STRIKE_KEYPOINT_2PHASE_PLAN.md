# 两端点关键点打击训练方案

> 状态：待实现的实验方案。对应新实验建议命名 `strike_keypoint_2phase`。
> 本文定义关键点版尝试；关节角版本见 `STRIKE_2PHASE_PLAN.md`，
> 其实现审计见 `STRIKE_2PHASE_AUDIT.md`。

## 1. 目标与范围

只训练 `jab_l / jab_r / heavy_l / heavy_r`，仍分两阶段：

1. 从热身结束状态到 Clip 0 的准备姿态。
2. 从准备姿态到 Clip landing 的出拳终态。

姿态目标改为机器人关键点位置，不再以参考关节角作为奖励或成功判据。
策略通过当前关键点到目标关键点的差向量获知任务，学习平衡、协调和接触。
只比较两个端点，不增加中间帧跟踪；收招不在本次目标内。

总共 **3 个奖励通道**：

- `r_kp_p1`：阶段一关键点位置误差，成功尾帧额外 +1。
- `r_kp_p2`：阶段二关键点位置误差，成功尾帧额外 +1。
- `r_potential`：保留 `0.01 × min(phi, 0.9)` 的稠密护栏。

不设置关节角、方差、后脚位移独立通道。后脚作为普通关键点参与
阶段二的位置误差计算，只是它的目标固定在过门当帧的实际位置。
新实验直接继承 `CombatExperimentPPOBase`。

## 2. 关键点集合：15 个，顺序固定

所有点都定义在 **humanoid21 机器人模型**上。左右为机器人解剖左右，
镜像 clip 使用其自身 retargeted 数据，不沿用 `_src.npz` 的人体标号。

| 索引 | 名称 | 精确取法 | 目的 |
|---|---|---|---|
| 0 | `head` | `head` body 原点，当前模型为头部球体中心 | 头部位置 |
| 1 | `torso` | `torso` body 原点，即模型 root 位置 | 上躯干位置 |
| 2 | `pelvis` | `pelvis` body 原点 | 腰胯中心位置 |
| 3 | `shoulder_left` | `shoulder1_left` 关节的世界锚点 | 左肩位置 |
| 4 | `shoulder_right` | `shoulder1_right` 关节的世界锚点 | 右肩位置 |
| 5 | `elbow_left` | `elbow_left` 关节的世界锚点 | 左肘位置 |
| 6 | `elbow_right` | `elbow_right` 关节的世界锚点 | 右肘位置 |
| 7 | `hand_left` | `hand_left` body 原点，即手部球体中心 | 左手位置 |
| 8 | `hand_right` | `hand_right` body 原点，即手部球体中心 | 右手位置 |
| 9 | `hip_left` | `hip_x_left` 关节的世界锚点 | 左髋位置 |
| 10 | `hip_right` | `hip_x_right` 关节的世界锚点 | 右髋位置 |
| 11 | `knee_left` | `knee_left` 关节的世界锚点 | 左膝位置 |
| 12 | `knee_right` | `knee_right` 关节的世界锚点 | 右膝位置 |
| 13 | `foot_left` | 左脚 body 上固定的足底中心标记点，见下文 | 左脚位置 |
| 14 | `foot_right` | 右脚 body 上固定的足底中心标记点 | 右脚位置 |

增加左右肩、左右髋的目的是让肩线、髋线及躯干相对转向也被位置集合
描述；不另外增加朝向奖励。这里“腰”明确指 pelvis 中心，配合 torso
点描述上下躯干关系，不把人体腰部观测与机器人 root 混用。

### 关节锚点与 body 原点不能混淆

实时端使用 simulator 暴露的世界关节锚点，或按
`body_xpos + body_xmat @ joint_local_pos` 计算并与 MuJoCo `xanchor`
验证一致。不能将 `shin` body 原点直接当膝关节：当前模型的 knee
具有局部 `pos=(0,0,0.02)` 偏移。目标端必须使用完全相同的取点函数。

### 足底点的定义

足底点是固定在脚上的几何标记，不是每帧变化的接触力中心。
取该脚两条足底 capsule 轴线中点的平均位置，再沿脚局部 −Z 移动
一个足底 capsule 半径。当前 `battle_circular_v2.xml` 对应：

```text
foot_local_marker = (0.035, 0.0, -0.027) m
foot_world_marker = foot_body_pos + foot_body_rot @ foot_local_marker
```

实现时从编译模型校验这些几何参数，避免换模型后悄悄失配。
这与旧 observer 的 `foot` body 原点不是同一个点。
单个固定点允许脚绕该点转动，不等价于锁死脚掌姿态，也不直接保证承重。

## 3. 参考数据与目标预处理

SSOT 仍为 `assets/clips/full/` 的四个 retargeted `.npz`：

| 技能 | Clip | landing 控制帧 | 发力脚 |
|---|---|---:|---|
| jab_l | `hdm05_3146_88_2895_127` | 11 | 右脚 |
| jab_r | `hdm05_3146_88_2895_127_m` | 11 | 左脚 |
| heavy_l | `cmu_144_20_m_seg01` | 6 | 左脚 |
| heavy_r | `cmu_144_20_seg01` | 6 | 右脚 |

发力脚只按动作规则指定：heavy 为出拳侧，jab 为对侧。

已有 clip 的 `keypoints` 是 body 原点集合，不能直接视为上述完整点集。
从 Clip 0、landing 的 root 位姿与关节角，通过当前机器人模型的 FK
生成上述 15 点。关节角在这里仅用于**计算参考几何**，不作为学习目标。
可复用 `mocap/humanoid21/robot_kin.py`，以 MuJoCo FK/关节锚点作一致性基准。
派生缓存记录 clip、帧号、模型版本和点集版本，不建立另一套手写参考数据。

训练前检查四种动作的两个端点：

- 目标与实时取点在相同 qpos 下应一致（数值误差范围内）。
- Clip 0 先对整个姿态做统一的 Z 平移，使最低脚部碰撞几何与地面
  接齐；不逐点随意修改位置，不用当前机器人高度代替参考高度。
- 检查非脚部穿地、自碰撞和支撑条件。统一抬高不能修复身体穿插。
  如仍有冲突，先生成经检查的可行端点并记录调整，不能把冲突交给 PPO
  硬学，也不能悄悄改动 SSOT。
- landing 经下面的发力脚锚定后也必须检查几何可行性。不要通过
  单独裁剪某个关键点的 Z 来制造不属于任何机器人姿态的目标。

## 4. 世界系目标：每个阶段只生成一次

令 `P0_i`、`PL_i` 为参考准备/落地帧的关键点，`ψref0` 为参考 Clip 0
的 root 水平朝向，`Rz` 为只绕世界竖直轴旋转的矩阵。

### 阶段一：锚定热身结束时的 XY 与 yaw

热身结束、第一步 action 之前，记录机器人 root 的 XY 与 yaw `ψs`。
以 `R1 = Rz(ψs − ψref0)` 旋转参考姿态，再统一平移，使参考 root 的
XY 对齐机器人当前 root XY；Z 使用 §3 的地面校准。

得到 `T1_i` 后冻结，直到阶段一结束。不能每步用当前骨盆重新生成
目标，否则整体漂移时目标也会跟着跑。

### 阶段二：用实际发力脚位置锚定 landing

首次准备达标帧 `g`，记录实际足底标记位置 `A = p_rear(g)` 和
机器人 root yaw `ψg`。令：

```text
R2   = Rz(ψg − ψref0)
T2_i = A + R2 @ (PL_i − PL_rear)
```

因此 `T2_rear = A` **精确成立**。所有其他关键点共享同一个刚体变换，
保留 landing 的完整几何关系。使用参考准备帧 yaw 作对齐基准，
而非把 landing 自身 yaw 消掉，保留参考从准备到出拳的转体。

`T2` 在过门帧构建并冻结，下一 action 使用；阶段二后脚每帧都与
同一个 `A` 比较。不更新锚点，不把机器人当前后脚位置作为新目标。

固定目标提供的是持续的位置误差约束，并非物理硬锁：后脚移动会
增加 `r_kp_p2` 的损失，但仍可能与其他点产生权衡，也可能离开后回来。
本版不增加额外通道或隐藏的轨迹成功条件；另报全阶段最大后脚位移，
用实测判断这个约束是否足够。

## 5. 观测：让当前目标直接可见

当前阶段使用冻结的世界系目标 `T_i`。逐步计算：

```text
delta_i_world = T_i − p_i
delta_i_ego   = Rz(−ψcurrent) @ delta_i_world
```

只旋转差向量，不重新平移目标。保留世界竖直方向，使高度误差不因
机器人侧倾而被掩盖。误差转换前后的欧氏长度相同。

第一版新 actor 输入 **105 维**，顺序明确：

| 内容 | 维数 | 定义 |
|---|---:|---|
| 本体观测 | 57 | 沿用现有本体接口，包含自身关节角/速度等 |
| 目标关键点误差 | 45 | 按 §2 顺序排列的 15×3 个 `delta_i_ego / 1m` |
| 阶段 | 2 | p1=`[1,0]`、p2=`[0,1]` |
| 剩余预算 | 1 | 当前 action 前还剩多少步，除以 30 |

保留自身关节角作为本体感觉，不等于用参考关节角训练。
误差首版不做硬截断，避免较大偏差失去方向和幅度信息。
actor/critic 使用相同任务观测；剩余时间使固定预算任务可观测。
不再把旧的 9 维命令或按时间回放的手靶作为本版 actor 的任务输入。
语义技能由任务层转换成目标点集；低层负责到达该目标。

## 6. 奖励：两条位置通道加一条护栏

第一版 15 个点均取 `w_i=1`。统一长度尺度 `s=1m`：

```text
L_kp(t) = Σ_i w_i × ||T_i − p_i(t)||² / (s² × Σ_i w_i)
r_kp(t) = −L_kp(t) + 1{本阶段首次成功}
```

这是按点平均的平方欧氏距离，不再额外除以 XYZ 的维数。
属于每步负误差奖励，不是势函数差分。

| 通道 | 活跃区间 | AW 初始值 |
|---|---|---:|
| `r_kp_p1` | 阶段一 | 4 |
| `r_kp_p2` | 阶段二 | 4 |
| `r_potential` | 所有保留的训练帧 | 1 |

后脚只占点集中一项，不重复加罚。首次成功 +1 只发一次，
后续丢弃帧没有 actor/critic 更新。仍关闭 confidence gating，避免
新 critic 冷启动时让任务通道退出 actor 更新。

注意 `phi` 是已有多阶段站立势能，包含高度、接触和承重，不是米。
`min(phi,0.9)` 不能被解释为“身高超过 0.9m 就不影响”。
框架会分别标准化通道 advantage，0.01 也不等于 actor 贡献缩小百倍。

## 7. 成功判据与轨迹

关节量程 5% 不再适用。以下为**本尝试建议初值，尚未实测校准**：

- 两只手、两只脚：每点位置误差 ≤3cm。
- 其余 11 点：每点位置误差 ≤5cm。

两阶段均要求**所有点同时达标**，不使用均值过门；脚目标在阶段二
按 §4 锚定，因此发力脚也必须满足同一位置容差。判据是端点位置，
不暗含速度阈值、触地承重或持续若干帧保持要求。

30 步从热身结束后开始计数，两阶段共享预算：

- 阶段一：从首个 action 到准备首次达标 action 的后状态 `g`，包含
  成功帧；p1 尾帧额外 +1。
- 阶段二：从下一 action 到 landing 首次达标 action 的后状态 `l`；
  p2 尾帧额外 +1，`l` 后帧全部丢弃。
- 30 步仍未过门：只有失败 p1；过门但未到 landing：保留失败 p2。
  失败没有成功奖励，也不能丢掉失败样本。
- 每条任务通道在成功或预算耗尽时终止，尾值为 0。
  护栏仅在内部 p1→p2 边界 bootstrap；最终结束时尾值为 0。
- 第一个 action 前即使初态已达标，也先执行并评价一个 action，
  不创建零长度 trajectory；末步才过门时无 p2 trajectory。

每段只挂所属阶段的位置通道及护栏。过门状态的 p1 reward 先计算，
随后构建 T2，输出下一 action 的 p2 observation，避免 reward/目标错位。

## 8. 初始化与 warmup：必须处理新旧接口差异

仍从用户指定的 `train_skill_full_mbs_ppo_20261020_104315` 最后
checkpoint `u06685` 提取 actor 基底，但旧 actor 是 66 维，新 actor
是 105 维，**不能直接 resume 整个模型与 optimizer**。

建议迁移：首层保留前 57 个本体输入的权重，新任务输入列初始化为
0；保留首层 bias、后续隐藏层与输出头。重新建立 actor optimizer，
所有 critic 冷启动，训练计数从 0 开始。迁移前后以同一本体观测、
旧命令为零验证初始 actor 输出一致；记录迁移来源与输入契约。

热身仍独立均匀抽技能（11 个基础技能，排除当前目标打击），步数
均匀 `[0,20]`。但 warmup 使用**冻结的 u6685 原 66 维策略**：
新 105 维低层仅训练关键点到达，不能直接传给需要旧语义命令的
`WarmupSteppingPlugin`。这样还可固定起手分布，便于比较学习进展。
热身状态写回后才建立关键点目标；热身帧不训练。

正式目标仅四种打击，先保留现有镜像侧 ×2 的目标技能采样权重。
这与 warmup 技能均匀采样是两套独立分布。

## 9. 验证与监控

实现前/实现后应逐项验证：

1. 四个 clip 的首末帧、左右映射、15 个取点定义、地面和碰撞校验；
   展示机器人模型与目标点叠图，不仅看原始人体视频。
2. 更换世界 XY/yaw 时误差不变；阶段内目标世界位置不漂移。
3. p2 的 `T2_rear` 与 gate 当帧 `p_rear` 相等；移动后脚会直接增加
   同一位置通道的损失，期间没有重锚定。
4. dump 逐帧复算误差、reward、成功 +1、轨迹包含端点与失败尾值；
   critic 的任务回报上界仍为 +1，不再出现无依据的大正估值。
5. 四种动作先做短 rollout 与 PPO smoke，再判断是否值得完整训练。

逐技能输出：p1 成功率、完整 p2 成功率（分母为全部尝试）、
p2 条件成功率（分母为进入 p2 的尝试）、两个阶段耗时、
逐点误差及最差点名称、目标位置 RMSE、后脚全阶段最大位移、
脚部触地/承重诊断和跌倒率。误差统计截到训练使用的阶段终点，
不能把成功后丢弃的帧混进去。

本版验证的是“从不同起手姿态到准备，再到出拳终态”。
仅凭端点到达和后脚点位稳定，不能宣称已学到参考中间路径或发力质量。
