# 手臂劫持机制（ARM_TAKEOVER）

> 概念与机制说明：动作子集被外部指令接管时，指令如何作用于
> 系统的两种载体形式，及各自在训练/推理时的含义。
> 实现参数与文件索引在文末附录。决策依据见 DECISION_LOG
> D6/D10/D17/D18。

## 1. 问题

策略的 21 维动作中，有 6 维是双臂关节。"手臂劫持"讨论的
是：**当一条外部指令流要接管这 6 维时，指令应该在哪一层
起作用**。

**直接目标**：让手臂关节可被指令直接控制——这条 obs→动作
的指令通道本身就是要建的能力（出拳/抱架等技能将来的"目标
姿态"都走它）。

它对**平衡**的附加影响有两个（是后果，不是目的）：

- **扰动源**：臂部动作本身扰动平衡——指令驱动臂运动时，
  策略需在扰动下维持站立
- **失去平衡手段**：臂维被指令占用期间，策略少了双臂这个
  抗扰/恢复工具

## 2. 两种载体形式

**硬劫持**——指令作用于**执行层**：环境在动作下发前把臂维
替换为指令值。策略输出的臂维永不执行。

**软劫持**——指令作用于**优化目标层**：指令只出现在观测和
奖励里，动作原样执行。是否跟随由策略在奖励权衡中自行决定。

一句话差别：**硬劫持是"执行 ≠ 策略输出"，软劫持是
"执行 = 策略输出 + 奖励引导"**。

## 3. 共有机制（概念件）

两种形式共享三个抽象组件，与载体形式无关：

- **指令流**：外部产生的臂关节目标序列，写入观测的专用段
- **观测承诺（同源契约）**：obs 中的指令字段 = 本步将被参考
  （硬劫持：被施加；软劫持：被对照计分）的那个目标。观测纯读
  无副作用——训/部任何时钟下读到的都是同一承诺
- **适用条件（flag）**：劫持概念上只在"机器人站稳"时成立
  ——起身/摔倒期占用臂维既无意义也有害。硬劫持用它硬门控
  覆写；软劫持里它退化为信息位

## 4. 训练时的差别

| | 硬劫持 | 软劫持 |
|---|---|---|
| MDP 性质 | **变换 MDP**：执行的是 f(act) 不是 act；轨迹存的是覆写前输出 | 标准 MDP |
| 信用分配 | 臂维优化从未执行的动作，logprob 与执行不符——死动作维，off-policy 污染（实测干扰下游任务学习） | 执行=输出，PPO 数据干净 |
| 跟随判定 | flag 硬门控：站稳即强制 | **学到的权衡**：站稳时跟随拿分，失衡时指令惩罚被 fall/potential 盖过——"该忽略时忽略"是学出来的 |
| 信号形态 | 无奖励信号（指令即命运） | 逐帧误差奖励（稠密；权重需压住不喧宾夺主） |

## 5. 推理时的差别

- **硬劫持**：完整系统 = 策略 + 指令源 + flag 状态机 + **覆写
  执行器**。缺了覆写层，策略臂维输出的是训练中从未被执行的
  漂移值——双臂行为未定义。策略单独不可部署
- **软劫持**：策略自洽——臂输出是真实动作。部署只需一个往
  obs 写目标的**指令源**（随机脚本/规划器/对手推导/人工皆可
  换）；"该忽略时忽略"的仲裁逻辑在权重里，随之带走

## 6. 一句话选型

硬劫持只有"必须物理强制臂执行"时才成立（例如指令就是安全
约束）；其余场景软劫持是更干净的默认——机制更简单、训练更
健康、部署更轻。

## 附录 A — 实现细节（本仓库）

### A.1 布局

- 臂关节：`act[15,16,17]`=右 shoulder1/shoulder2/elbow，
  `act[18,19,20]`=左（镜像轴，同 norm 值=镜像运动）
- 指令段：`obs[57]=flag`，`obs[58:64]=arm_tgt=[右3|左3]`
  （norm 空间=action 空间，可与 act 直接比距离）
- 指令源：`ArmScript`——每臂独立倒计时，到点重采目标
  `U(-1,1)`³ + 保持时长 `U(2,20)` 帧；两臂×双机独立 rng
- flag 判据：h>1.10m 计时，低于阈值宽限 5 帧清零，满 20 帧
  → flag=1（与推力插件同一站立判据）

### A.2 软劫持奖励

每帧 `err_r=‖act[15:18]−tgt[0:3]‖`、
`err_l=‖act[18:21]−tgt[3:6]‖`；通道 `r_arm_r/l = −w·err`，
w=1.0，aw=0.5（次要任务，权重故意低于 fall/potential）。
已知风险：稠密通道梯度占比高（实测 clip_frac ~0.85-0.98，
框架逐通道 clip 兜底）；若 arm_err 长期不降=学成全忽略，
调 w_arm 或改到期稀疏结算。
