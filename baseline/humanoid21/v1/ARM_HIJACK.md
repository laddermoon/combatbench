# 手臂劫持机制（ARM_HIJACK）

> 定位：说明"手臂指令接管双臂"这一机制的设计、两种载体形式
> （硬劫持/软劫持，D18）在**训练时**与**推理/部署时**各自的
> 工作方式。决策依据见 DECISION_LOG D6/D10/D17/D18。

## 1. 是什么

人形双臂 6 关节对平衡而言是弱驱动——它可以是抗扰工具，也可以是
被指令占用的执行器。"手臂劫持"指**把 act[15:21] 这 6 个臂关节的
控制权交给一条外部指令流**，让策略在"双臂不归自己"或"双臂有
外部任务"的条件下完成主任务（平衡/步令）。

两个目的：

- **作为扰动**：撤掉双臂这个抗扰手段（S3 的设计动机——推着
  机器人又不让它用手撑）
- **作为指令通道的载体试验**：将来出拳/抱架等技能的"目标姿态
  指令"复用同一条 obs→动作通道；先验证指令能不能被跟随

### 硬件布局（两套方案共用）

| 项 | 值 |
|---|---|
| 臂关节 | `act[15,16,17]` = 右 shoulder1/shoulder2/elbow；`act[18,19,20]` = 左（镜像轴，同 norm 值=镜像运动） |
| 指令段 | `obs[57]=flag`，`obs[58:64]=arm_tgt=[右3|左3]`（norm 空间=action 空间，可与 act 直接比距离） |
| 指令源 | `ArmScript`：每臂独立倒计时，到点重采目标 `U(-1,1)`³ + 新保持时长 `U(2,20)` 帧；两臂×双机共 4 条独立 rng |
| flag 门控 | 站立状态机：h>1.10m 计时+1，低于阈值宽限 5 帧清零，满 20 帧→flag=1（与推力插件同一判据） |
| 同源契约 | `obs[t]` 的 arm_tgt = 本步将被参考/施加的目标——观测无副作用，任何时刻读都是"当下承诺"（D6） |

## 2. 硬劫持（hard takeover）

**指令不经过策略输出**——环境把 `act[15:21]` 直接覆写为脚本目标。

### 训练时

- `V2Simulator(arm_script=True, arm_override=True)`（S3/S4-接管组）
- `set_action` 每帧：flag=1 → `act[15:21]=script.current` 后施加；
  flag=0 → 动作原样通过（起身/摔倒期策略自控双臂）
- **轨迹存的是策略原始输出**（覆写前的 act），不是实际执行的动作
  → 变换 MDP 上的标准 PPO：臂维优化一个从未被执行的动作，
  logprob 与执行不符，成"死动作维"只剩有界漂移
- 已知代价（D17 动因）：S4 接管组 foot_rate 贴死基线 vs noarm
  正常爬坡——off-policy 污染干扰学习的实测证据

### 推理时

- **仿真 eval**：零适配——覆写在 env 内，导出策略直接跑
- **仿真外部署**：必须完整复刻三件套——flag 状态机（要读
  root_z）、指令源（产生 arm_tgt 写 obs）、执行层覆写
  （act[15:21] 在下发前被替换）。**少了覆写层，策略臂维就是
  死维**：输出的是训练中从未被执行的漂移值，双臂行为未定义
- 即：硬劫持策略的"完整系统"= 策略 + 劫持执行器，缺一不可

## 3. 软劫持（soft takeover）

**指令照常进 obs，act 不覆写归策略全权；跟随压力由奖励表达。**

### 训练时

- `V2ArmCmdSimulator`（`arm_override=False`，v2_s3_armcmd）
- 同款 ArmScript 指令流写 `obs[58:64]`，flag 保留但**仅作信息
  位**，不门控任何东西
- 每帧结算 `err_r=‖act[15:18]−tgt[0:3]‖`、
  `err_l=‖act[18:21]−tgt[3:6]‖`，奖励通道
  `r_arm_r/l = −w·err`（w=1.0，aw=0.5 次要任务权重）
- **执行动作=策略输出**，PPO 信用分配干净；"要不要跟"是策略
  学到的权衡——站稳时跟随划算（白拿分），失衡/受推时自行压掉
  指令保平衡（aw 差距让 fall/potential 主导）

### 推理时

- **策略臂输出是真实动作**——部署只需往 obs[58:64] 写目标，
  来源任意：随机脚本、规划器、对手姿态推导、人工指令皆可
- 不需要 flag 状态机、不需要覆写执行器；"该忽略时忽略"的行为
  随策略权重一起带走
- 注意 obs 承诺语义仍成立：奖励参照的是**写入 obs 的当期目标**，
  部署侧指令源要保证 obs 里的 tgt 与意图一致

## 4. 对比

| | 硬劫持 | 软劫持 |
|---|---|---|
| act[15:21] 归属 | env（flag=1 时） | 策略全程 |
| 指令约束力 | 强制（物理覆写） | 奖励诱导（可选忽略） |
| PPO 数据 | 臂维 off-policy 死维 | 干净 |
| 跟随判定 | flag 硬门控 | 学到的权衡 |
| 部署依赖 | 需指令源+覆写执行器 | 只需指令源写 obs |
| 代表 run | v2_s3_balance_arm、S4 接管组 | v2_s3_armcmd |

## 5. 已知风险与观察项

- **硬劫持**：臂维死动作维是结构性缺陷，不是 bug；已观测到其
  对下游任务（步令）的学习干扰。仅当"必须物理强制臂执行"时
  才有存在理由
- **软劫持**：稠密奖励通道初期梯度占比高（首测 grad_clip_frac
  ~0.85，框架逐通道 clip 兜底）；arm_err 长期不降→策略学成了
  全忽略（合法但白挂通道）→ 调 w_arm 或改到期稀疏结算
- **共同**：flag/arm_tgt 占 obs 语义位，部署方变更需同步
  DATASPEC
