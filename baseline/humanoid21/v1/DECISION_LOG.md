## D1 — 第一阶段技能指令编码：6 维脚手分解码（v0，非最终方案）

**日期**：2026-11-16 ｜ **状态**：已采纳（v0）

**背景**：`bootstrip.md` 问题一。策略输入 = 本体观测 + 技能信息，不含对手信息。
原设想是二进制形式的"脚步动作编码 + 脚步参数 + 手部动作编码 + 手部参数"，
待评估点是不同技能间能否共享能力、互不打架。

**决策**：第一阶段采用 6 维技能指令，脚手两组各 3 维：

| 字段 | 取值 | 语义 |
|---|---|---|
| `step_enable` | 0 / 1 | 是否要求本步完成一次前迈 |
| `step_side` | +1 左 / −1 右 | 迈出的脚 |
| `step_size` | −1 小 / 0 中 / +1 大 | 步幅档（预留，当前固定 0） |
| `punch_enable` | 0 / 1 | 是否要求本步完成一次直拳 |
| `punch_side` | +1 左 / −1 右 | 出拳手 |
| `punch_height` | −1 低 / 0 中 / +1 高 | 打点高度档（预留，当前固定 0） |

**编码规则**：

- 开关：`0/1`
- 左右侧：`±1`（对称表达，沿用 hierarchy `eff_side` 惯例）
- 有序档位（大小、高低）：**单维三态 `−1/0/+1`**——一维浮点只取三个离散值
  即可表达三档，同时保留"小–中–大"的距离结构
- 无序类别（未来动作类别扩展时）：预留 one-hot，不采用无语义的二进制编号

**约束与说明**：

- 通道关闭时其参数统一置 0（不出拳则 `punch_* = [0,0,0]`），避免无意义参数
  成为输入噪声
- "不要求前迈" ≠ 禁止腿部运动——腿仍参与平衡与发力；是否必须完成一次脚步
  由技能契约与边界定义（`bootstrip.md` 问题五）
- 脚手两组指令可表达组合技能（如"同一步内前迈刺拳"），但组合可用性须单独
  训练与验证，不随单项技能自动成立
- 第一阶段实际变化 4 个技能（左/右前迈 × 左/右直拳），`step_size` /
  `punch_height` 为预留维度
- **本方案明确不是最终协议**：6 维只覆盖"技能选择"部分；"本步上下文"
  （相位、剩余预算、事件信息等，`README.md` §3、`bootstrip.md` 问题五）
  是否进入网络输入、以何种形式进入，待动作边界问题讨论后定稿。注意旧
  hierarchy 实现中移动目标点本身携带了相位信息，固定技能码不含相位——
  不要靠编码方案回避起始/终止态混淆问题
- **已知风险**：技能间能力共享与梯度冲突（步态与出拳共享躯干/重心控制）
  只能靠组合训练与成功率实验检验，编码形式只能缓解不能保证

**第一阶段四技能指令编码**（向量序 = 上表字段序）：

| 技能 | `step_enable` | `step_side` | `step_size` | `punch_enable` | `punch_side` | `punch_height` |
|---|---|---|---|---|---|---|
| 左前迈 | 1 | +1 | 0 | 0 | 0 | 0 |
| 右前迈 | 1 | −1 | 0 | 0 | 0 | 0 |
| 左直拳 | 0 | 0 | 0 | 1 | +1 | 0 |
| 右直拳 | 0 | 0 | 0 | 1 | −1 | 0 |

- `side` 语义：`step_side` = 迈出的脚，`punch_side` = 出拳手；+1 = 左，−1 = 右
- 按通道关闭规则，未启用通道的参数位一律为 0
- 全零 `[0,0,0,0,0,0]` = 无技能指令；其语义（原地保持/自由平衡）待技能契约
  定稿，第一阶段不当作技能训练
- 组合码（如 `[1,−1,0,1,−1,0]` = 右前迈 + 右直拳）语法上合法，但第一阶段
  不训练、不保证可用——组合技能是后续验收项而非初始训练目标

## D2 — 训练起点：hier_s2_balance_s42i_b 最新 checkpoint（u01680）

**日期**：2026-11-16 ｜ **状态**：已采纳

**背景**：`bootstrip.md` 问题七。沿用 hierarchy 课程（站立→迈步→扰动平衡）
先获得平衡与步态先验，再训技能；研发摸索期优先复用已训好的扰动平衡策略。

**决策**：以
`baseline/runs/hier_s2_balance_s42i_b/checkpoints/checkpoint_u01680.pt`
（该 run 最新 checkpoint）作为第一阶段训练的 warm-start。

- 策略类：`StateMixtureBoundedStdTruncatedNormalPolicy`
  （`init_policy_mbs_66d.yaml`），obs_dim=66、action_dim=21、
  hidden_dim=256、num_components=3
- 输入保持 66 维不变：57 维本体观测语义不变 + 原 9 维指令槽位中
  **只用 6 维**承载 D1 技能码，其余 3 维置 0
- v0 约定：技能码放指令块前 6 维（cmd[0:6]），cmd[6:9] = 0；
  槽位分配为可调整的实现细节，在实验配置中固定

**已知限制**：

- 9 维指令槽位的旧语义（vx, vy, w, h, eff_type, eff_side, txyz）与新 6 维
  技能码语义不同——指令块对应的首层权重携带的是旧指令的解释，续训中需要
  重新学习指令块语义；复用的主体是**本体观测通路的表征与平衡/步态控制
  先验**
- 该策略训练分布是连续即时伺服指令，未见过"步边界技能"语义；平衡/步态
  先验可复用，技能语义需新学
- 混合策略（num_components=3）对全新指令分布的响应未经检验——若续训
  初期表现异常，考虑对照"仅迁本体权重"或全新初始化
- 研发验证通过后，按 `bootstrip.md` 问题七做正式重训

## D3 — 第一阶段简化：前序技能链式起点池 + 整段结果评分

**日期**：2026-11-16 ｜ **状态**：已采纳

**背景**：README §4-§5 的完整方案（起点池自扩展、步内中途改选、rollout
可行性查询）会被问题四/五的复杂度卡住。先做简化版闭环，把"技能定义 +
引导训练"打通；中途切换、可行性查询、候选流形推迟到后续阶段回填。

### 简化一：前序技能链式起点池（不支持中途切换）

每轮迭代（一个或几个 update）：

1. 迭代前：每个技能有**候选起点状态集** C（首轮 = READY 等预定义起点）
2. 迭代后：基于最新策略评估，得到**可用起点状态集** U ⊆ C
3. 对 U 中起点执行 rollout，取其执行尾状态构成该技能的**终止状态集** T
4. 下轮迭代前：技能的候选起点 = 其所有前序技能终止状态集的并集
   `C_A ← ∪_{B ∈ pred(A)} T_B`

约定：

- 技能只能从指定前序技能的终止状态出发——不支持步内中途切换；
  中途接管、重锚定、可行性 rollout 全部推迟
- 每个技能需要定义它的**前序技能列表**
- 前序关系 = "允许尝试接续"，不承诺已支持；候选集中保留一部分
  READY 与历史成功起点，防止技能退化导致后继起点断供
- "终止状态"第一版只取执行明确结束的那一帧——取尾几帧会把未完成
  中间态混入，重新引入中途语义
- "可用起点"按当前策略版本理解，非永久标签

### 简化二：只定义执行结果，不设计过程轨迹

- 不人工设计技能的 CPose 过程（动画制作成本高，做不好有误导性）——
  把姿态设计问题变成奖励引导问题
- 结果由**整段评分函数**定义：输入为一次完整执行的 clip（RobotState
  序列），输出单分；一次执行（<0.5s）只给一个整体评分，不分帧
- 三个评分维度：
  1. `score_com` — 质心运动状态与支撑稳定性
  2. `score_step` — 脚是否迈到指定位置
  3. `score_posture` — 终点姿态接近程度与运动过程表现
- 评分实现不限（不要求 CPose），可用 clip 内任意帧信息
- 已落地为 `skills/base.py` v0 契约：`name/instruction/step_budget +
  三个 score_* 方法`；locate/reference/谓词等全部移除

### 奖励传递约定

三维度各成一个 reward channel，clip 末帧结算、actor_weight 全程放开
（`skill_step_mbs` 教训：只在结算帧给 actor_weight 会把准备动作的
学习信号掩掉）。

### 未决与注意

- 合格判定（尾状态能否入终止状态集）仍需少量明确条件，不只看加权
  总分——如"迈到点但已倒"不合格
- 直拳技能评分中必须有明确的打击到位判定，否则"站着不动"也能拿
  高姿态分
- 固定执行时长意味着暂不追求提前完成/速度最优
- 中途切换、可行性查询、自扩展起点池等 README 完整方案能力推迟，
  本简化收敛后再回填

## D4 — 奖励时间分配：γ=λ=1.0 蒙特卡洛 + trim_clip 裁剪结算

**日期**：2026-11-16
**状态**：已定稿（v0）

### 决定

1. **三通道 `gamma=1.0, gae_lambda=1.0`**：整段评分任务用蒙特卡洛
   advantage，`A_t = S − V(s_t)`（REINFORCE-with-baseline 标准形）。
   原 γ=0.99/λ=0.95 下末端稀疏分经 `(γλ)^T` 双重衰减，到第 0 帧
   只剩 ~9%；γ=1 同时让 critic 回归目标变平稳（E[S] 而非逐帧
   衰减的 γ^{T-t}E[S]）。
2. **否决"分数摊到每帧"方案**：摊分（r_t=S/T）本身合法且给出
   "前重后轻"的 credit 形状，但与裁剪组合后是**拖时间发生器**
   ——第 k 帧裁掉只发 S·k/T，早完成反而少拿分，系统性地奖励
   故意延迟完成。
3. **`Skill.trim_clip(clip) -> Optional[int]`**：技能契约新增裁剪
   判定方法，返回"任务已完成"的最早帧数 k；None=未完成/不裁剪。
   - step：摆动脚有效离地→过峰→踝高回落至近地 → 落地+3 帧 settle
   - jab：到位误差 argmin 帧（须 ≤0.16m 才算接近过）+ 5 帧回收余量
4. **裁剪即任务完成**：traj 截到 T_eff，三分在裁剪段上评、结算在
   第 T_eff-1 帧；`is_terminated=True`（对技能 MDP 是真终止，
   非 timeout 截断，V=0 bootstrap 语义正确）。
5. **终止状态回收点同步改为完成帧**：入池快照取 T_eff-1 的
   core_state（之前是 ep 末尾漂移态）。

### 语义与边界

- **速度中性**：早完成与晚完成回报相同——v0 不奖励也不惩罚
  速度；要奖励速度需显式加 `S·decay(t_done)` 类评分项（非本版）。
- **裁剪不终止物理 episode**：episode 跑满步数（observer 照录），
  截断只发生在 build_trajectories 的轨迹层。
- **仍存的退化风险**：非完成保底分（posture≈0.9 站桩）与完成分
  差距过大时，"拒绝尝试"是局部最优——靠 min-score 合格线防污染
  池子，若 step/reach 长期贴零再调分值结构（gating 式打分）。

## D5 — 手臂可脚本化假设的验证实验（arm_takeover）

**日期**：2026-11-17
**状态**：已验证（demo，未进训练管线）
**动机**：脚步+躯干是欠驱动、手臂不是——若手臂动作能用 IK+PD
脚本可靠产生，则可将"全身协调"问题缩小为"下肢在手臂运动时
维持平衡"问题。先验证两个前提：(a) 脚本能实现手臂动作；
(b) 现有平衡策略在手臂被接管后能否保持平衡。

### 决定

1. **关节划分**：臂 6 关节（action[15:21]，shoulder1/2/elbow×2）
   由脚本覆盖；躯干+双腿 15 关节继续由原策略输出。原策略 obs
   含手臂关节位置，能看到接管效果但无法控制。
2. **臂目标直接用归一化关节角指定**（=action 空间值，不经 IK）：
   每臂 `(shoulder1, shoulder2, elbow)`，左右同值即镜像
   （关节轴已按镜像设计）。IK/CPose 路线被放弃——对手向量
   选支不可控（能量最小支选鸡翅构型；肘下扣+颏部高手位又
   超 shoulder1 限位），关节角直接可控且姿势语义直观
   （JOINTSPEC.md 方向约定）。
   - 抱架 `(0.4, -0.3, 0.8)`：s1 pos=夹肘收臂、s2 neg=上臂
     后收锁肘于体侧、elbow pos=屈肘前臂竖护脸
   - 出拳 `(0.4, 0.8, -0.8)`：上臂前抬+肘近全伸直拳
     （e=-0.8 留余量不顶 -1.0 限位）
   - 设计流程：`Pose.render()` 离屏渲染迭代确认后进 rollout
3. **切换语义**：一次性切目标关节角并保持，无插值——PD 自行
   追踪（用户指定）。出拳目标保持 0.3s 后切回抱架。
4. **初始快照**：READY 全身 + 臂关节烘焙为抱架（第 0 帧即抱架）。
5. **序列**：抱架 1.0s → 右拳 0.3s → 抱架 1.0s → 左拳 0.3s →
   抱架 1.0s（72 步 @50ms）。

### 实测结果（s42i_b u01680，确定性 act）

v3 抱架/出拳（关节角直接指定）：

| 场景 | 存活 | max\|pitch\| | max\|roll\| |
|---|---|---|---|
| untouched（对照） | 72/72 | 0.37 | — |
| guard_hold（双臂接管抱架） | 72/72 | 0.43 | 0.23 |
| punch_seq（完整序列） | 72/72 | 0.43 | 0.24 |

（v1 IK 鸡翅臂 0.70 → v2 IK 肘下垂支 0.50 → v3 关节角抱架 0.43；
紧凑抱架使接管成本逼近 untouched 对照）

- **两前提均成立**：脚本臂动作可靠实现；策略全程无倒地。
- **代价**：pitch 峰值翻倍——未经适应训练的接管成本；暗示
  用脚本臂作扰动重训平衡策略有很大适应空间。
- **附带观察**：出拳帧中机器人正处于动态步态单腿抬起相——
  "脚步任意相位出拳"被动成立（双方互不感知，非协调结果）。
- com 漂移 ~0.7m/3.6s 三场景一致——策略固有踱步，非接管所致。

### 未决

- 出拳手实际到位略低于设计目标：臂目标是固定关节角（开环），
  运行中躯干倾斜变化后不跟踪。若后续要高精度出拳，需在躯干系
  在线 IK 或直接设定期望偏差。
- 本实验只验证了"接管不摔"。脚本臂作为**训练扰动**的路线
  （脚步训练时随机叠加脚本拳，逼下肢学补偿）尚未实施——
  这是解耦路线的正式下一步，届时再决定扰动强度 curriculum。
  → 由 D6 承接：观测编码与调度机制已定。

## D6 — 脚本臂指令入观测：6 维当前关节目标（无前瞻）

> 承接 D5 未决：脚步策略要能"预期"脚本臂产生的扰动，需把臂
> 指令放进观测。本决策定观测编码与调度一致性语义。

### 决定

1. **观测追加 6 维** = 双臂当前 PD 目标，顺序同 action
   `[s1_r, s2_r, e_r, s1_l, s2_l, e_l]`，值=本步实际施加的
   臂目标。obs 57+6=63 维，追加在末尾（57=本体感知42+全局
   状态13+触觉2，不含对手模块39）。
2. **物理关节目标编码，不用语义 one-hot**：
   - `cur_target − joint_pos` ≈ 未来数步 PD 拖臂方向与幅度——
     扰动方向/大小直接可算，不用策略自学动作→扰动映射；
   - 新姿态原语零成本进 obs，词汇表扩展不改编码；
   - 语义 ID（jab/body…）是战术层的关心，不进脚步 obs。
3. **无前瞻**：不报 next_target / t_until_next。理由（用户定）：
   实际用法中臂指令由上层即时下发，不存在可暴露的计划，
   即使有也会变。且 `cur_target` 自带隐式前瞻——指令下达
   瞬间 obs 即见目标位，而臂实际位置仍滞后 PD 追踪数步，
   "指令→到位"的时间窗本身就是预期窗口。
4. **观测完整性**（为何 6 维足够）：
   - 臂往哪走 → `cur_target`；
   - 臂走到哪/多快 → 已有 `joint_pos/vel_norm[15:21]`；
   - 瞬态 vs 稳态 → `pos≈target 且 vel≈0` 可推断，无需标志位；
   - 扰动何时结束 → 不需要，目标切换即指令切换，"回抱架"
     同样是瞬时指令。
5. **调度一致性语义**：step t 的臂指令在 step t−1 的
   post-step 阶段确定——保证 step t 的 obs 里的臂指令
   = step t 实际施加的臂指令，零延迟一致。若调度在
   `policy.act` 内才推进，obs 将滞后 50ms。
6. **ArmScript 单源**：常量指令表 + `next()→vec6` 每步
   推进；plugin（`on_pre_action_step` 覆盖 action[15:21]）
   与 observer（拼 obs）引用同一对象——调度与观测同源，
   承诺与执行不脱节。两模式：脚本序列（demo）/ 随机触发
   （训练扰动，随机臂×时机×原语，决定时刻在上一步
   post-step）。
7. **臂指令表 v1**（渲染确认的原语集合，obs 编码与之解耦）：

   | name | (s1,s2,e) | hold(步) | 代价档 |
   |---|---|---|---|
   | `guard_high` | (0.4,−0.3,0.8) | ∞ | T0 |
   | `guard_low` | (0.6,−0.2,0.45) | ∞ | T0 |
   | `neutral` | (−0.1,0.0,0.15) | ∞ | T0 |
   | `jab` | (0.4,0.8,−0.8) | 6 | T1 |

## D7 — 脚步指令编码：6 维参数化 + 横向用内中外（anatomical）

> **⚠ 已被 D13 取代**：维度形状保留但语义重定义（动作式→声明式
> 终态编码），横向不再用 anatomical。本节仅作历史参考。

> 上层策略（可 Code）向脚步策略下发的指令形式。参数化指令
> 取代技能枚举 ID——技能从"四件套"变为参数空间上的族，
> 评分函数需参数感知（score_step 目标 = 方向向量×步幅）。

### 指令布局（6 维，全零 = 原地小碎步保持平衡）

| 维 | 语义 | 取值 |
|---|---|---|
| 0 | 移动哪只脚 | −1 左 / 0 无 / +1 右 |
| 1 | 迈步方向·矢状 | −1 后 / 0 中 / +1 前（连续可用） |
| 2 | 迈步方向·横向 | −1 内 / 0 中 / +1 外（anatomical） |
| 3 | 步幅 | 标量（小→大，连续） |
| 4 | 朝向变化 | −1 左转 / 0 不变 / +1 右转 |
| 5 | 预留 | 0 |

### 决定：横向方向用内中外（相对于迈步脚的解剖方向），不用绝对左中右

理由：

1. **镜像对称免费**：左右关节轴已按"同 norm 值=镜像运动"
   设计。`[右脚,前,外]` 与 `[左脚,前,外]` 是严格镜像的同一
   个技能——策略学一遍镜像即得。用绝对系，`[右,前,右]`=开步、
   `[左,前,右]`=交叉步，同码不同几何，策略须自行内积出
   `脚×方向` 组合，训练更难。
2. **上层语义更诚实**：对 Code 战术层，"向左闪避"本来就分
   左脚开步/右脚交叉两种机制——anatomical 编码逼其显式选脚，
   不把机械差异藏进模糊编码里。
3. **朝向变化保持绝对系**（左=逆时针）：全身量不分脚。

### 语义细则

- `脚=0` → 本步不迈脚，原地小碎步维持平衡（冻结在动态平衡
  策略上不稳定，小碎步即 s42i_b 的天然行为）。
- `脚=0` 且 `朝向≠0` → 原地拧转（pivot），保留为原语。
- 矢状/横向两分量合成任意 ego 平面向量（前+内=前交叉步），
  连续编码比三态更通用；战术层可自行量化。

### 关联

- 脚步 obs（上层管线）：`[本体57 | flag(1) | 臂目标(6) | 脚步指令(6)]`
  =70 维；flag=0 起身期策略自控双臂、flag=1 被脚本接管
  （训练语义/翻转课程/臂头保温未决，详见管线讨论）。
- v1_train2 四技能 = 本参数空间四个点；评分函数待参数化改造。

## D11 — 臂描述符约定：按臂方位角 + 可选肘约束（默认自然肘）

> `arm_ik.py` 描述符语义的正式化。3 值核心 = 伸展度+极坐标
> （用户语言）；肘约束可省（默认自然肘），需要时再加。

### 决定

1. **azimuth 按臂约定**（替代原共享 torso 系）：左臂
   θ=atan2(+y,x)、右臂 θ=atan2(−y,x)——**θ>0=外展（远离
   中线）、θ<0=内收（穿中线）、0=正前、±180°=正后**。
   同一描述符在两臂产出镜像动作：锚点表只记一份、生成端
   无需分左右。代价：表达"两臂朝同一绝对方向"需生成端
   自行换算（罕见需求，且物理上多不可达）。polar/extension
   天然无歧义保持共享。`mirrored()` 退化为恒等。

   **极轴定义（用户拍板，v2 替代初版向下轴）**：极轴=肩心沿
   **外侧向**（右臂 −y、左臂 +y，按臂）；参考向=⊥极轴平面
   （x−z 矢状面）内 +x 前向。
   - azimuth θ=atan2(z,x)：0=前、+90°=天、−90°=地、±180°=后——
     **两臂同式**（σ 只在外展轴上）；矢状扫掠整圆连续
   - polar φ=与外展轴夹角：0=纯外展、90°=前平面、180°=穿中线，
     恒正
   - 语义红利：拳击动作本质是矢状面弧线（jab→上勾→后摆），
     圆坐标 θ 恰好落在该平面；三维参数单参正交——θ 管弧线
     高度、φ 管摆开宽度、ρ 管远近。拳击区 φ≈[25°,115°]。
     代价：φ=0 语义是 T-pose 非垂下（垂下=θ−90,φ≈60）；
     θ 退化点移至 φ≈0/180°。

2. **"肘约束"的真实语义**：3-DOF 臂下 3 值描述符至多有
   **2 个离散分支**（非 7-DOF 人臂的连续冗余族）——hint 是
   分支选择器而非冗余度参数。hint=None（默认）= **自然肘 =
   选肘 z 最低支**；`tuck`/`flare`/`hint_dir` 保留为显式覆盖；
   `prev` 仍最高优先（序列连续性）。选支序：prev > 显式
   hint > 自然肘。

3. **锚点表迁移**：按臂约定重标定（右臂新 θ=−旧共享 θ），
   hint 全部改 None 验证自然肘——渲染确认自然肘分支对
   jab/guard/backswing 形态均正确（肘低位=似人放松态）。

4. **合法性分层（用户拍板）**：`ArmPose` 是重表意对象——
   构造即校验、域外响亮拒绝：`polar∈[0°,180°]`、
   `extension∈(0,1]`（1.0+1e-3 容差吸收 describe 浮点噪声）、
   全量有限、`hint∈{None,tuck,flare}`；azimuth 为周期量
   wrap 归一 (−π,π] 不拒绝。**域内合法但物理不可达不判
   非法**——solve() 投影最近可达 + clipped/残差上报
   （dist_err 对原始请求而非投影后目标）。单位约定：内部
   一律 rad，`ArmPose.deg()` 度数控构造供人读面。

5. **不可达处理 = 可达集最近点投影（用户拍板，替代"解出
   再钳"）**：ArmPose 语义上是"指定空间点 P=ρLMax·d̂"。
   闭式解在限位内 → 精确命中（快路径，锚点逐位不变）；
   否则 `min|FK(q)−P|² s.t. q∈joint box`——3-DOF 箱约束
   LM，多起点（闭式候选+零位+±0.8·限位+prev），自适应
   阻尼+单调接受（保证不劣于任何种子）。近等残差(≤1mm)
   按 prev/hint/自然肘选支。诊断不变：clipped 三标志仍报
   哪类约束失败，新增 `pos_err`（m）报真残差；
   dir_err/dist_err 保留为分解诊断。200 采样对比旧钳法：
   111 更近/26 持平/0 更远，mean pos_err 0.221→0.144m；
   dir_err mean 34.5°→16.9°。代价：~20ms/次（仅不可达时
   触发，生成侧工具调用，可接受）。**语义变化**：投影在
   笛卡尔距离下自动权衡方向/远近——高 ext 时方向权重天然
   大（角度误差×杆长），符合"出拳越伸越在乎落点"直觉。

6. **抡臂扫掠验收（sweep_arm_validate.py）**：θ 整圆扫掠
   实测可达弧（pos_err<0.01）：φ=90°纯矢状面仅 ~150°
   ([−105°,+40°]，与 ext 几乎无关——肩限位决定)；
   **φ=30°+ext=0.95 → 360° 全程精确命中**——外展锥面扫
   掠完全落在可达流形内，机器人能做风车式抡臂，不能做
   贴身矢状面大回环。不可达段投影形态合理：屈肘沿工作
   空间边界滑动，prev 连续性无跳变。

### 验证

FK 对拍 3.6e-16 不变；L/R 同描述符→相同 norm→镜像形态
（渲染确认）；describe 反变换随约定更新。工作空间（新约定，
polar≈90°）：ext>0.8 时 az∈[−32°,+140°]，ext .4-.7 时
az∈[−60°,+70°]，真后摆仅 ext≈0.95 极限可达。

  ≥3步去抖，60步超时兜底）；落地稳定延迟2~3帧比姿态；
  朝向=边界时刻yaw+指令Δyaw，下边界实测。
- **Markov 链**：程序化生成合法边（几何校验）+权重叠加；
  脚交替偏置为主；撞墙/撞对手=落点预测拒绝重采。

**待确认**（详见 `STEP_GAIT.md` 待定参数表）：

- 脚×转向规则：几何推导=异侧脚前进转合法（R:前+左转），
  用户表述相反——"前进"锚定语义待拍板
- width/档距实测值（拟从 s42i 参考片段测脚距/步幅分布）
- Δyaw/步、误差饱和阈值、Markov 权重矩阵初值

## D13 — 步令编码终稿：声明式终态指令（取代 D7）

**日期**：2026-12-19 ｜ **状态**：已定稿

**背景**：D12 姿态集确定后，指令语义在"动作式"与"声明式"间
反复错位（自环怎么表达、"原地挪姿"如何编码、等价步令集为何
有两条）。用户拍板：**指令描述终态而非动作**——姿态转移表
退化为生成表，列均匀（终态只由指令决定）。

**编码**（6 维，形状沿用 D7，语义重定义）：

| 维 | 取值 | 语义 |
|---|---|---|
| 0 脚动 | −1 / +1 | 左脚动 / 右脚动；**0 不合法** |
| 1 转向 | −1 / 0 / +1 | 完成后 torso 左/不/右转（±30° 暂定） |
| 2 前脚 | −1 / 0 / +1 | 终态左脚前 / 齐平 / 右脚前 |
| 3 纵档 | −1 / 0 / +1 | 交错 小/不迈/大（维2=0 时必 0） |
| 4 横向 | −1 / +1 | 终态宽距 常距/宽距 |
| 5 预留 | 0 | — |

**语义要点**：

- 读法 `脚→终态·转`：`右→左领宽`、`左→马步·右`。
- **脚维无 0**：每条步令必有一脚迈动→步边界永远是落地事件；
  全零 = 无指令哨兵（`原`），非合法步令。
- **自环=踏步**：目标=当前姿态 → 该脚抬落原位。
- **脚≠等价**：同终态左右脚达成的位移方向相反（`右→右领`=
  前进、`左→右领`=后退）——脚维隐式编码移动方向。
- **可达性不在表管**：一切终态合法可编，动脚位移 |Δ交错|
  +宽距切换作为采样权重输入（`step_gait.step_cost`）。
- 旧"脚×转向合法性"之争作废：转向是独立维，物理可行性交训练。

**实现**：`step_gait.py`——GaitPosture(10态)、StepOrder、
POSTURE_ORDERS 生成表、step_cost、order_name。
**文档**：`STEP_GAIT.md` 已按本版重写。

## D15 — 步边界=obs 流纯函数；step_cur[5]=步龄消歧

**日期**：2026-11-19 ｜ **状态**：⚠️ 已被 D16 取代——相位机
退役，`step_boundary.py` 删除。保留此节作演进记录。

**背景修正**：早先方案把触地迟滞状态机放物理子步级
（`on_post_phy_step` / `physical_step` 覆写）——**否决**。部署态
策略只有 96 维 obs 流，指令源必须能仅凭 obs（+指令段自带的
步龄状态）判定步边界并决定何时给下一条指令；物理子步力
信号部署拿不到。
边界切分在训练/部署必须严格一致 ⇒ 检测器只能是 obs 纯函数。

**决策 1：边界检测 = 每令一周期相位机（最终版）**

> 修订说明：v1（物理子步迟滞机）被部署一致性否决；v2 简化版
> `age>0.5 AND 指令脚 force>0.4` 又被用户发现致命洞——指令脚
> 若本就承重（自环令/发令即站立），age 门一满自动判完成，
> 机制整体失效。v3 相位机为最终实现。

每令一周期，两相位、单超时（age≥6.0，age 每 action step +0.1）：

- **相位 A 候抬（选举摆动脚）**：某脚 force<0.1×BW 连续 K=2
  帧 → 当选 swing，进相位 B；同帧双脚齐抬→指令脚优先。
  已承重脚永远当不了 swing ⇒ stance 延续承重天然免疫误触发
- **相位 B 摆动（等落地）**：swing 脚 force>0.4×BW → 落地，
  步结，`executed=swing`
- **超时路径**：① 双脚始终不抬→超时 `executed=None`；
  ② swing 悬空不落→超时
- **错脚步可结算**：错脚先抬→它当选 swing→它落地即结→
  `executed≠cmd_foot` 判错，每步都有判决
- **自环白捡洞堵死**（v2 的已知漏洞消失）：同脚同姿态令必须
  真抬真落
- **训练/部署同源**：检测输入=obs `feet_forces`+指令段 age，
  无 sim 依赖；部署指令源同码驱动

检测挂点：V2StepSimulator 在每个 action step **最后一个物理
子步**驱动 update（此时力=本帧 obs 力；轮转在 obs 产出前完成
⇒ 部署侧"见到落地帧 obs 即轮转"与训练严格同帧）。报告经
`get_derived_state(["step_reports"])` 供 observer 读取（accessor
白名单合规通道）。

模块：`step_boundary.py`（无 sim 依赖，含自测）。

**决策 2：同脚同姿态连发的消歧**

- **漏洞**：`左→左领` 接 `左→左领`——旋转后 step_cur 内容不变，
  obs 前后两帧完全一样，策略无法分辨"旧令未完成/新令已下达"，
  第二条只能等超时
- **解法**：step_cur 预留维（dim5，原恒 0）= **步龄**——新令
  0.0 起计，**每 action step +0.1**，旋转瞬间归零（旧值>0→0，
  必变 ⇒ 天然消歧，等效奇偶位且附带"窗内剩余时间"信息）
- step_next[5] 不启用（未开始计时）

**实现**：`step_boundary.py`（共享）、`step_gait.StepOrder.to_vec`
的 dim5 由 sim 侧覆写步龄（编码位本身仍属预留语义）。

## D16 — 步令语义改为"时限预算到期结算"（取代 D15 事件驱动）

**日期**：2026-11-19 ｜ **状态**：已定稿（实现于
`v2_step_simulator.py`；`step_boundary.py` 删除）

**动因**：dump 数据（`v2_s4_step_r2/dumps/u00155`）表明相位机
机制虽全对（99.75% 部署一致），但语义有根伤：

- 订单 3~15 帧即结算（中位 4 帧），指令脚中位净行程仅 9cm——
  调度器在**给机器人自己的碎步盖戳**，令不牵引步态
- 踝高实测：稳态抬幅 p90 仅 3~7cm，且 18% 帧"贴地高度但
  零受力"（蹭地滑行）——**高度分不出摆/站，摆动相本身
  几乎不存在**，事件驱动的"落地结算"在这条行为流形上
  失去物理意义

**决策**：令 = (目标构型 C_k, 时限预算 H_k)，中间过程不测量。
到期帧测状态误差结算，随后轮转下一令。

- **预算**：发令时刻按动脚行程线性插值
  `H = h_min + (h_max−h_min)·s/s_max`，
  `h_min=0.15s`、`h_max=0.50s`（20Hz→3~10 帧）、
  `s_max=0.53m`（=2×STAGGER_UNIT 满行程）；超程截断
- **结算（到期帧）**：`d_mv=‖指令脚位−目标脚位‖`、
  `d_st=‖stance脚−发令原位‖`、`d_yaw=|yaw−目标yaw|`；
  `foot_ok = d_mv < 0.10m`（"到位"即"迈对"，取代
  executed==cmd 的事件判决）
- **executed** 降为纯诊断（窗口内净位移较大的脚；双位移
  <1cm → 0"未动"），不进奖励
- **step_cur[5]=age/H 归一化**（[0,1] 时间压力；取代 D15
  的 0.1/帧步龄——消歧功能不变：轮转即归零）
- **部署 parity**：指令源发令时拿同一对（动脚位, 目标位）
  算同一 H，之后纯数帧——比相位机更简单，无检测项
- **已知语义**：目标≈当前态的令免费得分（状态本就达成，
  语义诚实）；摔倒期照发令（靠 aw 比让策略学取舍）

**奖励映射不变**：r_step_foot/mv/st/yaw 四通道改在到期帧
结算；r_potential/r_fall 沿用。
