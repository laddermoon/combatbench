# V1：步内技能控制与自扩展训练

> 定位：接下来的主攻方向。本文记录已对齐的总体方案，供实现者制定实验与实现计划；不规定代码组织，也不盘点现有资产。

## 1. 目标与分层

建立一套具有统一运动风格、可被上层调用的全身技能，如前迈、制动、刺拳、摆拳、后手拳等。上层可以用 Python 战术代码，也可以后续学习：

1. 查询当前身体状态还支持哪些动作。
2. 选择一个动作，由底层策略持续输出关节控制 action。
3. 在同一步内，如果另一动作仍然可行，上层可以改选；不必等原动作完整执行后再启动新动作。

**关键语义：查询的是“从现在起，在当前这一脚落地边界前还能实现什么”，不是“落地以后，下一步可以做什么”。** 早期多个选择可能同时可行；随身体运动，一些选择消失，另一些也可能出现。“招用老了”对应其他选择已来不及实现。

## 2. 一步、状态范围与技能契约

以一次脚步作为基本任务边界。具体落地判据尚待实验确定；建议从“摆动脚经历有效离地后，重新接触并建立有效承重”起步，避免把擦地、瞬时接触当作完成。应有合理的步时上限，不能靠拖延落地获得无限执行时间。原地动作如何纳入，后续再扩展。

“状态流形”指宽泛的运动风格与允许状态范围，例如质心高度、步宽、摆臂幅度、肘部姿态等，不要求先构造严格的数学流形。普通技能在该范围内运动；超出范围后的恢复由恢复策略承担，其能力需另行验证。

**V1 不先实现通用流形定义器或采样生成器。** 风格通过训练引导、约束和任务完成态的参考姿态体现；实际需要覆盖的状态由技能轨迹逐步产生。能力判断仍需动态状态，不能仅凭姿态判断。

每项技能需要明确：动作类别及参数、步内必须实现的效果、落地完成态要求、失败条件。例如刺拳是否包含回收，应先定清楚；到过目标点不自动等于完成可用的拳。

## 3. 执行器与可行性

优先训练一个共享的技能条件策略：

```text
当前观测 + 技能编号 + 技能目标参数 + 必要的本步上下文
    → 全身关节控制 action
```

本步上下文只保留维持任务语义所需的信息，如支撑/摆动脚、固定目标或参考坐标系、剩余预算。若成功条件包含“本步曾完成一次出拳”，还需保留相应事件信息。不要求另建复杂的技能进度、结束与中断输出接口。

可行性定义为：**配套的当前执行器从此状态接管，能否在本步边界前按要求完成该动作。** 它不代表理论上存在任何控制器可以完成。不同技能有不同的支持范围，不要求所有状态都支持所有技能。

第一版直接用 rollout 查询可行性：

- 复制当前完整仿真状态及必要上下文，对各候选技能执行策略，直至本步结束或失败。
- 按实际结果返回支持/不支持，也可保留质量、耗时和失败原因。
- 中途查询或改选不能重置脚步、延长剩余预算；观测重建的近似仿真与完整快照分支应区分。
- 无未知扰动、确定性仿真和执行方式一致时，成功轨迹沿途应保持原目标可完成。若不一致，检查快照、上下文、策略执行与评测语义。

有对手或外部扰动时，结果取决于所采用的对手行为/扰动假设。先验证受控条件，再扩展。

**不以训练独立 affordance 分类器作为 V1 前置条件。** 若候选 rollout 开销成为瓶颈，可后续用真实 rollout 标签蒸馏成多头分类模型；执行器更新后，标签和评估也应更新。

## 4. 自扩展的候选起点池

所有技能最初从同一个基本站立状态训练，先掌握基础执行。训练中引导统一风格，并要求合格的任务完成态。

随后循环扩展：

```text
已有起点 → 执行技能 → 收集过程状态
    → 从这些状态训练各技能接管 → 产生新轨迹 → 补充起点池
```

用一个共享候选起点池 D，各技能在其中拥有自己的支持子集。新状态不是所有技能必须完成的承诺，而是希望通过训练尽可能覆盖的候选。分支数量会增加，但有效覆盖不保证指数增长。

起点条目应保存完整仿真快照与本步上下文。截取中间状态后训练的是原脚步的剩余任务；有效落地后才能建立下一步的新上下文。

两类数据用途分开：

- **可靠轨迹扩充核心池**：优先从成功、质量合格的执行中收集状态。
- **交叉尝试扩展能力**：把这些状态配给其他技能，包括当前尚不能稳定完成的配对。不能只训练已经支持的配对，否则能力边界会固化。

失败结果保留用于诊断和评估；失败轨迹中的状态不应不加筛选地淹没普通技能起点池。明显失控状态与恢复训练分开处理。

## 5. 每个 update 的固定训练循环

1. 从起点池采样状态，并选择要训练的技能及参数。
2. 用当前采集策略执行 rollout，到本步结束或失败，获取奖励和真实结果。
3. 更新共享执行策略。
4. 从本轮轨迹选取部分状态补充起点池，更新已尝试配对的结果记录。
5. 保持起点池容量与采样分布平衡，重复以上过程。

不需要保存所有帧，也不需要每次遍历所有状态×技能。初期按来源技能、步内位置、数据新旧分层采样，并始终保留标准起点与旧成功状态，防止遗忘。训练同时覆盖已会配对、接近能力边界的配对及部分未探索配对；持续失败配对降低频率但不永久认定为物理不可达。

若使用 PPO：历史快照可作为新 rollout 的 reset 起点；历史策略产生的 transition 不应直接混作当前 on-policy 数据。能力记录是策略版本相关的估计，不是永久标签。

奖励以“本步完成目标且落地合格”为核心，可配合目标推进与风格约束提供早期学习信号。辅助奖励上涨不能替代真实成功率。逐步从标准起点扩展到自身中间态、其他技能中间态，再到连续多步和接触扰动。

## 6. 首轮验证与实现边界

先用少量具有共同起手的技能验证闭环，例如“普通前迈”和“同一步内前迈刺拳”，不要一开始扩展完整动作库。

核心验收：

- 独立起点集上的技能成功率与完成质量。
- 不同步内状态下，各技能的可行区域及重叠区域。
- 选定动作执行过程中，剩余任务可行性的一致性。
- 在可行域重叠处中途改选，是否确实能完成新目标。
- 连续多步的可靠性，以及扩大支持范围时旧能力是否保持。

成功标志是出现可重复的“早期可以换招、晚期某些招已不可行，以及在允许时换招成功”，而不是池内状态数量增长。

实现者先明确落地事件、技能成功定义、风格范围、终态参考与必要上下文，再盘点可复用资产并制定小规模实验。网络细节、奖励权重、采样比例和容量由实验确定；不把通用状态生成、完整动作库或上层博弈学习作为本轮前置任务。
