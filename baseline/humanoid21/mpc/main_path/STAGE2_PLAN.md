# 第二阶段实施方案：连续 MainPath 与区间可行性验证

状态：设计方案，尚未实现。第一阶段按已完成处理；目标朝向、曲线路径
与转身仍保留 TODO，本阶段不扩大到这些功能。

## 1. 核心交付

`MainPath` 是完整 `MainPathState` 的连续时间表示：

```python
path.state_at(t) -> MainPathState
validator.check_interval(path, ta, tb) -> ValidationReport
planner.plan(request) -> PlanningResult
```

任意定义域内时间都可查询；任意合法时间区间都可验证。采样数组由
`state_at` 导出，不另存一套可能与查询结果不一致的轨迹。

可行性同时包括：单时刻的能力约束、时间区间的动力学一致性、接触
事件的衔接，以及末端可持续保持。两个端点各自合法不意味着中间合法。

机器人能力包络是有适用范围的近似模型。报告应明确参数来源和校准
状态；满足未校准的包络只表示候选通过该模型检查，全身执行验证仍
是后续环节。

## 2. 时间差分与物理验证

对任意 `ta < tb`，验证以下积分残差：

```text
rc = c(tb) - c(ta) - integral(l(t)/m, ta, tb)
rl = l(tb) - l(ta) - integral(m*g + fL(t) + fR(t), ta, tb)
rL = L(tb) - L(ta)
     - integral((pL(t)-c(t))×fL(t) + (pR(t)-c(t))×fR(t), ta, tb)
```

有限时间差分除以时长，得到的是区间平均变化率，必须与平均作用比较；
不能直接与端点瞬时力或力矩比较。力矩积分使用随时间变化的质心力臂。

另做分段内部的微分残差检查，以及事件两侧的单边检查。跨接触事件
的区间先拆段再积分。各残差保留物理单位，使用独立的绝对/相对容差；
短区间不只检查除以时长后的残差，避免放大浮点误差。

有限随机采样用于发现错误，不能替代整段约束验证。

## 3. 输入、输出与定义域

沿用 `MainPathState` 全部字段，质量和重力作为固定模型参数：

- `MainPathTrajectoryRequest`：初始状态、第一阶段支撑序列、目标位置；
- `MainPathModel`：质量、世界坐标重力向量；
- `MainPathConstraints`：能力包络、终端要求、每项容差；
- `SolverConfig`：网格、迭代预算、缩放、细分预算；
- `PlanningResult`：状态、通过验证的 path（成功时）、结构化诊断。

第一版定义域为 `[start_time, end_time]`，越界查询报错，不静默 clamp。
有限 horizon 不代表开放支撑已经结束。只在末端满足平衡条件后，
提供显式的保持段扩展；不把所有轨迹自动外推到无限未来。

初始查询须匹配输入全部字段。初始脚点/支撑标志与 schedule 冲突时，
返回 `INPUT_CONFLICT`，不把悬空脚强行改成着地，也不修改输入脚高。
当前第一阶段仍可能生成假定双支撑的序列；本阶段预检查须暴露该冲突。

成功结果不附带“尽量可行”的隐藏松弛。失败候选可用于诊断，但不能
作为通过验收的 MainPath 返回。

## 4. 连续表示：从脚力积分出状态

推荐采用分段线性脚力与解析动力学积分。每个支撑事件必须是分段边界；
事件之间可按最大 `0.05 s` 初始网格细分，时间步是数值参数，不是状态契约。

单段内每只脚的力写成 `f(s)=f0+s*df`，`0 <= s <= h`，支撑脚点固定。
令 `a0=m*g+fL0+fR0`，`b=dfL+dfR`：

```text
l(s) = l0 + a0*s + b*s²/2
c(s) = c0 + l0*s/m + a0*s²/(2m) + b*s³/(6m)
L(s) = L0 + integral(sum((pi-c(u))×fi(u)), 0, s)
```

角动量右侧是低阶多项式，可直接积分。无支撑时两脚力恒为零，自然
得到弹道质心和恒定角动量。全段动力学由构造成立，而不只在网格点成立。

节点状态由上段积分结果衔接。禁止独立插值 `c,l,L` 后再声称它们满足
同一受力轨迹。表示层本身应能在没有优化器的情况下被解析例子验证。

## 5. 支撑切换、摆动脚和朝向

- 支撑区间采用 `[start, end)`，事件时刻按右侧支撑状态查询。
- 支撑标志是离散量，可以跳变；连续表示不要求布尔字段连续。
- 第一版无冲量模型：`c,l,L` 连续，脚力连续且变化率有限。
- 离地前力降为零；落地时从零开始加载。活动支撑允许零法向力，
  不能全程要求严格正的最小法向力，否则与连续切换冲突。
- 不支持瞬时动量跳变；需要冲击才能成立的候选须失败并指出原因。
- 接触脚点保持不动。两段支撑之间，用零端点速度/加速度的五次
  过渡和可配置抬脚弧线定义等效脚点，以便任何时刻都返回完整状态。
- 检查摆脚净空、速度、加速度和相对 COM 的可达范围；不生成关节轨迹。
- 输入没有摆动脚速度，不能声称已接续任意进行中的摆动。
  首个规划里程碑从双支撑静止脚开始；初始悬空状态的衔接留待显式
  边界约定，返回 `UNSUPPORTED_INITIAL_CONTACT`，不在 schema 禁止它。
- `heading_yaw` 保持初始值。总角动量不是躯干角速度，不能写
  `yaw_dot=Lz/I`；固定 heading 是当前参考约定，由姿态能力包络和
  后续全身实现检验，不从总角动量伪造朝向演化。

在平地上统一“等效脚点”高度与抬脚净空基准；现有值接近足部几何中心
高度，不能直接当脚底地面高度使用。

## 6. 机器人能力包络

使用显式配置和来源记录，不把几何比例推导的步长当作已验证的动力能力。

| 约束 | 检查内容 | 参数来源 |
|---|---|---|
| 接触力 | 非负法向力、每脚最大法向力/合力 | 模型承重尺度与后续标定 |
| 摩擦 | `norm(fxy) <= mu_safe*fz` | 接触材料参数及保守折减 |
| 力变化 | `norm(df/dt) <= rate_max` | 待标定配置 |
| 支撑可达 | body frame 下 COM 与脚点的相对范围 | 几何、屈膝姿态范围 |
| 整体运动 | COM 高度、速度和角动量包络 | 指定适用姿态族及标定 |
| 摆动能力 | 脚速度/加速度、抬脚高度、净空 | 几何与待标定配置 |

质量、几何、摩擦可从模型获取；力、力变化率和可达包络需要经验初值，
随后通过受限姿态采样和独立仿真实验收紧。包络参数注明单位、来源、
安全系数、适用范围和版本。缺失必需参数时失败，不默默补无限能力。

这些约束属于 planner/validator，不添加左右脚时序关联到 SupportInterval。

## 7. 轨迹求解

不采用“固定 COM 曲线 → 每帧独立配力”作为最终求解器，因为单脚
阶段的线动量和角动量不能独立指定。名义 COM 曲线仅用于初始化和软目标。

1. 预检查初始状态、支撑事件、终端支撑和平衡受力是否可能；
2. 固定第一阶段的脚点和时间，构建事件对齐网格与摆脚参考；
3. 用重力分配、缓慢重心转移及到目标的平滑参考初始化；
4. 联合优化脚力节点和分段起始 `c,l,L`，施加解析积分衔接等式；
5. 硬约束包含初始条件、受力、可达、终端目标和停稳条件；
6. 软目标包括跟随名义进度、较小角动量、较小力变化和合理高度。
   不强制运动全程 `L=0`，也不强制双脚平均承重；
7. 先用 SciPy 约束优化实现可复现基线，变量和残差按 `mg`、腿长、
   时间尺度归一化；记录迭代数、求解耗时、最大约束违反量；
8. 独立连续验证；若段内违反约束，在相应位置增加约束节点再求解，
   达到预算仍不能验证则返回失败。

这是一个小规模非线性约束问题，不能保证总能求到解。
`SOLVER_FAILED` / `VALIDATION_FAILED` 不等于数学上已证明不可行。
只有可直接证明的输入矛盾或平衡条件矛盾才报告相应不可行原因。

本轮不自动修改第一阶段结果。失败报告指出步长、时长、力或终端
条件的冲突，后续再由上层决定重规划。终端保持时长可显式配置，
不复用第一阶段 `settle_duration=0.6s` 当作已经站稳的证据。

## 8. 独立验证器

验证器不相信优化器 success 标志，也不复用优化约束残差作为验证结论。

- 对 `state_at` 查询做独立数值积分，检查任意区间的三项守恒残差；
- 验证节点衔接、事件两侧、初始条件、终端条件和完整字段；
- 线性力的法向力/凸摩擦锥约束可用端点保证全段满足，斜率直接检查；
- COM、角动量、摆脚及相对距离等多项式约束，求极值或使用 Bernstein
  区间界和自适应细分；范数约束转成平方多项式不等式；
- 边界太近而无法在预算内判定时，返回 `INCONCLUSIVE`，不冒充通过；
- 记录最坏时刻或区间、实测值、上/下限、容差、验证方法和能力包络版本。

首版能力约束选择能做区间界验证的形式。复杂经验函数若只能采样检查，
须单独标记验证强度，不能与整段有界检查混为一谈。

最终保持段应有恒定 `c`、`l=L=0` 和恒定双脚力，满足合力抵消重力、
关于质心的合力矩为零。数值求解按容差验收，不偷偷把非零末端速度
清零来拼保持段。无法接续时继续求解或失败。

## 9. 模块和实施里程碑

| 顺序 | 文件/工作 | 可验收产物 |
|---|---|---|
| 1 | `contracts.py`、`trajectory.py` | MainPath 查询接口、分段积分、定义域和事件规则 |
| 2 | `constraints.py`、`validation.py` | 明确能力配置、区间守恒与整段约束检查 |
| 3 | `trajectory.py`、`force_allocation.py` | 静态平衡初始化和联合轨迹求解 |
| 4 | `diagnostics.py` | 失败位置、原因、残差、验证强度 |
| 5 | 现有可视化和用例入口 | 机器人时间 1:1 的二维 MainPath 回放 |

先做表示和验证，再做求解器，避免生成器与验证器一起掩盖错误。
新测试集中放在 `test_trajectory.py`，保留第一阶段已有测试。

验收用例：

1. 双脚静态保持：非零起始时间、任意查询时间、稳定保持延长；
2. 单脚静态保持：COM 位于等效点上方；
3. 无支撑解析段：弹道解、零脚力、角动量守恒（表示/验证器用例）；
4. 短步重心转移：使用第一阶段输出，完整初始衔接、卸载/加载和末端停稳；
5. 非零初始动量的减速：验证没有静默清零；
6. 构造失败：摩擦不足、法向力不足、摆脚过快、初始支撑冲突；
7. 区间内部违规：端点合法但中间越界，验证器必须检测；
8. 事件前后及随机多尺度区间：验证积分一致性和离地脚力为零。

视频仍采用单一二维视图，显示查询得到的移动 COM、朝向箭头和当前
着地脚，可叠加受力箭头。离地脚不画；数值残差输出到报告，不恢复
之前的四面板展示。视频是 MainPath 的消费者，不另算一条展示轨迹。

完成标准：表示层可独立验证；静态、短步等成功用例通过连续约束检查；
失败用例有明确诊断；终端保持可接续；第一阶段回归通过。物理包络
尚未标定的部分明确列出，不宣称已经获得全身执行保证。
