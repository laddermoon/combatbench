# Gating 分类器重设计分析

> 本文件记录对扰动状态分类器（Gating Network）数据采集与训练方案的结构性分析及改进设计。

## 背景

Gating 分类器的作用：在推理时实时判断当前状态是否安全（`p_safe`），不安全则切换到冻结的恢复策略 `π_recover`。分类器需要回答的核心问题是：

> 从状态 s 出发，冻结的 π_recover 能否救回来？

这是 (s, π_recover) 的联合属性。既然 π_recover 永久冻结，这个标签函数是良定义且稳定的。

## 两个正交问题

数据采集方案的质量取决于两个独立维度：

| 轴 | 需求 | 说明 |
|---|---|---|
| **标签函数** | 良定义、稳定、低噪声 | 必须条件于冻结的 π_recover |
| **状态分布**（输入覆盖） | 覆盖部署时会遇到的状态 | 应与任何单一策略解耦，且物理自洽 |

## 现有方案分析

### 旧方案：状态空间直接扰动（`InitialStatePerturbationPlugin`）

- 在关节角度、角速度、倾斜等维度独立均匀采样
- **标签函数**：正确（用 π_recover 跑 episode，按结局标注）
- **状态分布缺陷**：物理不自洽——独立采样的关节偏移 + 倾斜 + 速度组合可能违反动力学约束，产生现实中不可达的状态

离流形状态的间接危害：
1. 消耗模型容量，扭曲流形附近的决策边界
2. 污染 `pos_weight` 的类别平衡计算
3. 让 val F1 虚高（大量易分的离流形样本拉高 accuracy）

实证：`gating_model_plus_mix_level` 的 val_acc=0.980 但 unsafe_f1 仅 0.654，巨大落差很可能就是这个现象——容易的样本（含离流形）拉高了 accuracy，真正关键的边界附近样本没学好。

### 新方案：冲量力扰动 + 策略参与（`RelativeImpulsePlugin`）

- 物理仿真中施加恒定冲量力，策略在扰动过程中驱动 robot
- **标签函数**：正确
- **状态分布缺陷**：被单一策略限制——用策略 A 采的数据训分类器，部署到策略 B 时状态分布不同 → OOD

### 共同的更大问题：标签噪声

现有 **Temporal Back-Tracking Noiseless Labeling** 是最大的噪声源：

- 最终摔倒的 episode，第 0 帧的完美站立状态也被标为 unsafe
- 存活的 episode，中途险象环生的濒临失衡状态被标为 safe

等于把 episode 级结果标签硬摊到所有帧。真实的 `p_safe(s)` 在 episode 内是单调下降的（越接近摔倒越危险），整集标注把它压成常数。这个噪声比离流形问题严重得多。

## 正确的做法

### 核心原则：状态生成与标签生成彻底解耦

#### 状态生成（求覆盖，混合多源）

所有源都必须经过前向物理仿真，保证物理自洽：

- 多个 checkpoint 的策略（gen0 / gen5 / gen9，行为模式差异大）
- 不同噪声强度的弱化策略（σ = 0, 0.05, 0.1, 0.2）
- 冲量参数覆盖全谱（不只是 cd 附近，也要有远超和远低于 cd 的）
- 旧的状态空间扰动也可以保留，但后面接一段沉降（几步无控仿真）让状态回到物理自洽

#### 标签生成（求正确性，单一来源）

- 对每个采到的状态存快照
- 用冻结的 π_recover 从该状态跑 N 次（不同随机种子）到 episode 结束
- 标签 = 恢复率（软标签，回归而非分类）

这样：物理自洽（全部来自前向仿真）+ 覆盖广（多生成器）+ 标签良定义且低噪声（逐状态 MC）。

### 数学本质

逐状态 MC 恢复概率本质上是在学 **π_recover 的价值函数 / 可行性核（viability kernel）边界**，而不是一个二分类器。

当前 `balance_recover` 做的 critical duration boundary 探测，是这同一个可行性边界在 (angle, force, duration) 低维切片上的测量。两件事在数学上是同一个对象。

## 部署时的分布漂移

即使做到上面这些，主策略 π_primary 在训练中会不断漂移，它访问的状态分布也在变。这是 **DAgger 的经典问题**，无法靠一次性数据采集解决。

唯一解法是**迭代数据聚合**：主策略训练若干轮后，用当前 π_primary 重新采集状态、重新标注、重训 gating 网络，聚合到历史数据上。

这和现在 `iterative_train.py` 里"probe → 重算采样分布 → 训练"的循环是同构的。可以直接扩展成"probe → 采样分布 + gating 数据 → 训练"的三段循环。

## 实施路线

1. **状态快照机制**：在 episode 运行中定期保存 core state 快照（不只是 episode 结束）
2. **MC 恢复评估器**：从快照加载状态，用冻结 π_recover 跑 N 次，计算恢复率作为软标签
3. **多源状态采集器**：聚合多个策略 checkpoint × 多噪声强度 × 冲量全谱的状态
4. **Gating 网络改为回归**：输出 `p_safe ∈ [0,1]`，用 MSE 或 BCE 软标签训练
5. **迭代聚合**：集成到 `iterative_train.py` 循环，每代训练后采集新 gating 数据
