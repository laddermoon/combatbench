# humanoid21 动作资产与动作先验建设大纲

> 类型：任务大纲
>
> 状态：待在独立任务中实施。本文记录目标、边界和验收路径，不代表相关工具或先验已经实现。

## 1. 背景与用户意图

CombatBench 已通过强化学习逐步获得起身、平衡、移动和初步出拳能力。但后续通过增加拳速、肩速、躯干角速度奖励来引导全身发力，并没有可靠地产生协调的攻击动作；用户观察到前倾、乱挥和机械重复。身体运动量增加不能证明有效传力，也不能证明攻击质量提高。

用户决定将动作先验作为独立任务建设，不在当前打斗训练中继续临时堆叠动作奖励。期望建立一个包含自然运动片段、分类、数据处理工具和训练接口的可复用基础模块，用于以后不同任务的强化学习。

核心分工：

- **动作先验**：提供合理、协调的运动方式。
- **任务奖励**：决定要达到什么结果，例如跟随、命中、重击、攻击后恢复。
- **物理约束与验证**：检查运动是否适用于当前机器人及控制系统。

本任务可以脱离具体打斗任务实施，但不能脱离机器人形态、物理参数和控制方式。自然不等于有效，符合先验也不保证物理稳定。

## 2. 目标与非目标

### 目标

1. 建立可追溯、可分类、可检索的自然运动资产库。
2. 建立从源动作到 humanoid21 参考运动的重定向、可视化、质量检查流程。
3. 区分运动学上合理与物理上可执行，形成分级验收的机器人参考运动库。
4. 提供动作跟踪及动作先验奖励的训练接口，供不同任务复用。
5. 用小规模实验验证先验是否改善动作质量，同时不过度牺牲任务效果。

### 首版非目标

- 不训练完整拳击战术、防守、自对弈或对手池。
- 不收集“所有自然动作”，先打通少量片段的端到端流程。
- 不将人形动画播放成功当作物理控制成功。
- 不把旧训练策略、仿真器或计分规则的大范围改造混入本任务。
- 不承诺一个冻结的先验奖励模型可以无条件适用于所有任务和机器人。

## 3. 概念边界：运动数据不是控制 action

动捕通常记录身体如何运动，而不是使其运动的电机指令。

- **源运动**：人的骨架姿态、根部轨迹及时间信息。
- **机器人参考运动**：重定向后的根部状态、关节状态、关键点轨迹、接触等。
- **控制 action**：当前 humanoid21 使用的归一化目标关节位置，由 PD 控制器转换成力矩。

把参考关节角归一化后直接交给 PD 控制器，不保证实际运动能跟上参考，也不保证平衡。因此，“重定向”与“物理跟踪/修正”应当是两个明确环节。

AMP 类先验通常比较身体状态及其时间变化，不要求先从动捕恢复对应的电机 action。如果保存 action，必须注明其生成控制器、控制频率和模型版本，不能与参考关节角混为一谈。

## 4. 总体数据与工具链

```text
原始动作资产与来源/许可
    ↓
格式统一、坐标与时间校准、清洗和切片
    ↓
humanoid21 运动重定向
    ↓
运动学检查与源/目标对照可视化
    ↓
物理跟踪验证，必要时修正参考或训练跟踪策略
    ↓
分级机器人参考运动库
    ├── 参考动作跟踪训练
    ├── 动作先验奖励训练/适配
    └── 后续可选：技能控制器与潜空间
```

保留原始数据、重定向数据和物理验证结果之间的关联；失败片段应有原因记录，不应静默修补后混入已验收数据。

## 5. 数据范围与资产规范

### 5.1 首版动作集合

以一个小而完整的动作集合为起点：

- 稳定站立、准备姿态；
- 少量走路、转向、停止或侧移；
- 左右直拳；
- 收拳、换重心、攻击后恢复；
- 移动与准备、准备与出拳、出拳与恢复之间的过渡。

先筛选少量代表性片段，再决定是否加入勾拳、蹲起等。不能只收集“出拳瞬间”，忽略动作前后衔接。

### 5.2 数据寻找与筛选

- 优先审计项目已有数据，再补充其他动捕来源。
- 核验每个片段的真实内容，不因数据集名称或 subject 编号就认定它属于某类动作。
- 记录来源、作者/数据集、许可、下载信息、校验值及允许的使用/再分发范围。
- 排除或标记严重遮挡、缺帧、足滑、穿透和不可适配片段。
- 大体积原始数据和生成工件采用明确的存储方案，不默认全部提交 Git；索引与可复现处理配置应可版本管理。

### 5.3 建议的数据契约

具体文件格式在实施前确定，至少覆盖：

| 类别 | 内容 |
|---|---|
| 身份 | clip ID、来源 ID、主体/会话、父片段、版本与校验值 |
| 时间 | 时间戳、源帧率、重采样频率、有效帧/缺失掩码 |
| 坐标 | 长度/角度单位、坐标轴、朝向、四元数顺序、骨架层级 |
| 根部 | 位置、朝向、线速度、角速度及其表达坐标系 |
| 关节 | 关节名/顺序、姿态、速度及关节定义 |
| 几何与接触 | 关键点轨迹、地面高度、左右足接触及估计可信度 |
| 分类 | 动作类别、左右侧、阶段、过渡、多标签与标注可信度 |
| 质量 | 源数据问题、运动学检查结果、物理验证等级与失败原因 |
| 适配 | 目标模型版本、重定向参数、控制器与仿真配置 |

速度和接触允许从原始数据推导，但必须记录方法。缺失不能默认填零并伪装成测量结果。

分类宜支持“移动＋出拳”等组合，不强制互斥。阶段标签可先粗分准备、执行、恢复。训练/验证划分应按源片段、主体或会话进行，避免相邻帧和镜像增强泄漏。

## 6. 需要建设的工具

### 数据与检查工具

- 导入不同源格式，输出统一的运动表示。
- 重采样、平滑、分段、标签与索引管理；避免平滑破坏接触和速度峰值。
- 源动作播放器，检查骨架、地面、关键点、接触与时间序列。
- 自动检查单位、关节顺序、四元数连续性、缺帧和异常速度。

### 重定向工具

- 核验 humanoid21 的真实关节轴、自由度、限位与身体比例。
- 联合处理根部、躯干、末端和支撑关系，不只逐关节复制角度。
- 处理足部接触、地面穿透、自碰撞与关节限位。
- 对无法适配的运动显式标记；不能靠大量限位裁剪掩盖错误。
- 左右镜像需要几何与关节语义验证，不能只交换数组索引。

### 可视化与物理验证工具

- 源动作与重定向动作同步对照。
- 区分运动学回放与动力学跟踪，输出参考/实际轨迹对照。
- 记录足滑、穿透、限位、跟踪误差、力矩饱和、跌倒、恢复与控制代价。
- 允许小范围起始状态扰动，检验是否只在一个精确初始条件下成立。
- 物理验收不得逐帧覆盖机器人状态来假装控制成功，也不得依赖未声明的支撑或外力。

## 7. 先验使用方式与接口

### 7.1 参考动作跟踪：先验证“能否执行”

输入参考片段、相位和机器人实际状态，以姿态、速度、关键点及接触一致性训练跟踪控制。先用它证明当前模型能执行少量协调动作，不要求立即实现大规模技能切换。

### 7.2 分布式动作先验：再验证“是否能改善任务运动”

以 AMP 等方法为候选，从参考运动与策略运动的状态转换或短窗口学习风格评分，避免只判断单帧姿态是否合理。

接口应明确：

- 输入特征、坐标不变性、采样频率、时间窗口、归一化统计；
- 可选动作类别条件，以及准备/执行/恢复的覆盖范围；
- 奖励输出的尺度、版本与分项诊断；
- episode 边界和缺失帧处理，不能把重置前后拼成自然动作转换；
- 数据集、模型、特征提取器之间的兼容性。

数据库可固定复用，但 AMP 判别器通常还需用当前策略生成的数据继续训练。是否冻结先验、如何做任务适配，应通过实验决定，而不是预设“一次训练后永久通用”。

多类别数据可以由任务奖励引导选择，也可训练条件先验。类别限制不能阻止必要的混合动作和过渡。单一运动学评分不能替代物理可行性或任务成绩。

### 7.3 后续扩展

先验还可用于低层技能控制器或潜空间，供上层任务策略调用。首版只预留边界，不同时实现全部路线。

## 8. 与现有 CombatBench 的衔接

所有下列路径均相对项目根目录。

### 可审计的既有资产

- `baseline/humanoid21/mocap/prepare_data.py`：已有 CMU 数据下载与处理入口。
- `baseline/humanoid21/mocap/{asf_parser,amc_parser,fk,retarget,retarget_v2,visualize}.py`：解析、映射、可视化等历史实现。
- `baseline/humanoid21/mocap/data/{raw,retargeted}/`：已有原始及重定向工件，需逐项核验内容与质量。

现有准备流程主要保存 `(T, 21)` 关节角及归一化结果；这不足以证明已有完整的根部、接触和可执行全身运动。历史 `retarget_v2.py` 采用直接 DOF 映射并引用旧模型，不能未经验证就作为当前模型的标准答案。先复用可验证的部分，不默认删除或搬迁旧目录。

### 实际身体与训练接口

- `envs/humanoid21/battle_circular_v2.xml`：当前机器人/场地模型，核验关节轴和自由度。
- `envs/humanoid21/simulator.py`：观测、身体状态与目标关节角 PD 控制。
- `envs/humanoid21/DATASPEC.md`：数据契约；与实际实现交叉核验。
- `baseline/framework/ppo/{trajectory,trainer}.py`：接入奖励时需核查的通道与优势计算。

当前 PPO 的 `actor_weight` 作用于 GAE 之后的优势，不等同于在 reward 上施加门控；各通道优势还会分别归一化并进行权重合并。先验与任务的相对影响不能仅按原始奖励数值比较。接入前应验证真正的优化目标，避免重复“看起来给了奖励、实际信用分配不同”的问题。

首版在本目录组织新任务资产与工具；确需修改共享仿真/训练代码时，单独评审接口和回归范围，不顺带改动打斗策略、基准计分或现有运行实验。

## 9. 分阶段交付与验收

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| M0 资产审计与契约 | 数据清单、许可核验、模型适配检查、最小动作集合与数据规范 | 来源可追溯，片段真实内容与关节语义明确 |
| M1 导入与运动学重定向 | 可复现导入/重采样/重定向流程、对照可视化、自动检查 | 少量片段通过人工和运动学检查；异常被显式报告 |
| M2 物理执行验证 | 跟踪测试或跟踪策略、参考/实际对照与失败样例 | 核心动作及恢复可在当前物理模型执行，不依赖逐帧状态覆盖 |
| M3 先验奖励原型 | 特征提取、先验训练、版本化接口和诊断 | 能发现明显不合理的运动转换；完成策略钻空子的压力测试 |
| M4 小任务对照 | 无先验/有先验的受控实验 | 动作质量改善且任务效果不过度下降，在留出片段/场景上成立 |
| M5 扩充与复用 | 更多类别、过渡、条件接口及第二类任务验证 | 数据和接口复用成立，而非为每个任务重做整套工具 |

M4 可选简单移动或目标触达任务，不必等待完整打斗方案。跟踪能力验收与任务泛化验收必须分开；数据多、判别器准确率高或风格奖励上涨，都不能单独算通过。

每个里程碑开始前确定定量阈值，至少覆盖：任务成绩、动作质量、物理稳定性、失败率和复现性。模型相关阈值需用当前机器人标定，不能照抄人的速度或关节范围。

## 10. 最小验证与失败时的处理

- 同一场景和随机种子比较有/无先验；尽量控制网络、训练预算和任务奖励等其他因素。
- 视频展示成功与失败样本，不只挑最好片段；必要时进行盲比。
- 对先验测试静止、重复单帧、时间打乱、不合理变速、抖动、原地循环和过渡缺失等情形；根据对应动作类别判断，而不是假设所有静止都应扣分。
- 检查策略是否为了“像数据”而忽略目标，或为了任务分数而离开合理运动分布。
- 运动学回放不好：先修坐标、重定向与数据质量，不急于训练 RL。
- 回放好但物理执行失败：检查身体自由度、接触、控制和参考可行性，不用隐藏外力掩盖。
- 先验分数高但实际运动差：修特征、数据覆盖、判别器训练或接口，不直接提高先验权重。
- 动作自然但任务差：检查先验强度、技能覆盖与条件接口，不把“自然”当作任务成功。

## 11. 新任务的启动顺序

1. 读取仓库和项目指导文件，再阅读本文。
2. 审计既有 mocap 资产、实际模型与控制语义，明确可复用部分和缺口。
3. 选定最小动作集合，确定数据契约和验收阈值。
4. 先跑通一个完整片段的“源数据 → 重定向 → 物理验证”，再扩展批处理。
5. 完成 M2 后，再决定先做简单跟踪先验还是 AMP 原型，不一开始同时铺开多套方法。
6. 每次迭代保留复现信息、失败原因和验证结果；代码变更依照项目规则测试、提交并推送。

参考方向（不是必须复刻的实现）：

- AMP：运动数据提供风格约束，任务奖励表达目标。https://arxiv.org/html/2104.02180v2
- RoboStriker：动作跟踪、技能表示与高层对抗决策分离。https://arxiv.org/html/2601.22517

**首个成功标准：不是得到庞大的动作库，而是得到少量可追溯、可适配、可物理执行，并能在任务训练中真正发挥作用的动作资产。**
