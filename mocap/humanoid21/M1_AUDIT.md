## W1 定标（calibrate.py → calibration.json）

- CMU y-up → MuJoCo z-up：`C_CMU2MJ` 固定基变换（x→x, y→z 交换+符号），
  位置 `p' = C·p`，旋转 `R' = C·R·Cᵀ`。
- 尺度：人体腿长（髋→踝 ref_fk 输出单位）对机器人腿长 0.79 m 定标，
  `meters_per_cmu_unit ≈ 0.1169`；全肢体共用（上臂/腿比例验证一致，
  各肢体独立比值差异 <8%）。
- 站立帧脚底 z≈0 自洽（grounding 残差 ~5 mm）。

## W2 源侧导出（export_library.py）

- 每 clip 两个 npz：`cmu_*_src.npz`（`joint_space="cmu_asf"`，含全部 29 骨
  joint 关键点 + 每骨 AMC dof 展平向量 + `joint_names`）与
  `cmu_*.npz`（`joint_space="humanoid21_v2"`，21 维 `CONTROLLED_JOINTS`
  顺序）。
- 坐标统一 MuJoCo 世界系（z-up，米，弧度，quat wxyz），120 Hz 源帧率无损保留。
- 速度由 `np.gradient` 中心差分；接触为启发式（踝/趾低高度带 +
  低速门限），方法写入 index `quality.contact_method` / `velocity_method`。

## W3 重定向（retarget.py + robot_kin.py）

方法：**世界系逐帧 IK**，不是角度直拷。

- 躯干朝向 ← 人 thorax 坐标架（基变换后）；腹部 3 轴 ← 骨盆架相对解。
- 腿（4 dof）：踝相对髋位置（缩放，主目标）+ 小腿方向先验（定髋扭转/
  膝铰链平面）+ hamstring 肌腱软罚（`0.5·hip_y − 0.5·knee ≥ −0.3`）。
- 踝（2 dof）：足跟→脚尖方向匹配。
- 臂（3 dof）：手相对肩位置匹配（缩放）。**关键教训**：3-dof 臂对
  3-维目标是方阵系统，加大臂方向先验会把肘压死在 −100° 限位上
  （先验与位置目标冲突）；撤掉方向项后正常解出（如站立帧
  elbow −62°/−51°，残差 0）。
- 求解器：自写有界阻尼 Gauss-Newton（scipy least_squares 每次调用
  开销过大：458→38 ms/帧），热启动 + 肘部备选种子 + 分支翻转守卫 +
  `0.35 rad/帧` 速率上限（~2400°/s，拳击峰值之上）。
- `robot_kin.fk_positions`：解析式位置/姿态 FK（含关节锚点），与
  `mj_forward` 全 body 对比误差 ≤1e-15，迭代内环提速 ~30×。

实测（13_17 全片 4840 帧）：leg p95 ≈ 0.05–0.09 m，arm p95 ≈ 0.18–0.20 m，
最大帧间跳变 = 速率上限 20°（无 IK 分支翻转）。

### 已知形态学缺口（非缺陷，显式记录）

- 机器人臂长 0.62 m 肩→手 vs 人体 ~0.55–0.6 m 目标带宽：动态拳击帧
  手臂残差 p95 ~0.2 m，表现为出拳伸展度略欠 —— index 记
  `high_residual_arm_*`。

### W5a "手臂朝后打" 排查与结论（用户复核反馈）

用户报告：preview_v2 / compare 中线段人的拳看似朝身体后方打出；
机器人走路正常但拳击方向偶觉不对。

**排查**：

1. 源侧 FK 再逐行对照官方 viewer（display.cxx/skeleton.cxx/
   transform.cxx/motion.cxx）：axis 合成、dir 全局→局部、父子连接、
   dof 施加顺序（Rz·Ry·Rx 后乘）、dofo→drx/dry/drz 映射、root 顺序
   —— 逐项一致。
2. 独立约定交叉验证：CalciferZh 系实现（`M(b)=M(p)·C·R·C⁻¹`、
   方向用全局 dir）与官方约定在本骨架上给出**数值完全相同**的手部位置。
3. 下载 CMU 官方渲染视频 13_17.avi / 07_01.avi 逐帧对照：同一帧的
   剪影一致（含手臂姿态、出拳方向）；07_01 行走方向与 +z 前进一致。
4. 数据侧量化：拳击片段中"手在胸前平面之前"占比低是**数据真实内容**
   —— subject 13 的拳击为大幅度挥拳/风车样挥臂，拳峰帧手臂侧向或
   过头绕摆。07_01 行走时手-腿反向摆动相关 −0.47 正常。
5. 机器人侧：手部相对胸廓方向统计与源一致（lhand med −0.02 vs 源
   −0.11；rhand −0.06 vs −0.10），横向左右手相关性 0.76/0.83，
   肘屈伸角逐帧误差 ≤3°（个别极限帧 48°→19° 为可达性截断）。
   → 机器人无反向；偶见"方向不对"= 手臂伸展残差（p95≈0.2，臂长差）
   + 同一投影判读问题。

### W5b 肘关节方向实锤修复（第二次用户复核反馈）

用户复核 v3 后确认：**肘是向后折的**（人肘只能向前折），且机器人出拳
偏向侧方/下方。W5a 的"仅投影问题"结论被推翻。

**根因（确证）**：逐行对照官方 viewer 源码（transform.cxx 的
rotationX/Y/Z 为标准右手系矩阵；display.cxx 按 Rz、Ry、Rx 顺序
post-multiply）证实我们的 FK 与官方 viewer **完全一致**。但 T-pose
受控测试给出决定性证据——lradius/rradius 的声明 axis 分别为
(180,-30,-90)/(180,30,90)，其 e1 在 rest pose 恰为世界 ±y；+rx 绕
该轴将前臂**水平向后折**。而 ASF limits (-10,170) 声明 +rx 为屈曲
域，且 **CMU 官方渲染视频**（下载 13_17.avi 逐帧对照）显示相同正
值数据下肘向前折、双手在前呈抱架。结论：数据语义中肘铰链轴为声明
frame 的 −e1，即 AMC 的 radius rx 值须取负。开源实现
（CalciferZh/fairmotion）与下载版 viewer 同样会渲染出后折肘——属
上游约定陷阱，不是我们独有。

**修复**：`ref_fk.py` 增加 `DOF_SIGN = {lradius: -1, rradius: -1}`，
在 `_dof_values` 映射处对 radius 的 rx 取负。其余骨骼不动（膝 +rx 后
折本身正确，全骨取负会破坏腿）。受控合成位姿回归：垂臂 +rx 前臂
向前（z+）；真实出拳帧双手均在胸廓前方。

**对重定向的附带修复**：原先后折的手目标点在几何上对短臂机器人不
可达（臂残差 p95≈0.18–0.20m），IK 被迫给出侧/下方向的"最近点"——
这正是用户看到机器人"打向侧方/下方"的机制。修正后手部目标进入可
达域，arm 残差 p95 降到 **0.002–0.018m**（拳击片段），约 20× 改善。
wrist/hand 小指骨符号约定未单独验证（仅影响 ~8cm 手段朝向，对 retarget
的手目标无实质影响，标记为 cosmetic 未决项）。

全量重导出 17 clips + kinematic_check 全过 L1（0 限位/肌腱违例），
对照视频重渲染至 `compare_v4/`，源预览 `preview_v4/`。

**遗留**：W5a 节的"仅投影问题"结论作废；但朝向对齐视图（v3 引入）
本身仍然正确且保留——它消除的是判读歧义，与本次铰链符号修正是两
