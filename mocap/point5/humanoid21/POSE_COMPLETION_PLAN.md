# P5 → Humanoid21 全身姿态补全：实施计划

> 类型：实施计划  
> 状态：方案已定，未实现  
> 目录：`mocap/point5/humanoid21/`  
> 上游契约：`mocap/point5/DESIGN.md`

## 0. 定位与边界

P5 是**纯几何模型**：只管 5 个点的空间位置（姿态语义），不管速度、
动力学、接触力。本模块回答的问题是：

```
给定一个 P5（5 个世界系目标点）→ Humanoid21 的全身代表姿态（root 位姿 + 关节角度）
```

实现机制：把 Humanoid21 当作**纯机械连接件**（骨骼长度固定、关节限位、
完全无重力），用"自然姿态偏好 + 关节刚度权重"在可行解中选一个代表姿态。

明确不做：

- 无重力、无地面支撑、无接触/碰撞动力学、不跑物理仿真
- 踝关节不参与优化，固定参考角度；不做脚姿态求解
- 不做自碰撞避免（v1 只渲染供观察，不判定）
- 不承诺动力学可执行/可被控制实现（那是下游的事）
- 不碰 P5 核心（点集/插值/序列化契约不变）

## 1. 五点位置定义（与 adapter 统一，第一优先固化）

| P5 点 | Humanoid21 定义 | 说明 |
|---|---|---|
| `head` | 头部几何中心 | 由 head geom 尺寸/位置推导局部偏移 |
| `hand_right`/`hand_left` | 手部几何中心 | 同上 |
| `foot_right`/`foot_left` | **踝关节中心** | 用 ankle joint anchor，不是 foot body 原点 |

实施时核对 XML/编译模型，把每点落成 `(body, local_offset)` 常量表，
adapter 与补全器共用同一份定义。

**语义变更**：脚点从"脚 body 原点"改为"踝关节中心"后，
`z≈0` 不再等于触地。P5 侧接触判断（`is_planted`）语义同步调整或仅保留
为"接近地面"标注；旧口径的文档/测试要更新。

## 2. 自然姿态（与用户迭代确认）

自然姿态 `q^0` 是一份显式的全身关节参考配置，**不等于归一化 0 位**。
目标观感：膝微屈、髋腰温和弯、肩肘放松、左右基本对称、不塌腰。

**确定流程**（用户闭环，预计几轮）：

1. 我提出一版关节配置（yaml/json）
2. 渲染正/侧/斜三面图 + 5 点标注，给用户
3. 用户指出"哪里看着累"→ 调整
4. 用户确认后冻结为 `natural_pose` 配置，所有求解共用

自然姿态与刚度配置独立成文件，改配置不改算法。

## 3. 关节刚度模型

弹性代价（只选姿态，不对应真实 PD/物理刚度）：

```text
E_pose(q) = ½ Σ_j k_j · ((q_j − q^0_j) / s_j)²
```

- `q^0`：自然姿态；`s_j`：现有关节归一化尺度（沿用，不改定义）
- `k_j`：分组偏好权重，v1 不逐关节精调：

| 组 | 相对刚度 | 意图 |
|---|---|---|
| 踝 | **固定** | 不优化，锁在参考角 |
| 腰腹 | 较硬 | 防止够手时大幅折腰 |
| 髋/膝 | 中等 | 允许腿部屈伸适配头脚关系 |
| 肩/肘 | 较灵活 | 手部目标优先由手臂完成 |

左右同名关节同权。初值是待验证配置：够手时若躯干代偿过多，调权重。

## 4. 求解流程（三阶段，约束累积保留）

**求解变量**：root pos(3) + root rot(3) + 全部活动关节（踝固定）。
**硬约束**：骨骼长固定、关节限位、每点位置容差。

| 阶段 | 新增约束 | 作用 |
|---|---|---|
| 1 固定双脚 | 双踝关节中心 = 目标 | 定身体位置与大致朝向 |
| 2 固定头 | + 头部位置 = 目标（双脚保持） | 定身体整体弯曲/扭转 |
| 3 固定双手 | + 双手位置 = 目标（脚头保持） | 手臂为主，全身微调 |

关键点：**先固定的点在后续阶段继续保持约束**（带容差），
不是解完就放开。各阶段在保留约束前提下最小化 `E_pose`。

**注意**：脚+头固定后身体仍可能有多种屈曲/扭转组合，不是已唯一。
顺序的作用是减少自由度进入顺序、让结果稳定，不是数学唯一性证明。

## 5. 唯一性保证方式（确定性，不是数学证明）

同一个 P5 + 相同配置 → 稳定输出同一姿态，靠固定规则实现：

- 固定 `q^0` 与刚度配置
- 固定求解顺序（脚→头→手）与初始化规则
- 固定优化器/终止条件；无随机初值、无随机重试
- 每阶段从上阶段结果继续

初始化：由双踝连线估身体左右向 + z 轴向上 → 初始 root 朝向；
`q^0` 平移到目标附近作初值。双踝重合等退化输入显式报错。
若个别自由度仍漂移，加弱"初始化位姿偏好"作为选解依据。

## 6. 输出与不可达诊断

每次求解输出：

- `root_pos/root_rot` + 全关节角度（含固定踝的参考值）
- 求解后实际 5 点位置 + 逐点位置误差
- `satisfied`：是否全部点在容差内
- 失败阶段（feet/head/hands）与停止原因

骨骼不拉伸。无解时返回当前最优候选 + 明确标注未满足点；
"求解器没找到" ≠ "数学上不可达"，文案中不混用。

## 8. 分阶段实施与验收

**A. 五点映射 + 自然姿态（首交付）**
- landmarks 表固化；与 adapter 口径对齐
- 自然姿态图片迭代（正/侧/斜面 + 5 点标注），用户确认冻结
- 验收：渲染姿态"看着不累"、关节不越界

**B. 单 P5 补全**
- 回归：自然姿态提取的 P5 → 解出姿态 ≈ 自然姿态
- 小幅变体：低头、单手前伸、双脚分距、单手过头
- 验收：目标点误差 < 容差、姿态视觉合理、无随机差异（同输入同输出）

**C. 叠加可视化**
- 渲染全身结果 + 目标 5 点 + 实际 5 点 + 误差标注
- 验证刚度配置（观察是否过度扭腰/奇怪肘向）

**D. clip 连续补全（单帧验收后）**
- 先逐帧独立求解看跳变；有问题再加连续性项（仍纯几何）
- 验收：相邻帧姿态变化连续、无构型跳变

## 9. 主要风险

| 风险 | 应对 |
|---|---|
| 五点映射不一致（踝中心 vs body 原点） | 先固化 landmarks，adapter/求解共用 |
| 多局部解 → 不同初值不同结果 | 固定初始化规则；漂移再加深陷偏好 |
| 刚度量不合理 → 姿态怪 | A/B 阶段看图迭代，权重按组调 |
| 不可达输入被误当成功 | 逐点误差 + satisfied 字段显式输出 |
| 自碰撞姿态被渲染"看着还行" | v1 不判定；常见问题再专项补 |
