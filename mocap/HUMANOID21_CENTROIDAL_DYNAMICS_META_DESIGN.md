# Humanoid21 质心动力学模型元设计

> 类型：设计边界与验收框架  
> 状态：提案，未实现、未验证  
> 范围：Humanoid21 的质心动力学抽象，以及它与未来主路径规划、全身细化、真实仿真的契约  
> 本次交付：仅本文档。以下构建步骤、实验和接口均为后续工作，不表示已经执行。

## 1. 为什么需要这个模型

目标是从一个完整仿真状态 A 出发，到达目标状态约束集合 B，并找到具有物理意义、能够继续执行后续行为的运动。

当前 Reclip 直接优化关节控制序列，再用仿真检查路径进度。这种方法需要通过大量试错，隐式发现支撑、重心转移和动量协调。已有 pilot 暴露出一个问题：动作可以精确回放，也可以达到路径进度事件，但仍不具备合格的运动质量。

质心动力学模型要提供一个更低维、可解释的中间层：

```text
完整初态 A + 目标集合 B
    → 接触方案与质心/动量主路径
    → 全身运动与实际控制动作
    → Humanoid21 仿真验证
    → 将失败原因反馈给主路径规划
```

本模型首先回答“身体整体如何被外力推动、如何保持或改变动量”。主路径规划器使用模型求解；全身细化器负责把主路径落实到关节与执行器。三者职责必须分开。

## 2. 它是什么，以及不承诺什么

### 2.1 定义

质心动力学模型（centroidal dynamics model）是对**单个机器人全部刚体**的整体运动描述。它保留全身质心、线动量、绕质心的角动量及外部接触作用，暂时不把所有关节作为规划自由度。

它包含两个不同层次：

1. **状态与受力解释层**：从完整仿真中提取质心量，核对动量收支。这是模型正确性的基础。
2. **降维预测层**：在给定接触方案与外力假设下，预测质心和动量演化，并提供必要的可行性约束，供未来规划使用。

整体动量平衡具有明确的物理基础；把接触力作为可选择输入、把全身构型省略后形成的规划模型，则是有适用边界的抽象。

### 2.2 必须防止的误解

- 机器人根位置不是全身质心，根速度不是质心速度。
- 根朝向和根角速度不能代表全身角动量。摆臂、摆腿也携带角动量。
- 质心动力学不是一个只有位置、没有速度的几何骨架。
- 接触力是降维模型的输入，但不是当前仿真器可直接下发的 action。
- 质心轨迹可行只是全身可实现的必要条件之一，不证明关节可达、力矩足够或 PD 控制能够跟踪。
- 不能从质心角动量唯一反推出躯干朝向；也不能默认使用一个恒定惯量矩阵把两者等同。
- “身体倾斜”和“不可恢复地失衡”不是同一件事；姿态直立也不保证动态可控。
- 搜索超时或局部求解失败不等于证明 A 无法到达 B。

## 3. 应该有什么：最小模型组成

| 组成 | 应包含的信息 | 用途 |
|---|---|---|
| 机器人物理描述 | 刚体归属、质量、惯量、运动学结构、接触几何、控制限制 | 定义模型适用的实体 |
| 质心状态 | 质心位置 c、线动量 l、质心角动量 L | 描述整体运动 |
| 接触描述 | 接触对象、位置、法向、接触坐标系、可用摩擦及力矩能力 | 描述外界如何作用于机器人 |
| 外部作用 | 重力、地面接触、推力及其他外部约束作用 | 闭合动量收支 |
| 动力学关系 | 连续平衡、离散推进、接触切换的处理约定 | 预测与核验 |
| 适用域与能力边界 | 接触模式、可达区域、构型依赖的能力近似 | 避免生成明显无法细化的主路径 |
| 目标集合契约 | 可在质心层检查的目标，与必须保留给全身层的目标 | 正确表达 A → B |
| 诊断与证据 | 残差、接触余量、适用域违例、预测误差、来源版本 | 验收及定位失败 |

建议核心状态采用 `z = (c, l, L)`，共 9 个连续量；质心速度由 `v_c = l / m` 得到。接触模式、落脚位置、阶段时间和全身参考构型属于伴随信息，不算作这 9 个量能够隐含表达的内容。

躯干朝向、足部位姿、打击末端状态可以作为后续主路径的辅助变量，但必须注明它们需要额外运动学/动力学关系。不能因为把字段加入数据结构，就认为质心模型已经能够预测它们。

## 4. 关键物理定义与坐标契约

### 4.1 状态定义

对属于目标机器人的每个刚体 i，设质量为 m_i，刚体质心位置和速度为 r_i、v_i，世界坐标下的质心惯量为 I_i，角速度为 ω_i：

```text
m = Σ m_i
c = Σ(m_i r_i) / m
l = Σ(m_i v_i)
L = Σ[I_i ω_i + (r_i - c) × m_i(v_i - v_c)]
```

角动量包含刚体自身转动和各刚体围绕全身质心运动的贡献。惯量必须旋转到与速度相同的坐标系，位置必须使用刚体质心，而非随意使用 body 原点。

提取公式与 MuJoCo 可用的质心/动量接口应独立交叉核对。未来可以用质心动量矩阵表达 `h = A_G(q) v`，但必须明确其角/线分量排列、参考点和坐标系，不能直接拼接不同约定的空间向量。

### 4.2 动力学定义

在均匀重力下，围绕瞬时全身质心写平衡关系：

```text
ċ = l / m
ḷ = m g + Σ f_j + f_ext
Ĺ = Σ[(p_j - c) × f_j + τ_j] + τ_ext,c
```

- f_j 是外界作用在该机器人上的力，p_j 是作用点。
- τ_j 是接触在 p_j 处真实允许的附加力偶，不是任意可用的控制量。
- τ_ext,c 已转换到质心参考点；不能遗漏外部推力的力臂，也不能重复计入。
- 同一机器人内部的接触作用在整体收支中相互抵消。另一机器人、地面、墙壁的作用均属于外部作用。
- 内部电机能够改变构型和动量分配，并通过接触影响外力；不能作为任意改变全身总动量的额外外力。

对仿真中存在的附加惯性、被动元件、外部约束或插件作用，应核对上述刚体公式与实际动力学的对应关系。若存在未被刚体求和覆盖的项，必须显式记录和解释残差，不能把不闭合全部归因于“数值误差”。

### 4.3 统一约定

- 第一版内部计算统一采用世界坐标和 SI 单位；角动量参考点固定为全身质心。
- 每个 wrench 必须注明“作用于谁”“在哪一点表示”“在哪个坐标系表达”。
- 局部 CoreState 速度转为世界量时，应复用并核对现有仿真器约定。
- 以物理子步分析力和动量；规划步长可更粗，但要记录其与控制步长、物理步长的关系。
- CoreClip 的 20 Hz 状态不足以重建所有接触力峰值和冲量；后续核验需要真实物理回放中的子步记录。
- 仅恢复 CoreState 不一定恢复所有求解器缓存、控制目标和插件状态。复现实验必须定义完整的初始化与同步步骤。

## 5. 接触是模型的核心边界

### 5.1 先忠实于 Humanoid21 的接触几何

当前只读核对确认：`Humanoid21Simulator` 加载 `battle_circular_v2.xml`；脚部由胶囊几何构成，相关默认接触维度为 `condim=3`。这不是可以直接假设为理想刚性矩形平足的模型。

因此第一版应从实际接触点力及其聚合入手：

- 单个三维接触点具有法向力和切向摩擦力，不能凭空添加独立扭转/滚动接触力矩。
- 多接触点的力可以通过力臂形成合力矩；聚合到一个足部参考点时必须保持合力和合力矩等价。
- 几何足部覆盖范围、实际接触点集合、规划允许的接触区域应分别记录。
- 不能因为某只脚有非零触地信号，就把整只脚的几何外轮廓作为可用支撑多边形。
- 摩擦及接触参数应以实际加载模型和接触对的有效参数为准，不只读取 XML 中某一行默认值。

未来可以把多点接触压缩为足部 wrench cone，但必须先证明这种近似不会扩大实际可用的接触能力。

### 5.2 约束与模式

基本约束包括非负法向力、摩擦锥或其保守近似、合法接触区域，以及与接触模式一致的非穿透和滑动假设。

“有接触”“承重”“无滑移支撑”是不同状态。记录层应保留真实测量，规划层可以采用带滞回的模式判定，避免阈值抖动，但不能用滞回抹去真实的接触丢失。

第一版以给定的双脚地面接触方案为范围，不求解接触序列。即使双脚方案固定，实际接触点仍可能移动或数量变化；失去支撑、发生明显滑移或出现未建模接触时，应报告超出适用域。

接触切换、腾空、落地和冲击属于扩展阶段。届时需要按冲量核对动量跳变，不能用粗时间步的平滑力模型掩盖冲击。

## 6. 目标集合 B 与“保持平衡”

完整状态 x 到质心状态 z 的映射是多对一。两个 z 相同的机器人可以有不同关节构型、末端位置和可恢复能力。

所以目标集合需要分成相互关联的两部分：

| 层次 | 可以表达的要求 | 不能据此单独宣布的结论 |
|---|---|---|
| 质心层 | 质心区域、速度/动量范围、接触模式、接触能力余量 | 已完成指定出拳姿态 |
| 全身层 | 根朝向、关节构型、手脚位姿与速度、碰撞和执行器限制 | 仅凭几何匹配就已动态稳定 |

质心层目标是完整目标的投影或近似，必须标明是外近似、保守近似还是经验代理。落入外近似只能说明值得继续细化。

根位置自由也不意味着没有物理边界：平面平移可自由，而离地高度、接触关系和可达性仍应由任务与动力学约束表达。不能在本模型中悄悄改写现有 `root_pos_mode=free` 的语义。

平衡相关评价至少区分：

1. **当前受力可行**：接触力是否在允许范围内，动量变化是否满足平衡。
2. **有限时域可继续**：给定接触方案下，是否存在下一段可行动作。
3. **恢复控制器验证通过**：特定控制器接管后是否恢复到指定集合。

三者都不等于求得精确的可行域或可恢复域。捕获点、支撑投影、倾斜角可以作为有假设的诊断，不能当作通用稳定证明。

`pass` 的目标仍允许非零末速度。未来应把“通过任务目标”和“末态仍可继续控制”分别验收，而不是把 pass 改成必须停止，也不是允许完成事件掩盖随后失控。

## 7. 如何与全身细化和 Reclip 协作

未来主路径应向下游提供：

- 质心、线动量、角动量的时间轨迹或允许范围；
- 接触阶段、候选落脚位置和接触力参考；
- 目标集合、必要的全身辅助约束以及允许偏差；
- 假设、有效域、模型版本和可行性余量。

这些产物宜作为独立的主路径描述，不应冒充已有 CoreClip。CoreClip 仍描述全身状态与可选执行动作。

全身细化需要反馈结构化失败：运动学不可达、接触不一致、关节/执行器超限、跟踪失败、模型预测失配或计算预算耗尽。上层据此修改时间、支撑分配、质心路径，必要时更换接触方案。

当前仿真器采用归一化关节位置目标与 PD 控制。即使某全身优化器能给出理想力矩，也必须再验证它能否通过这个实际 action 接口实现。质心模型自身不负责承诺这一步成功。

不应预先断言加入主路径一定提升吞吐；额外规划成本和反复细化成本都要计入。

## 8. 如何构建：按证据逐层推进

| 阶段 | 工作内容 | 交付与进入下一阶段的条件 |
|---|---|---|
| M0：物理契约审计 | 确认刚体归属、编译后质量惯量、接触几何、摩擦、执行器、被动项、外部作用、时间与坐标约定 | 可复核的物理参数清单和模型指纹；未决项显式列出 |
| M1：只读状态提取 | 从完整仿真状态计算 c、l、L，独立交叉核对 | 状态提取报告；坐标、机器人隔离、惯量参考点测试通过 |
| M2：受力与收支核验 | 提取接触/外部作用，核对每段运动的动量变化 | 动量收支报告；不存在未解释的系统性残差 |
| M3：降维预测 | 使用明确输入的接触力与接触方案推进 z | 在声明的时域与适用域内满足独立预测误差门槛 |
| M4：规划能力边界 | 加入保守接触能力、构型可达性和能力近似，定义目标集合接口 | 能标明哪些结论只是必要条件，能拒绝已知不合法输入 |
| M5：下游集成评估 | 后续由主路径规划和全身细化共同验证 | 在相同计算预算下，与直接 Reclip 比较合格率和耗时 |

M0–M4 构成模型建设路线；M5 是系统价值验证，不能在尚无全身细化器时伪称完成。所有阶段均为后续提案，本次不创建实现、采集数据或运行实验。

第一版范围建议：单机器人、平地、双脚给定支撑、无对手碰撞，包含站立、受控重心转移和支撑不变的上肢运动。全身形变仍然存在，不能退化为恒定惯量的单刚体。

转步、单脚踢腿、腾空、落地、与对手交互、跌倒恢复留作扩展。超出范围的输入应报告不支持或适用域违例，不静默裁剪成第一版问题。

## 9. 如何验收：模型正确性与系统价值分开

### 9.1 验收矩阵

| 验收项目 | 试验/证据 | 通过原则 |
|---|---|---|
| 实体隔离 | 改变 robot_b 状态，保持 robot_a 不变且无接触 | robot_a 的质量和质心量不被污染 |
| 状态提取 | 多构型、多速度，刚体求和与独立接口/推导交叉核对 | c、l、L 误差符合预先冻结的数值门槛 |
| 坐标一致性 | 整体平移；绕重力轴旋转整个场景；速度坐标变换 | 质心随位置变换，质心角动量平移不变，向量旋转协变 |
| 动量收支 | 自由运动、持续支撑、已知外推力、上肢摆动 | 重力与外力可解释线/角动量变化，无系统性符号或力臂错误 |
| 接触聚合 | 原始点力与足部聚合 wrench 对比 | 合力、合力矩一致，且不增加不存在的接触能力 |
| 接触能力 | 拉地、过摩擦、虚构接触力矩等反例 | 非法候选被明确拒绝或标为域外 |
| 离散预测 | 一步及多步，对照物理子步积分 | 声明时域内误差受控；时域变长时报告误差增长 |
| 可恢复性代理 | 相似姿态但不同速度/动量的状态对 | 能暴露动态风险差异，不以倾斜角或高度单独判定 |
| 失败语义 | 缺字段、未知外力、域外接触、预算耗尽 | 显式错误或分类失败，不输出伪成功 |

静止支撑时合力应近似抵消重力；无外部接触和外推力时，线动量变化应由重力解释，绕质心角动量应符合无外力矩条件。这些是基础核验场景，不代表第一版必须支持腾空规划。

### 9.2 重点使用积分收支

接触力可能尖锐，直接对低频状态求导会放大噪声。应优先比较一个时间窗中的动量增量与子步外力积分：

```text
r_l = l(t1) - l(t0) - ∫[m g + Σf + f_ext] dt
r_L = L(t1) - L(t0) - ∫[Σ((p-c)×f + τ) + τ_ext,c] dt
```

同时检查采样相位、接触力与状态时间对齐、warm start 和离散积分误差。残差应按来源解释，不能只给一个平均数。

### 9.3 阈值如何制定

本元设计不把未经测量的厘米数、角度数或百分比写成既定门槛。后续必须先完成以下过程，再宣布验收：

1. 分离校准集与独立验收集，覆盖静态、动态、近边界和故意违规样本。
2. 依据仿真重复性、子步离散误差和独立提取误差确定数值基线。
3. 按下游允许的规划偏差确定预测容差，不能只按拟合结果反向放宽阈值。
4. 冻结绝对误差、归一化误差、最大值/分位数、预测时域和域外比例门槛。
5. 在独立验收集上报告结果；门槛变动必须记录原因，并重新验收。

归一化可用质量 m、特征长度 ℓ、速度 √(gℓ) 构造尺度：线动量尺度为 `m√(gℓ)`，角动量尺度为 `mℓ√(gℓ)`。不能用接近零的瞬时动量作相对误差分母。

必须区分两种证据：用真实记录的接触力积分，只验证收支和积分器；使用规划得到的力预测未来，再由全身控制实际实现，才能验证规划用途。不能用前一种结果宣称后一种能力。

### 9.4 系统价值的后续验收

使用相同初态、目标集合、物理配置及总计算预算，对比直接 Reclip 与“质心主路径 + 全身细化”。至少报告：

- 质心层候选通过率、全身细化通过率、最终任务合格率；
- 全身接触/执行器违例、末态接管结果及模型失配；
- 首个合格解耗时、总耗时、仿真步数、超时率与长尾耗时；
- 按初态类别统计成功和失败，避免只在容易的状态上筛选后比较。

首个可行解速度与动作本身时长是两个指标，应分别优化和报告。合格判据必须包含任务完成、全身约束和明确的继续控制测试；回放误差小或 `s>=1` 单独不足以通过。

## 10. 证据产物与可视化要求

未来实现至少应交付：

- 物理参数与模型指纹清单，包括 XML/编译模型相关参数、MuJoCo 版本、控制参数及插件配置；
- 状态/接触/坐标契约及适用域说明；
- 独立核验数据、分阶段验收报告、失败样例；
- 质心预测与真实回放对照，带接触点、力箭头、质心位置/速度及角动量显示；
- 误差与约束余量的时间曲线，能定位某一帧发生了什么；
- 规划候选与全身细化之间的失败反馈记录。

可视化用于检查解释是否符合实际，不能替代动量收支和执行验证。后续采样频率、文件格式、类名和目录结构留给详细设计决定。

## 11. 当前设计决定与待定项

**本元设计建议确定的边界：**

- 以单机器人全身质心及动量为核心，采用世界坐标和明确的受力方向。
- 先建设状态提取与动量收支核验，再建设预测与规划约束。
- 接触能力来自实际几何与有效接触参数，不预设理想平足 wrench。
- 第一版接触方案给定；接触序列搜索独立于模型。
- 全身可实现性、PD action 可执行性、末态可继续控制性分别验证。
- 本次不改变 Reclip 的目标语义、筛选规则或已有实验产物。

**必须通过审计或实验确定的事项：**

- 编译后总质量、惯量、机器人 body 集合及附加动力学项的处理；
- 胶囊脚实际接触可支持的力矩范围及其保守近似；
- 规划时间步长、有效预测时域、接触模式判定阈值；
- 构型可达性与执行器能力近似采用什么表达；
- 目标集合中哪些条件可投影，哪些必须留给全身层；
- 继续控制测试采用什么控制器、时域、允许接触与成功集合；
- 误差门槛、求解预算，以及是否值得引入更复杂的接触模型。

这些待定项不妨碍先建立可核对的状态和动量收支模型，但会阻止过早声称它已经能够规划稳定打击。
