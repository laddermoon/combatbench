# Humanoid21 技术规范

本文档详细说明观测空间、动作空间、机器人控制模式等技术细节。

## 观测空间

### 结构

观测空间为 `Dict` 类型，包含两个机器人的观测：

```python
{
    "robot_a_obs": Box(-inf, inf, (127,), float32),
    "robot_b_obs": Box(-inf, inf, (127,), float32),
}
```

### 观测维度分解 (127维)

| 模块 | 维度 | 说明 |
|------|------|------|
| **本体感知** | 42 | 关节位置 (21) + 关节速度 (21) |
| **根状态** | 13 | 高度 (1) + 局部姿态 (6) + 速度 (6) |
| **触觉反馈** | 8 | 脚部接触 (2) + 外力 (6) |
| **对手观测** | 64 | 相对状态 + 关键点 |

#### 1. 本体感知 (42维)

- **关节位置 (21维)**：所有可控关节的当前位置
- **关节速度 (21维)**：所有可控关节的当前速度

#### 2. 根状态 (13维)

- **高度 (1维)**：根节点（骨盆）的 z 坐标
- **局部姿态 (6维)**：旋转矩阵的前两列 `[r[:,0], r[:,1]]`
- **线速度 (3维)**：根节点的线速度 `[vx, vy, vz]`
- **角速度 (3维)**：根节点的角速度 `[ωx, ωy, ωz]`

#### 3. 触觉反馈 (8维)

- **脚部接触 (2维)**：`[左脚接触, 右脚接触]`，0/1 二值
- **外力 (6维)**：施加在关键部位的力
  - 骨盆受力 (3维)
  - 头部受力 (3维)
  - 左手受力 (3维)
  - 右手受力 (3维)
  - 取前6维（骨盆+头部）或累积

#### 4. 对手观测 (64维)

- **相对位置 (3维)**：对手根节点相对位置
- **相对速度 (3维)**：对手根节点相对线速度
- **对手四元数 (4维)**：`[w, x, y, z]`
- **关键点位置 (27维)**：9个关键点的相对位置（局部坐标）
- **关键点速度 (27维)**：9个关键点的相对速度（局部坐标）

**关键点列表**：
- head, hand_right, hand_left, lower_arm_right, lower_arm_left
- shin_right, shin_left, foot_right, foot_left

## 动作空间

### 结构

动作空间为 `Dict` 类型，包含两个机器人的动作：

```python
{
    "robot_a": Box(-1.0, 1.0, (21,), float32),
    "robot_b": Box(-1.0, 1.0, (21,), float32),
}
```

### 动作维度 (21维)

动作值域为 `[-1, 1]`，对应 21 个可控关节：

| 索引 | 关节 | 说明 |
|------|------|------|
| 0-2 | abdomen_z, abdomen_y, abdomen_x | 腹部 (3) |
| 3-8 | hip_x_r, hip_z_r, hip_y_r, knee_r, ankle_y_r, ankle_x_r | 右腿 (6) |
| 9-14 | hip_x_l, hip_z_l, hip_y_l, knee_l, ankle_y_l, ankle_x_l | 左腿 (6) |
| 15-17 | shoulder1_r, shoulder2_r, elbow_r | 右臂 (3) |
| 18-20 | shoulder1_l, shoulder2_l, elbow_l | 左臂 (3) |

### 动作映射

动作 `[-1, 1]` 通过以下方式映射到关节目标位置：

```python
# 动作归一化到 [-1, 1]
# 目标位置 = 动作 × 关节范围缩放
# 然后通过 PD 控制器执行
```

## 机器人控制模式

### PD 控制

机器人使用 PD 控制器进行关节控制：

```
τ = Kp × (q_target - q_current) + Kd × (q_dot_target - q_dot_current)
```

**参数**：
- `Kp = 4.0`（比例增益）
- `Kd = 0.4`（微分增益）
- `q_target`：由动作计算得出
- `q_current`：当前关节位置
- `q_dot_target = 0`：目标速度为零

### 控制流程

```
动作 [-1, 1]
    ↓
归一化处理
    ↓
目标关节位置
    ↓
PD 控制器
    ↓
关节力矩
    ↓
MuJoCo 物理引擎
```

### 物理步与控制步

- **物理时间步 (dt)**：0.002 秒 (500 Hz)
- **控制频率**：默认 20 Hz
- **每控制步物理步数**：`phy_steps_per_action = 500 / 20 = 25`

## 伤害系统

### 有效攻击部位

攻击部位（造成伤害）：
- 手 (hand)
- 前臂 (larm)
- 上臂 (uarm)
- 大腿 (thigh)
- 小腿 (shin)
- 脚 (foot)

### 易伤部位

易伤部位（承受伤害）：
- 头 (head)
- 躯干 (torso)
- 腰部 (waist)

### 伤害计算

```
伤害 = -(权重 × 冲量) / damage_scale
```

**伤害规则**：
- 头部：权重 = -3.0
- 躯干：权重 = -1.0

**默认 damage_scale = 100.0**

### KO 判定

- 当某方血量 ≤ 0 时，立即判定 KO
- 对方获胜

## 环境信息

### info 字典内容

```python
{
    'step': int,                    # 当前步数
    'health': {
        'robot_a': float,           # 机器人 A 血量
        'robot_b': float,           # 机器人 B 血量
    },
    'damage_taken': {
        'robot_a': float,           # 机器人 A 承受伤害
        'robot_b': float,           # 机器人 B 承受伤害
    },
    'events': [                     # 事件列表
        {
            'type': 'hit',
            'attacker': 'robot_a',
            'defender': 'robot_b',
            'part': 'head',         # 击中部位
            'damage': float         # 伤害值
        },
        ...
    ],
    'winner': str,                  # 获胜者（'robot_a', 'robot_b', 'draw'）
    'termination_reasons': [...]    # 终止原因
}
```

### 终止原因

- `TIMEOUT`：时间到
- `KO`：血量耗尽
- `FOUL`：犯规（如有）
- `OUT_OF_BOUNDS`：出界（如有）
- `CUSTOM`：自定义原因

## 奖励函数

当前实现中，奖励函数返回 0.0：

```python
def build_reward(self, ctx: SimContext) -> Dict[str, float]:
    return {'robot_a': 0.0, 'robot_b': 0.0}
```

可以根据需要自定义奖励函数，例如：
- 造成伤害奖励
- 保持直立奖励
- 接近对手奖励
- 击中关键部位奖励

## 防摔倒约束

当启用 `non_fall_mode` 时：

### 约束条件

- **Pitch 限制**：`±pitch_limit_deg`（默认 ±5°）
- **Roll 限制**：`±roll_limit_deg`（默认 ±5°）

### 约束行为

当姿态超过阈值时：
1. 将 pitch/roll 裁剪到阈值范围内
2. 清零水平线速度 `(vx, vy)`

### 检测指标

环境会记录每个机器人的 `clamp_count`，表示被拉回的次数。

## 初始状态

### 机器人位置

- 两个机器人相向而立
- 初始距离：2 米
- 初始姿态：站立

### 关节初始位置

从 MuJoCo XML 的 `qpos0` 读取，通常为自然站立姿态。
