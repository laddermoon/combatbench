# 接触参数设计 (battle_v2)

本文档描述 `battle_v2.xml` 的接触参数方案。所有结论均来自本目录下模型的实测，
测量脚本的做法记录在文末「复现方法」一节。

> 旧版 `CONTACT_DESIGN.md` 与 `battle_v1_new.xml` 已删除。它们的参数建立在对
> MuJoCo `gap`、`solref` 合成规则和 `condim` 合成规则的误读之上，见「附录：旧方案
> 为什么无效」。

---

## 一、必须先理解的三条 MuJoCo 合成规则

动态生成的接触，其参数**不是**直接取自单个 geom，而是由两个 geom 合成。
不理解这三条规则写出来的参数大部分是无效的。

### 规则 1：`condim` 取两者最大值

```
contact.condim = max(condim_1, condim_2)
```

实测（`battle_v1.xml`，脚 `condim=1`、地面 `condim=3`）：

```
ground x foot1_right_a  ->  dim=3
```

**推论**：v1 中脚虽然写着 `condim=1`，脚地接触仍然是 3 维、摩擦正常，行走没有问题。
真正受影响的是**机器人之间**的接触——双方都是 `condim=1`，取 max 仍是 1。

实测两机器人对撞 400 步，跨机器人接触共 726 个，**全部 dim=1（零摩擦）**。
这是 v1 唯一确凿的接触缺陷。

### 规则 2：`friction` 逐元素取最大值

```
contact.friction[i] = max(friction_1[i], friction_2[i])
```

**推论**：地面 `friction=1.0`，脚上无论写 `0.7` 还是 `0.9`，合成结果都是 `1.0`。
不设 `priority` 的情况下，**脚的滑动摩擦系数完全无法通过脚 geom 控制**。

### 规则 3：`solref` / `solimp` 按 `solmix` 加权平均

```
contact.solref = (solmix_1 * solref_1 + solmix_2 * solref_2) / (solmix_1 + solmix_2)
```

实测（脚 `solref=0.004`、地面 `solref=0.02`）：

```
ACTUAL contact solref = 0.012
```

**推论**：想要的 4ms 时间常数从未生效，实际是 12ms。

### 破解方法：`priority`

`priority` 高的 geom **完全接管**接触参数（condim / friction / solref / solimp 全部），
不再做 max 或平均。这是唯一能精确控制接触行为的手段，v2 方案的结构基础。

## 二、v2 参数方案

### 2.1 全局

```xml
<option timestep="0.002" impratio="10" />
```

| 参数 | 取值 | 依据 |
| :--- | :--- | :--- |
| `timestep` | `0.002` | 实测 `0.001` 使 8 m/s 穿透从 83mm 恶化到 92mm，且耗时翻倍。无收益。 |
| `impratio` | `10` | 摩擦约束刚度与法向的比值。见下表实测。 |
| `iterations` | 默认 100 | 实测 `200` 与 `100` 结果**逐位相同**，求解器未受迭代次数限制。 |
| `cone` | 默认 pyramidal | 见 2.4 取舍说明。 |

`impratio` 实测（35 kg 载荷、施加 μ=0.5 的横向力，理想应零滑移）：

| `impratio` | 滑移 | 30 N·m 偏航力矩下自旋 |
| :--- | ---: | ---: |
| 1（MuJoCo 默认） | 5.48 mm | 8.4° |
| **10** | **0.55 mm** | **0.8°** |

这是整个方案中收益最大的单个参数。

### 2.2 分层结构：两层，不是三层

```
priority = 0   场地 (ground / walls)
priority = 1   躯干与四肢 (torso/head/thigh/shin/arm/hand)
priority = 2   脚
```

只分两层机器人层级。旧方案把 hand/arm_lower 单列一层，但没有任何可测指标支持
"拳头需要不同接触参数"，徒增复杂度。**没有测量依据的分层不做。**

### 2.3 具体参数

**躯干与四肢（`priority=1`）**

```xml
<geom type="capsule" condim="3" friction="0.7 0.005 0.0001"
      solimp="0.9 0.95 0.002" solref="0.015 1" priority="1" />
```

- `condim="3"`：核心修复。让机器人互撞产生切向摩擦，推搡、纠缠不再打滑。
- `solref="0.015 1"`：15ms = 7.5×dt，临界阻尼。留足稳定裕度。
- `solimp="0.9 0.95 0.002"`：贴近 MuJoCo 默认。不刻意软化——实测软化反而使穿透变差（见 2.5）。

**脚（`priority=2`）**

```xml
<geom size=".027" condim="3" friction="1.0 0.02 0.001"
      solimp="0.9 0.95 0.001" solref="0.01 1" priority="2" />
```

- `priority="2"`：使这些值真正生效，而非与地面平均。实测确认脚地接触 `solref=[0.01, 1]`。
- `solref="0.01 1"`：10ms = 5×dt。比躯干硬，支撑即时；但不取 `0.004`（=2×dt，恰在
  MuJoCo 稳定性下限，无裕度）。
- `condim="3"` 而非 `4`：见下。

**`condim=4` 被否决**——实测在 `impratio=10` 下：

| 脚配置 | 自旋（30 N·m） | us/step |
| :--- | ---: | ---: |
| `condim=3` | 0.8° | 59.3 |
| `condim=4` | 0.9° | 60.9 |

扭转摩擦**没有带来任何抗自旋收益**，只增加成本。物理原因：每只脚由两根 capsule
组成、每根产生两个接触点，四个接触点的力臂本身就足以抵抗偏航，不需要额外的扭转
摩擦维度。抗自旋实际由 `impratio` 提供（8.4° → 0.8°）。

**场地（`priority=0`）**

```xml
<geom name="ground" ... condim="3" friction="1.0 0.005 0.0001"
      solref="0.02 1" solimp="0.9 0.95 0.001" />
<geom name="*wall"  ... condim="3" friction="0.3 0.005 0.0001"
      solref="0.02 1" solimp="0.9 0.95 0.001" />
```

- 地面用 MuJoCo 默认值，只是写显式，避免隐式依赖。
- **墙面摩擦刻意调低到 0.3**：这是一个反 exploit 决策。墙面若保持
  `friction=1.0`，机器人可以靠摩擦"挂"在墙上维持站立，为 standing / non-fall
  类任务提供廉价捷径。0.3 仍允许蹬墙借力，但无法悬挂。

### 2.4 `cone`：默认 pyramidal，高保真评测可切 elliptic

| `cone` | 滑移 | 自旋 | 8 m/s 穿透 | us/step |
| :--- | ---: | ---: | ---: | ---: |
| pyramidal（默认） | 0.55 mm | 0.8° | 83.1 mm | 59.3 |
| elliptic | 0.26 mm | 0.2° | 77.8 mm | 66.4 |

elliptic 各项都更好，代价是再 **+12%** 耗时（相对 v1 累计 +25%）。

**默认选 pyramidal**，理由：pyramidal 的已知缺陷是摩擦各向异性（对角方向摩擦上限
被高估最多 √2 倍），但在 `impratio=10` 下滑移已压到 0.55mm，策略在所有方向都处于
"不滑" 区间，各向异性没有可利用的空间。把 12% 的训练吞吐换取一个实际无法触发的
精度提升不划算。

**需要时一行切换**：`<option cone="elliptic" ...>`。建议在最终评测 / 论文数据上使用。

### 2.5 明确不使用 `margin` / `gap`

v2 全部保持 `margin=0`、`gap=0`。

`gap` 的真实语义是 `includemargin = margin - gap`，`[margin-gap, margin]` 区间内的接触
被放进 `mjData.contact` 但**不进求解器、不产生任何力**。实测确认：

```
margin=0.0120 gap=0.0100 -> includemargin=0.0020
```

因此 `margin/gap` 组合有三个问题：

1. **不产生"气垫"**。它只是把接触检测距离推远，力的起点仍在 `margin-gap`。
   想要 2mm 缓冲直接写 `margin="0.002"` 即可，加 `gap` 纯属自我欺骗。
2. **有成本无收益**。gap 区间内的 inactive 接触照样跑窄相检测、照样占 `mjData.contact`
   槽位，只是不出力。
3. **`margin` 会放大 hitbox**。geom 在接触意义上变"胖"。若命中判定依赖接触，
   这等于悄悄改变了判定范围——这种事必须显式设计，不能作为副作用出现。

此外实测表明**软化并不能减少穿透**：把躯干 `solimp` 从 `0.9 0.95 0.002` 软化到
`0.8 0.95 0.006`，8 m/s 穿透反而从 83.1mm 涨到 103.0mm。深穿透来自碰撞后两具身体在
重力下互相压叠，不是接触刚度不足，软化只会让压叠更深。

## 三、v1 → v2 实测对照

| 指标 | `battle_v1` | `battle_v2` | 说明 |
| :--- | ---: | ---: | :--- |
| 跨机器人接触维度 | **1（零摩擦）** | **3** | 核心修复 |
| 8 m/s 对撞最大穿透 | 106.1 mm | **83.1 mm** | −22% |
| μ=0.5 横向力滑移 | — | 0.55 mm | |
| 30 N·m 偏航自旋 | — | 0.8° | |
| 静载穿透 | — | 0.005 mm | |
| 平均 `nefc` | 72.3 | **72.3** | 无增长 |
| us/step | 53.3 | 59.3 | **+11%** |
| 10 s 稳定性 | 通过 | 通过 | 无 NaN、无爆震 |

作为对比，已删除的 `battle_v1_new.xml`：穿透 **114.2mm（比 v1 更差）**，
`nefc` 86.2，us/step 65.4（比 v2 慢 9%）。即：旧方案在三项主要指标上都劣于 v2。

## 四、复现方法

所有数字可用如下方式复现（`dt=0.002`，模型为本目录 XML）：

- **接触合成规则**：`mj_step` 若干步后读 `d.contact[c].dim / .solref / .friction / .includemargin`，
  与 `m.geom_*` 对比。
- **滑移 / 自旋**：独立探针模型——一根与脚同参数的 capsule（35 kg）落在地面上，
  施加 `0.5·m·g` 横向力 1000 步测位移；施加 30 N·m 偏航力矩 1000 步测转角。
  用独立探针而非整机，是因为整机没有站立控制器会直接摔倒，指标会被摔倒过程污染。
- **穿透**：两机器人 torso 分别给 ±8 m/s 初速对撞，取 800 步内所有跨机器人接触
  `dist` 的最小值。
- **性能**：预热 300 步后计时 3000 步。

## 五、遗留事项

- **圆形场地墙面需同步**：`combatbench_platform/scenebuilder` 生成的圆形场地墙目前
  使用 MuJoCo 默认摩擦（1.0）。大版本更新时应统一到本文的 `friction=0.3`。
- **`cone="elliptic"` 的评测基线**：若最终发布数据使用 elliptic，需重新跑一遍
  本文所有指标并更新第三节表格。
- **所有 v1 checkpoint 失效**：v2 改变了接触动力学，已训练策略不可迁移，需重训。
