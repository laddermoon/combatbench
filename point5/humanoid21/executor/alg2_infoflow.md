# 算法2 · 信息流分解

> 输入：`Observation, Clip, Landmarks` → 输出：`Action (21,)`
> 规范来源：`point5/humanoid21/bootstrip.md`

## 信息项（I）

| # | 名称 | 内容 | 来源 |
|---|---|---|---|
| I1 | 当前 P5 | 当前五点姿态 (5,3) | Observation 解码；clip kf0 亦有同一份 |
| I2 | 下一 landmark 的 P5 | 下一个锚点对应的五点姿态 | `F1(landmarks,clip)`  |
| I3 | 下一帧目标 P5 | 本控制步应到达的五点姿态 | `F2(I1, I2, I8)` |
| I4 | 当前姿态 | 关节位置 (21,) | obs[0:21] |
| I5 | 目标姿态 | 关节空间参考 (21,) | `F3(I3, I4, I8?)` |
| I6 | 当前质心位置 | com (3,) | obs 解码（工具1/8） |
| I7 | 锚点质心位置 | 下一 landmark 的 com (3,) | Landmarks |
| I8 | 下一帧质心目标 | 本控制步的质心位置目标 | `F4(I6, I7)` |
| R | 结果动作 | 归一化 PD 目标 (21,) | `F5(I8, I5)` |

## 功能点（F）

| # | 函数 | 签名 | 说明 | 难度 |
|---|---|---|---|---|
| F1 | 锚点 P5 求取 | `F1(landmarks, clip) -> I2` | 统一出口：姿态锚点→经 lm.frame 链接从 clip 关键帧取 pos；接触锚点→由锚点质心态（foot_pos/com）+先验/后续姿态 P5 补全 | 中低（欠定但先验强） |
| F2 | 下一帧 P5 目标 | `F2(I1, I2, I8) -> I3` | 当前 P5 → 锚点 P5 的过渡；须与质心轨迹一致（I8 输入）——非直线插值（摆动轨迹） | 中 |
| F3 | P5 → 关节姿态 | `F3(I3, I4, I8?) -> I5` | 全身姿态求解；I8 质心约束可选 | **已解决** = 工具2 pose_solver |
| F4 | 质心轨迹目标 | `F4(I6, I7) -> I8` | 插值 + capability 约束；含到达时刻决策 | 中 |
| F5 | 目标 → 动作 | `F5(I8, I5) -> R` | 跟踪控制器求解：候选=控制器参数（增益/残差），在**内部仿真器**闭环 rollout 评估——反馈信号来自内部 sim 每步输出，非外部信息项 | **核心难点** |

## 数据流（DAG）

```
输入解包
  Observation ──► I1, I4, I6
  Clip        ──► I1
  Landmarks   ──► I7

F1 出口
  landmarks, clip ──F1──► I2    （姿态锚点取 clip pos；接触锚点补全）

主链
  I6, I7 ──F4──► I8          （质心先行）
  I1, I2, I8 ──F2──► I3      （姿态目标与质心对齐）
  I3, I4, I8? ──F3──► I5     （关节姿态求解）
  I8, I5 ──F5──► R           （输出动作）

F5 内部闭环（非信息项）
  内部仿真器状态 ──反馈──► 跟踪控制器（rollout 内逐步）
```

执行顺序：**先 F4 出 I8，再由 F2 用 I8 锚定 I3**（姿态目标与质心轨迹一致），然后 F3、F5。

## 已知缺口

- **可行性检查**：I8 可能不可达——需 capability margin 判（工具4）后再决策
- **到达时刻**：Landmark 无时间，迈步帧物理需 ~1s——F4 需决策节奏或由调用方进度门控兜底
- **单帧视野**：逐帧推进本质短视，长后果需平衡项或更长视野兜底
