# Executor 第一阶段计划：标准站姿执行 stand_punch 指令

> 类型：实施计划；状态：待执行。本文不表示已实现或已通过验收。
> 总体目标与强制契约：[SERVO_PLAN.md](SERVO_PLAN.md)。
> 各任务按依赖顺序执行，适合由中级 AI 助手逐项交付。

## 1. 本阶段交付目标

从 Humanoid21 标准站立状态出发，调用方使用 `stand_punch.py` 生成 P5Clip，
提交给 Executor。Executor 通过简单规划和仿真动作搜索，真实执行五点动作，
在指令结束后收势并短时保持平衡。

最终交付：可调用的 Executor、可重跑的 CLI、固定评估集、轨迹/视频/诊断报告。
先离线运行，不设实时承诺；记录每周期耗时。拳击只负责提供测试指令，
Executor 核心不得按左右拳或目标坐标硬编码动作序列。

**范围：**平地、单机器人主动运动、另一机器人远离且无接触；执行几何出拳动作，
不模拟击中对手的冲量，不评估攻击伤害。本阶段不训练 PPO，不实现任意地形、
手撑/跳跃、跌倒起身或完整通用恢复策略。
缓存替换/清空必须具备正确契约；复杂执行中换任务的运动质量留待后续阶段。

**大逻辑优先：**

1. 少量确定规则 → 低维参考 → 真实仿真校核；避免一上来做全身非线性最优控制。
2. 时间主要由粗质心运动与支撑能力估计，再用手脚速度/加速度检查。
3. 允许保守、有限重试和明确失败；不能靠修改指令、放宽起点约束或无限延期掩盖失败。
4. 物理执行只能通过 Action 推进。严禁逐帧写 qpos、施加隐形扶正力、冻结身体等作弊。
5. 精确姿态只作初值/软偏好；代理质心和惯量不作为精确真值。

| `adapter.point5_from_view` | 局部 P5、世界原点与 yaw | 返回位置本身已是世界坐标 |

| `mocap/humanoid21/centroidal_dynamics/` | 真质心状态、外力收支、短时预测 | 已有完整质心规划器 |
| `mocap/humanoid21/clip/reclip.py`、`rederive_action.py` | 仿真序列搜索、滚动窗口与初值复用 | 现成的 P5/COM 评分或实时保证 |

路径未标前缀的均相对本目录；`mocap/`、`envs/`、`baseline/` 相对 combatbench。
先读本项目 `CLAUDE.md`、本目录 `CONTEXT.md` 及上述相关函数，不需要遍历整个训练框架。

### 必须在调用方解决的首帧问题

`stand_punch` 当前首帧 `coil` 已降低头部，不能直接从标准站姿提交。
演示调用方应先提取同一快照的 CurrentP5，传入 `plan_stand_punch(..., initial=...)`，
再显式构造 `start→coil→swing→land→strike` 五帧指令：

- `start.pos = CurrentP5.pos`，无 transfer。
- 为原 `coil` 添加从 start 到 coil 的 transfer。当前生成器中二者原点和 yaw
  不变，可用零位移/零转角；必须用世界点对照验证这一假设。
- 其余帧、标注、元数据与 transfer 保留；`dur` 放合法正数占位，执行时间另行安排。
- 可参考 `baseline/humanoid21/hierarchy/p5_world.py:prepend_start` 的逻辑，
  但本模块不应为此依赖 PPO 实验或使用其固定 0.65 秒配时。
- 原始四帧 Clip 直接提交必须被 Executor 拒绝。这不是接收层自动补接，
  不应修改 `stand_punch` 既有四帧 API 来绕过问题。

## 3. 实现边界与接口约定

建议新增 `point5/humanoid21/executor/` 包，按职责组织约 6 个模块：
`contracts.py`、`state.py`、`reference.py`、`search.py`、`executor.py`、`demo.py`。
单元测试集中于 `test_executor.py`，慢的闭环评估由 demo/评估入口负责，避免大量碎文件。
目录首次创建后按 context-curator 流程补充简短 CONTEXT。

建议接口（任务 E0 时固定具体签名）：

```python
executor.submit(current, clip)   # 同一快照，强校验，验证失败不替换旧缓存
executor.clear(current)          # 清空，进入收势/保持
result = executor.step(current) # 不提交就是 KEEP；返回 action、status、diagnostics
# 调用方只对真实环境执行一次 result.action，再提供新的 current
```

- `Current`：快照版本/时间、机器人 CoreState、世界放置、接触与克隆仿真所需信息。
  CoreState 六字段以 `mocap/humanoid21/clip/core_clip.py` 为准，不能丢速度。
- `action`：有限的 `(21,)` 归一化 PD 目标，范围 `[-1,1]`；不是力矩。
- `RefFrame`：相对规划时刻、世界五点位置/速度、yaw/yaw rate、COM 位置/速度、
  支撑阶段、容差；可选自然姿态参考及角动量范围。
- `status`：至少区分 RUNNING、SETTLING、HOLDING、FAILED。
  指令完成事件与进入 HOLDING 分开记录；拒绝提交是输入错误，不得算执行成功。
- 时间：控制周期 0.05s、物理周期 0.002s，核对模型后每 Action 推进 25 子步。
  `RefFrame[k]` 对齐未来第 k 个动作结束时刻；单独保留真实 t=0 边界。
- 保留不可变的提交记录/世界目标，另有内部剩余序列、单调事件进度和上次动作序列。
  更新内部首帧及 transfer 不得改变未完成目标的世界位置。

## 4. 任务分解与结果要求

依赖主线：`E0 → E1 → E2 → E3 → E4 → E5 → E6 → E7`。
E4 可在 E2 后开始，但其最终评分必须使用 E3 的时间参考。
每项完成后提交代码和本项结果；未通过验收不能标记完成，不能跳过问题直接调 MPC。

### E0 — 固定边界、案例与验收口径

**输入：**本计划、现有代码和标准站姿配置。
**工作：**固定上述数据结构、状态机和错误类型；读取
`Humanoid21Meta.INITIAL_POSES['standing']`，核对实际 reset。
保存固定案例表、配置和种子，不启动训练。
**产物：**contracts、配置与案例清单；简短接口说明。
**验收：**明确区分 KEEP/REPLACE/CLEAR；数值容差、失败状态、总预算均有唯一配置来源。
**要点：**站姿的原始关节弧度零不等于所有接口的归一化零；以后转换必须用相应定义。

### E1 — 可恢复的状态与无指令站立基线

**输入：**E0 接口；Simulator、adapter、CentroidalStateExtractor。
**工作：**构造标准站立环境，读取真实 P5/COM/速度/接触，建立工作仿真器快照恢复。
核对 `set_core_state` 没覆盖的仿真时间、warmstart、外力、控制目标及 Python 缓存，
使用完整快照或明确的统一重置策略。实际环境与搜索环境必须隔离。
先用当前姿态 PD 目标验证站立保持；不足时只做简单支撑/姿态反馈或短窗口搜索。
**产物：**state adapter、快照恢复、stand-hold 演示与重放检查。
**验收：**

- 同一快照和动作，单步预测与实际推进的 root/关节误差各 ≤1e-5
  （位置 m，关节比较用弧度）；短序列逐步重放同样比较，不混单位。
- 评估候选顺序交换后，同一候选结果不变；搜索不改变实际环境。
- 无指令保持 3s，无非足部地面接触；最后 1s 的 COM 速度 RMS ≤0.10m/s。
- 指标失败就先定位恢复/单位/PD 问题，不靠改成动态重置姿态通过。

**要点：**不把 current root 速度当 COM 速度；脚点是踝中心，z≈0.087 不代表离地。

### E2 — 合法指令生成、缓存与世界坐标锚定

**输入：**E1 Current、stand_punch 与 P5Clip。
**工作：**在 demo 调用方构造五帧指令；接收层做结构、快照版本、首帧校验。
解析并保存世界目标；每次实际执行后将内部首帧更新成 CurrentP5，
从保留的未来世界 frame pose 重算剩余 transfer，不移动目标。
**产物：**调用方 builder、缓存与进度结构、纯几何测试。
**验收：**

- 正确五帧提交通过；原四帧、头点改动 1mm、过期快照均被拒绝，旧缓存不变。
  首帧默认绝对容差 1e-6m、rtol=0，仅覆盖数值误差。
- 两种平移及 90° yaw 放置下，未来世界目标符合 SE(2) 变换。
- 多轮模拟跟踪误差后，内部首帧匹配实际状态；未消费世界关键帧误差 ≤1e-8m。
- 不提交继续执行；CLEAR 转收势，不构造非法零帧 P5Clip。

**要点：**提交时锚定是调用者义务，执行中维护是 Executor 义务；不能模糊两者。

### E3 — 用大逻辑生成支撑、质心与时间参考

**输入：**E2 世界关键帧、真实初始 COM/速度、本体粗能力参数。
**工作顺序：**

1. 从脚的世界位移/高度变化识别支撑脚、摆动脚和落地节点。
   第一版只支持双支撑与一脚摆动；不支持的接触类型返回原因。
   label 可用于诊断，不能靠 `strike` 名字决定关节动作。
2. `mass_proxy` 只在各关键帧自己的局部系计算，再变换到世界系；
   真 COM 作为 t=0，代理目标作为带容差的未来参考。
3. 固定支撑脚，分段平滑五点与 yaw；位置和速度来自同一曲线。
   第一版可在关键节点停顿以降低难度，明确这不保证真实打击速度。
4. 用有限候选配时。对归一化曲线 x(u)，通过
   `T >= max(max|x'|/v_cap, sqrt(max|x''|/a_cap))` 给出初值，
   综合 COM、手脚、转向与接触转换的时间需求；保留当前非零速度边界。
5. 粗查 `F=m(a-g)` 的法向/摩擦能力及支撑力矩；能力参数来自摩擦、
   本体量级和保守配置，记录依据，不能把摩擦能力当成完整执行器能力。
   可用固定接触候选的非负力分配小问题；若暂不检查力矩，显式标为未验证。
6. 不满足时按 1.25 倍延长时长，最多 6 次且总任务 ≤6s。
   静态/几何矛盾直接拒绝；支撑转换失败不能通过无限放慢掩盖。

**产物：**有限时长的 RefFrame 序列、各段时长来源、接触阶段、粗可行性诊断。
**验收：**t=0 对齐实测；关键帧位置保持，时间严格递增；支撑脚世界位置不漂移；
速度与位置数值差分一致（误差随差分步长减小）；每次延时能解释限制来源。
增加位移或降低能力上限的受控对比，应增加所需时间或明确拒绝。
测试不得把原 0.1s 占位或 PPO 的 0.65s 直接当作输出配时。

**注意/可尝试方向：**参考 COM 与五点共享进度，不从任意 CNext 独立反解五点。
先尝试零端速曲线与粗 COM 容差 0.08m；若卸载/摆动冲突，尝试小范围质心候选，
但不偷偷增加头/手关键帧位移。无解应列出冲突，需要改变指令时交给调用方重新规划。
当前保守 domain checker 不适合作为所有动态支撑的唯一拒绝条件。

### E4 — 姿态初值与可解释的 rollout 评分

**输入：**E2/E3 几何参考、mechanics、工作仿真器。
**工作：**可选地反解少量节点并缓存；用 q_rad 按 Simulator 的 reference/scale
转换为动作初值，不能默认 mechanics.q_norm 与 Simulator 的归一化一致。
独立实现 rollout scorer：真实五点/COM、yaw、支撑脚速度、非预期接触、动作变化。
自然关节姿态只用较弱权重；不要搬用 reclip 的固定 root_z 防跌倒奖励。
**产物：**候选动作初值、逐通道代价/违规诊断。
**验收：**单位、坐标、采样时刻明确；人为扰动单个评分量能改变对应通道；
正常下蹲不因“低于固定站姿高度”被直接判跌倒。反解 `satisfied=False` 必须记录，
不作为合法真值；可跳过该初值继续物理搜索，不谎报任务完成。

**要点：**P5 真实点速度需包含偏移点的角速度贡献，尤其踝点；也可暂用世界位置
差分，但参考与实际必须使用相同的时间定义。真实 COM 用物理质量计算，不用
`mass_proxy(actual_p5)` 代替，否则无法约束五点以外的质量分布。

### E5 — 有限预算仿真 MPC

**输入：**E1 恢复机制、E3 预测窗口、E4 评分和初值。
**工作：**借鉴 `solve_action_window`，搜索 H 步动作，仅返回第一步；
下轮将上轮最优序列前移。先测 H=6、32候选、2轮 CEM、固定种子，
同时保留“上一轮序列”和姿态初值两个基线候选，不让随机搜索丢掉已有更优结果。
只有接触前瞻不足的证据出现时再增加 H，不盲目放大预算。
**产物：**search 接口、最优代价/分解/候选数/耗时，确定性的失败返回。
**验收：**动作有限且范围正确；最优代价不劣于已评分基线；实际只执行一个 Action；
候选和实步在同一快照下落点一致；预算耗尽仍返回 best-effort 并标明违规，
不能把“找到最小代价候选”当成“满足任务”。

**要点：**本阶段不承诺 20Hz 实时。允许离线较慢运行，但配置有候选/迭代上限，
单案例墙钟超时建议 10 分钟，超时记录失败。若计算成为瓶颈，优先缓存/复用、
动作分块或低维修正，不先另建大型并行框架。

### E6 — 闭环推进、完成判定与收势

**输入：**E2 缓存、E3 参考、E5 动作。
**工作：**串起 submit→step→真实推进→读取 Current。
事件按顺序推进；用真实到达误差与必要接触确认关键节点完成，不按时钟自动跳过。
迟到允许有限次重新配时（建议最多 2 次），总任务时间从提交起计，不随重规划重置。
剩余序列从实测首帧继续，原世界目标不变。
末帧之后进入 SETTLING，生成近邻平衡/减速目标；稳定后进入 HOLDING。
**产物：**Executor 类与完整事件日志；当前指令结束后仍返回保持动作。
**验收：**标准目标左右手跑通；真实 land/strike 到达有记录；
超时/失衡返回明确失败，不把重置或恢复算成功；任务结束后实际再运行 2s。
CLEAR 在已稳定状态可用；动态 CLEAR 即便失败，也需报告且无状态瞬移。

**可尝试方向：**先保留末帧脚位，减小 COM 速度、调整躯干/双手收势。
若末帧无法保持，允许生成明确记录的内部收势目标；不能把它混入原指令完成指标。
复杂补步恢复不属于首阶段必须成功的能力。

### E7 — 固定案例评估、可视化和交付说明

**输入：**全部实现及 E0 固定清单。
**工作：**提供命令入口，保存输入、计划、动作、真实状态、事件、逐通道误差、
耗时、失败原因和模型/配置/代码版本。渲染真实 rollout，叠加参考五点与 COM。
保留“姿态初值直接执行”和“加入 MPC”对比，至少在标准目标两手各运行一次。
**产物：**可复现 CLI、机器可读报告、两手标准案例视频、简短使用说明与已知限制。
**验收：**满足第 5 节；干净新进程可从记录重放并生成相同统计；
失败案例也必须留在汇总中，不能只输出成功视频。

## 5. 固定验收与诊断标准

以下是首阶段工程验收阈值，不是已经验证可达的能力。若无法达到，应报告阻塞，
保留数据并提出修改原因，不能静默降低标准。所有误差使用实测数据。

**案例（目标在初始局部系，单位 m）：**

- 必过：`(1.05, 0, 1.15)`，左右手，搜索种子 0、1。
- 扩展：`(1.20, 0, 1.15)`、`(1.10, 0.15, 1.10)`、
  `(1.10, -0.15, 1.10)`，每个左右手，种子 0。
- 调用方生成时若某项 reachable=False，报告生成器拒绝；不偷偷换目标。
  必过案例拒绝是阻塞；扩展案例分别报告生成/规划拒绝和执行失败，不混分母。

编写本计划时，已用标准站姿局部 P5 核对上述八个“目标 × 手侧”组合，
当前生成器均返回 reachable=True；尚未进行 Executor 物理执行验证。

**必过案例四次均需满足：**

1. 首帧锚定与快照/重放检查通过；只通过 PD Action 推进，无任何轨迹状态注入。
2. 在提交后 6s 内依次到达 coil、swing、land、strike。
   关键节点容差：头/非出拳手 ≤0.12m，双脚 ≤0.06m，躯干 yaw ≤20°；
   swing 的摆动脚至少较初始踝高 0.02m，land 有足部接触确认。
3. strike 时出拳手距 Clip 最终拳点 ≤0.08m；另外报告距原 target 的误差。
   这两者不同，不能用生成器的目标误差冒充执行误差。
4. 全程无非足部地面接触/对手接触；支撑脚在指定支撑区间的水平漂移 ≤0.05m
   （脚自身转动造成的踝点变化需同时记录），姿态和动作没有 NaN/越界。

实现中发现的精确语义（后续包必须遵守）：

- **Action = 归一化 PD 位置目标**：`target_rad = action*scale + reference`，
  torque=`KP*(target-q) - KD*qd` 经 gear/ctrlrange 限幅。`action=0` 指向

- `_target_pos_norm` 存在 simulator 对象上（非 mjData）——快照恢复时 E1 必须
  另行恢复该字段（或保证恢复后先 set_action 再 step）。

- 站姿 PD 开环保持是**不稳定平衡点**（实测 2s 内 tilt→1.34rad 跌倒），
