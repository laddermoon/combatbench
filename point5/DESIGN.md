# Point5 (P5) — 业务动作语言设计

> 版本：v2（躯干朝向局部系）。v1 世界绝对坐标系已废弃。

## 1. 定位

P5 是**与仿真器无关的业务层动作语言**。人（或高层战术规划模型）只设定
稀疏的"五个点"来表达动作意图；下游的领域模型（插值平滑）、重建模型
（姿态反解）、质心动力学模型、控制器负责把 P5 变成可执行动作。

```
人/战术规划  →  P5 clip（稀疏关键帧）
           →  领域模型：插值、平滑、合法性初筛
           →  重建模型：姿态反解（本仓库 humanoid21/mechanics.py）
           →  质心动力学 → 控制 → 动作执行
```

P5 层只表达**几何意图**：位置、朝向关系。不含速度、力、关节细节。
关节空间解的唯一性与动力可行性由下游各层各自保证。

## 2. 五个点

| 点名 | 语义 | Humanoid21 落地 |
|---|---|---|
| `head` | 头部中心（身体球心） | head body 中心 |
| `hand_right` / `hand_left` | 手部中心 | hand body 中心 |
| `foot_right` / `foot_left` | 脚踝中心 | foot body 上的踝中心 |

五个点的顺序即上表顺序，`POINT_INDEX` 在 contracts.py 定义。

## 3. 局部坐标系（v2 核心）

**P5 状态 = `local_pos[5×3]`，仅此而已。** 无绝对位置、无绝对朝向、
无独立 yaw 字段。

坐标系由**躯干朝向**定义：

```
原点 O = 双脚脚踝 XY 中点（Z 原点 = 地面 z=0）
X 轴   = 躯干前向（torso facing）
Y 轴   = 躯干左侧
Z 轴   = 上
```

- X 轴是**语义声明**：编码端（人或提取器）知道躯干朝哪，据此写局部
  坐标。X 轴不是从 5 个点推导的——这正是拧转信息的载体。
- 踝线在局部系中是一条**斜线**：它与 −Y 方向的夹角等于躯干拧转角
  （旧称 torso_yaw）。拧转不再是标量字段，而是藏在脚坐标里的几何
  事实：

  ```
  twist = atan2 于「踝线方向在局部系中的倾角」，可直接从存储的脚
  坐标恢复。脚踝线恰好是 Y 轴 ⟺ twist = 0（正对站姿）。
  ```

- 编码端必须为 "X = 躯干前向" 提供来源（adapter 用 torso 四元数；
  人工作者需明确自己设定的朝向）。

### 为什么去掉绝对信息

同一站姿 P5 在场内任何位置、任何朝向通用——clip 数据可复用、可
组合。世界放置（站哪、面朝哪）是**消费时的选择**，不是姿态的属性。

## 4. Clip：关键帧 + 坐标转移链

```
Clip = keyframes[]
每帧 = { p5: local_pos[5×3],
         transfer: {dx, dy, dyaw, dur} }   # 最后一帧可无 transfer
```

`transfer_k` 记录**第 k+1 帧的局部坐标系在第 k 帧局部系里的位姿**：

```
F_{k+1} = F_k ∘ T(dx, dy, dyaw)
dx, dy = 下一帧原点在 F_k 中的 XY 位移（米）
dyaw   = 下一帧躯干朝向相对本帧的转角（度，逆时针为正）
dur    = 本帧 → 下一帧的时长（秒）
```

- **记录在上一帧上**：第 k 帧携带"如何走到下一帧"。
- 世界位姿由链式合成：`F_k^world = F_1^world ∘ T_1 ∘ T_2 ∘ ... ∘ T_{k-1}`。
  `F_1^world`（第一帧放在世界哪里）由消费者决定。
- `dyaw` **不可从两帧局部数据推导**（局部系内部看不到世界旋转），
  必须作为数据存储。
- `dx, dy` 有一个规范化推导方式：**锚脚世界不动**——转移使支撑脚
  在两帧间世界坐标不变（如迈步时前脚动、支撑脚钉地）。建议作为
  默认推导，允许手动覆盖。

### 插值

段内采样 = 局部位置线性插值 + 该段 transfer 的渐进施加：

```
pos(s)  = p5_k + (p5_{k+1} − p5_k)·s
frame(s)= F_k ∘ T(dx·s, dy·s, dyaw·s)     s∈[0,1]
```

**局部插值而非世界插值**——保持"姿态纯"。语义上同一姿态形状的
中间态也只在局部系中插值。

### 语义注意（非 bug）

当动脚上步时，支撑脚在**局部系中读数是"后退"的**——因为局部原点
跟着双脚中点走。这是表示法特性：局部系里看，世界钉地的脚在后移；
转移 dx,dy 的作用正是把帧链展开回世界时补偿掉这部分。

## 5. 退化情形

- **双脚重合**（踝中点 < 阈值）：原点退化，无法定义局部系——不合法。
- Z 坐标永远以地面为参考，Z 退化不存在。

## 6. 合法性

P5 的合法性 = **能否被目标机器人以该动作的语义重建出来**。两层：

1. `check_legal(p5)` —— 毫秒级几何包络必要条件（脚间距、头高度、
   手-头距离等）。违反必非法；通过不保证合法。
2. 完整两段式求解（humanoid21/mechanics.py）——阶段 1 解主体姿态
   （脚+头+拧转，拧转从踝线倾斜恢复），阶段 2 解手臂。两阶段都可
   重建才合法。

## 7. 序列化

### 状态帧

```json
{"type": "p5.v2",
 "p5": [[x,y,z]×5]}            // 顺序 = POINT_NAMES，躯干朝向局部系
```

### Clip

```json
{"type": "p5clip.v2",
 "name": "...",
 "keyframes": [
   {"p5": [[x,y,z]×5],
    "transfer": {"dx": 0.15, "dy": 0.0, "dyaw": -30.0, "dur": 0.4}},
   {"p5": [[x,y,z]×5]},
   ...]}
```

### 单点规格（可选标注，供下游打分/容差）

关键点位的 `tolerance`/`weight` 作为**标注**保留（PointSpec），P5 层
不消费。

## 8. v1 → v2 变更对照

| v1 | v2 |
|---|---|
| 世界绝对坐标 5×3 | 躯干朝向局部系 5×3 |
| `torso_yaw` 字段（可选标量） | 消失，拧转藏在脚坐标里 |
| Keyframe 含 PointSpec anchors | Keyframe = local p5 + transfer |
| durations 数组 | transfer.dur 逐段记录 |
| 世界位置是姿态属性 | 世界放置是消费端的选择（F_1^world） |

## 9. 本仓库分层

```
point5/                     # 业务语言层（仿真器无关）
  contracts.py              # 点定义、Keyframe/Clip 类型、serde
  trajectory.py             # 采样/插值/帧链合成
  punch_planner.py          # 示例高层规划器（出拳）
  studio/                   # Web 编辑/可视化工具
  viz.py                    # 离线可视化（几何版）
  humanoid21/               # 机器人落地层（可替换其它机体）
    adapter.py              # 物理状态 ↔ P5 提取
    mechanics.py            # 弹簧骨架 + 两段式平衡求解 + 合法性
    clip_render.py          # clip → 人体模型 mp4 渲染
    render.py / fk.py       # MuJoCo 渲染/FK
```
